# 逆向复刻项目经验库

版本：1.0（2026-11-25）

本目录整理《天使帝国 II》Web 重制版从建库到 1.3.0 的开发经验，有两个用途：

1. **指导下一个项目：** 两份蓝图可以直接复制、按目标游戏裁剪，作为新项目的流程、门禁和角色边界；
2. **分享经验：** 两份复盘记录实际经过、数字、返工和可讲的故事，可以作为文章和视频教程的底稿。

这里不保存《天使帝国 II》的原版事实。原版事实在 `reverse/`，复刻设计在 `design/remake-gdd/`，当前进度在
[`planning/STATUS.md`](../../planning/STATUS.md)。

## 1. 两轮开发

| | 第一轮：复刻 | 第二轮：增强 |
| --- | --- | --- |
| 时间 | 2026-07-13 至 2026-11-08 | 2026-10-26 至 2026-11-25 |
| 版本 | 0.1 → 0.16.0，1.0.0 的规则部分 | 1.0.0 的交响音乐 → 1.3.0 |
| 目标 | 复现原版可达的全部战役、规则、像素、音乐和 UI，修复原版缺陷，调整平衡 | 加入原版没有的现代内容：交响改编、AI 语音、高清肖像、高清剧情画面、高清地图特效 |
| 核心问题 | 怎样证明“原版就是这样” | 怎样加新东西而不破坏复刻 |
| 判断依据 | 原版证据加产品决定 | 产品决定加人工审美验收 |
| 对结算的影响 | 修复与平衡会改变结算 | 只换表现，不改结算、随机序列和存档 |
| 蓝图 | [`round-1-remake-blueprint.md`](round-1-remake-blueprint.md) | [`round-2-enhancement-blueprint.md`](round-2-enhancement-blueprint.md) |
| 复盘 | [`round-1-remake-retrospective.md`](round-1-remake-retrospective.md) | [`round-2-enhancement-retrospective.md`](round-2-enhancement-retrospective.md) |

两轮在时间上有重叠：交响音乐的试点（10-26）开始时，第一轮最后三条平衡修复还没发布；第二轮期间也还在做
怀旧开关这类规则工作。划分看的是性质而不是日期——会改变结算的归第一轮的方法，只换表现的新内容归第二轮。
项目在 1.3.0 发布当天从「Web 復刻版」改称「Web 重製版」，名称的变化也对应着这次转向。

**启动一个新的复刻项目：**

## 3. 贯穿两轮的结论

1. **事实、决定和实现分开存。** 第一轮靠它防止“代码已经这样写”反过来变成原版事实；第二轮的增强素材同样以原版
   证据为锚，原版一变，生成器就拒绝生成。
2. **模拟和表现分开。** 第一轮为此付出的约束，在第二轮全部兑现：五类增强都不需要改动模拟或存档，存档身份从
   1.0.0 到 1.3.0 一直不变。
3. **重复的真值交给生成器。** 地图、对白、职业、字体、图集，以及第二轮的音乐、语音、肖像、剧情画面和特效清单，
   都由脚本生成并带硬性校验，不在多个文件里手抄。
4. **人做判断，AI 做执行和筛查。** 两轮里每一次方向性的转折——冰雪规则怎么改、提示词怎么写、程序特效要不要、
   音效现代化取不取消——都来自用户。AI 负责把判断变成流程、跑完批量、筛掉明显的坏结果。
5. **证据也会错。** 第一轮有提取器误读被写进玩家说明后撤回；第二轮的高清化又暴露了原版风格自己的定位错误和
   取证误读。任何一层都不能被当作无需复查的真值。
6. **先复用流程，再复用工具，最后才复用领域代码。** 下一款游戏应该重新证明它自己的规则、内容和资源格式。

## 6. 维护规则

- 蓝图写“下一个项目应该怎么做”，复盘写“这个项目实际发生了什么”；同一条经验在复盘里讲经过，在蓝图里写成规则；
- 数字必须能追到仓库里的出处，推算值要标明；工作台（git 忽略的 `tmp/`）里的东西只说明方法，不作为唯一出处；
- 新一轮工作（例如 RoadMap 上的剧情回顾、支线挑战、Mod 与关卡编辑器）如果开始，另起 `round-3-*` 文件，不改写前两轮的结论；
- 插图在 [`../illustration/`](../illustration/README.md)，内容变化时同步更新两轮的图。
