# 第二轮“增强”蓝图：在忠实复刻之上加入现代内容

版本：1.0（2026-11-25）

来源：《天使帝国 II》Web 重制版 1.0.0–1.3.0（2026-10-26 至 2026-11-25）的交响改编音乐、剧情语音、
高清动态肖像、高清剧情画面、高清地图特效和素材重编码全过程。实际经过、数字和返工见
[`round-2-enhancement-retrospective.md`](round-2-enhancement-retrospective.md)；第一轮“复刻”的方法见
[`round-1-remake-blueprint.md`](round-1-remake-blueprint.md)。

本文件回答一个问题：一款忠实复刻已经能玩、能发布之后，怎样用生成式 AI 加入原版没有的内容，又不破坏复刻
本身。它不保存《天使帝国 II》的原版事实。文中的工具和模型都是本项目 2026 年 11 月的实际选择，只当示例；
下一个项目应按当时的质量、许可和成本重新选型，保留的是流程和门禁。

## 1. 什么算“增强”，什么时候开始

### 1.1 五类改动

重制版里的改动可以分成五类。前三类属于第一轮的规则工作，后两类才是本文件说的“增强”：

| 类别 | 本项目的例子 | 决策依据 | 会不会改变结算 |
| --- | --- | --- | --- |
| 复刻 | 原版规则、像素、音乐、对白节奏 | 原版证据 | 本身就是原版 |
| 修复与平衡 | 证据冲突修正、关卡平衡（`REMAKE-157`、`159`、`182`–`184`） | 证据加产品决定 | 会，进 `stableRemake` |
| 怀旧开关 | 「敗退保留經驗」「原版冰雪」（`REMAKE-215`、`216`） | 让玩家切回原版结算 | 会，切回原版 |
| 现代便利 | 自动配置、小地图拖曳、删除存档槽、右下角宿主选单 | 产品决定 | 不会 |
| 增强内容 | 交响改编、AI 语音、高清肖像／剧情画面／地图特效 | 产品决定加人工审美验收 | 不会，只换表现 |

分类决定走哪条流程：会改变结算的，按第一轮的证据→决定→合同→实现链处理；只换表现的，走本文件的增强
流程。两条线在时间上可以并行（第二轮期间仍在修第一轮的规则），但同一项改动只归一类。

### 1.2 进入第二轮的门槛

第二轮能在 30 天里上线五类增强，靠的几乎全是第一轮留下的基础设施。开始增强前，至少要满足：

1. 原版可达内容全部可玩，并已经对外发布过一段时间，存档迁移链完整；
2. 模拟与表现分离已经实际验证过：动画速度、声音和跳过演出都不会改变战果；
3. 资源清单、私有素材仓库、按关分包、下载进度和解码门都已就绪——增强素材全走这条供应链；
4. 原版素材的“证据身份”已经机器可读：图集哈希、逐帧时间线、对白分页和文字、旁白时长。增强以它们为锚；
5. 有调试中心和实验室，能不打战役就直接看到某个对白、某个特效或某段剧情。

这五条缺任何一条，增强就会变成重写。反过来讲，这也是第一轮那些看似过度的约束（证据身份、生成器、实验室）
在第二轮兑现的地方。

## 2. 九条增强不变量

每一项增强都必须同时满足下面九条。它们是第一轮“九条边界”在增强内容上的具体形式。

1. **可选，默认原版。** 每项增强都是玩家显式打开的设备级偏好，默认原版，不写进存档，也不改变保存身份。
   同一个偏好可以从几个入口切换（开场方框、设定面板），但只存一份。
2. **只换表现。** 增强不碰模拟、PRNG、存档和动作提交时点。控制器照原版逐帧等待；增强层只能在原版时段内
   前进，多出来的余韵由表现层在控制器离开后自己播完，不让游戏多等。
3. **原版为锚。** 原版的时间线、帧序和像素是骨架：关键画面落在原版时刻，总长与原版相同；原版的画框、标志、
   文字、手写字和点阵字保留原样，AI 只换画面内部。
4. **关着就不存在。** 关闭时一个请求都不发；打开后按关或按画面按需下载，不抢首屏和必需资源的带宽。
5. **失败可见地回退。** 回退以完整单元为粒度（一张插图、一次施法、一页语音、一条肖像），在单元开始时
   决定，失败只提示一次。不能悄悄换成另一个版本，让玩家误以为看到或听到的是增强版（1.0.0 当天因此重发两次）。
6. **原物一变就拒绝。** 增强素材的清单记下它依赖的原版身份（图集哈希、原图哈希、旁白时长、帧起点）。原版
   证据一变，生成器就拒绝生成，要求先复审对应的增强素材。
7. **工作台在仓库外。** 生成工具、原始生成结果、对照页和挑选记录都放在 git 忽略的工作台；仓库只收生成器、
   生成的运行时代码和测试，成品只进私有素材包。素材包里的清单是真值。
8. **人是验收者。** 自动指标（接缝评分、ASR 漏读、像素差异、VMAF、时长核对）只负责筛掉明显的坏结果。
   用户逐轮看、逐轮听，做最终选择；每一轮的意见和选择都要落成文件。
9. **许可先行，来源公开。** 全量生成前读完模型和平台的许可条款；研究用途的模型不进生产。游戏内的说明
   面板写明每项增强用了什么工具、做了什么，以及原版完整保留。

## 3. 一项增强的生命周期

单项增强的内循环：

```text
Proposal → Pilot → Decide → Batch → Screen → Review → Import → Integrate → Verify → Ship → Refine
提案评估    小样      用户决定   批量生产   自动筛查   人工审阅   导入清单   运行时集成   定向验证   发布     复审与优化
```

### E0：提案与评估

写一份评估文档（本项目放在 `planning/audits/`），至少回答：

- 增强哪些表面，哪些明确不做（例如祈禱结果、战绩卡、制作人员表不配音）；
- 有几条技术路线，每条的质量上限、成本、速度和许可；
- 原版哪些部分必须保留原样，增强素材怎样对齐原版时间线；
- 默认值、开关位置、下载与回退策略；
- 预计的素材体积和生成耗时；
- 验收方法：哪些靠自动指标，哪些靠人工审阅。

### E1：小样

只做最小的一组，例如第 0 关的三首曲子、四张插图、一个特效族、几位主角的肖像。小样的目的是尽早否决
路线，而不是证明能做出来。本项目的肖像在一两天内否决了超分、低去噪图生图、局部重绘和独立说话片段四条
路线；地图特效先用代码画了一版程序化火焰，用户看后整条路线否决，改走“AI 重绘关键帧加视频补间”。

退出条件：用户看过或听过小样，选定路线，授权批量。

### E2：批量生产

在工作台里按计划文件批量生成。要求：

- 可断点续跑，失败只重跑失败项；
- 每个结果带旁注：模型、版本、种子、提示词、输入哈希。旁注不符就当作没有，防止旧结果顶替新任务；
- 每个版本同时绑定输入和参数（例如“朗读稿＋音色”），改选时换新版本号，不覆盖旧版本；
- 每个单元生成两到三个候选，留给人挑。

### E3：自动筛查

按媒体选指标，见第 6 节。指标只排序和报警，不做最终判断。例如肖像的唇定位失败有 4 条，数值都正常，
看图才发现。

### E4：人工审阅

- 审阅页把原版和增强版按游戏里的合成方式、相同尺寸并排放；
- 最弱的排在最前面；
- 选择结果能直接复制回对话或写进 `picks` 文件；
- 每一轮把意见写成可执行的修改项，下一轮逐项回应。

本项目每项增强都走了两到四轮，常见的意见有：循环每圈卡一下、云会倒着飘、口型逐字瞬切、特效卡顿、
收尾突然消失、多出不该有的东西。

### E5：导入

工作台导出交付件，仓库里的生成器用 `--import` 读入素材包并写出运行时代码，再更新资源清单。生成器负责
所有硬性检查：编码、轨道、尺寸、帧数、时长、原版哈希、有没有多余文件。

### E6：运行时集成与验证

按第 5 节的模式接入，补单元测试和端到端测试。必须覆盖：关闭时零请求、打开时按需下载、下载失败回退、
增强开关不改变战果。画面类增强还要人工看截图，并在 Safari 等非主力浏览器上复查合成。

### E7：发布、复审与优化

素材仓库先推，再发布游戏。发布说明写清楚新增了什么素材、多少体积、资源清单身份和来源说明。上线后再走
一到两轮复审，最后在内容稳定后统一压缩编码。

## 4. 工作台

每类增强一个工作台，统一放在 git 忽略的 `tmp/<增强名>/`：

```text
tmp/<enhancement>/
  inputs/        # 从证据层导出的原版锚：帧、时间线、文字、旁白时长
  tools/         # 可重跑的脚本（生成、筛查、收尾、导出）
  runs/          # 原始生成结果，体积最大，可以清理
  review/        # 对照页、预览视频、审阅记录
  picks/         # 人工选择
  export/        # 交付候选，导入仓库的唯一来源
  README.md      # 方法、命令、已知坑
```

本项目工作台的体积：肖像约 9.6 GB、剧情画面约 9 GB、地图特效约 7.5 GB。这些都不进仓库，但要定期备份
最终交付件和不可再生的资产（例如设计出来的音色——库音色可能下架，描述文字也复现不出同一个声音）。

增强素材清单至少记录下面这些字段（示意，数值不是本项目的真实记录）：

```yaml
manifestVersion: 6
entries:
  - id: story/bk-0010            # 稳定语义 ID
    sourceIdentity:
      originalImageSha256: "…"   # 原版一变就拒绝
      narrationMs: 7420          # 时间依赖也要钉住，旁白一变就拒绝
    files: [loop.mp4, sky.webp]
    encoding: { codec: h264, crf: 25, frames: 132 }
    fallback: original-per-entry # 回退粒度
    provenance: [qwen-image-edit-2511, minimax-h3, rife-4.25]
```

## 5. 运行时集成模式

| 关注点 | 做法 |
| --- | --- |
| 偏好 | 设备级本地偏好，不进存档；多个入口写同一个键；默认原版 |
| 下载 | 增强素材放进独立的 stream 包，不进关卡包；资源门按本关实际会用到的内容预取（本关出场的脸、本关职业施放得出的特效、本次结局显示的尾声段） |
| 开场 | 开场方框出现后后台下载，选原版立即进入，选增强显示百分比，失败留在方框提示重试或改选原版 |
| 回退 | 以完整单元为粒度，在单元开始时决定；中途到达的素材下一单元再用 |
| 时钟 | 原版时间线是主时钟。增强层的时间 = 当前原版帧起点 + 经过时间，夹在本帧终点之前；语音自动翻页复用玩家的推进入口，只改时刻，不改次数和顺序 |
| 合成 | 原版像素层（UI、文字、画框）保持原样；透明视频用上下或左右堆叠（颜色×α 与 1−α），在 WebGL 或画布里拆回预乘透明度 |
| 同步 | 必须严格同步的内容放进同一个文件（肖像的脸和嘴格编在同一帧），不靠两个计时器对齐 |
| 缩放 | 大比例缩小用连续 2:1 减半；检查全局 CSS 有没有 `!important` 覆盖画布平滑设置 |
| 浏览器 | Safari 把 `<video>` 画到 2D 画布时不理会合成模式，要先把当前帧复制到画布再合成 |
| 调试 | 调试中心能直接切换美术风格、语音和音乐风格；实验室能重放高清版本 |

## 6. 按媒体的方法卡

### 6.1 改编音乐

- **锚：** 原曲的无损渲染，按游戏实际播放结构拼成参考音频：入场段＋循环段×2＋淡出尾。短循环多重复几遍。
- **生成：** 本项目用 Suno 的 Cover 模式，用户亲自上传、生成和下载。提示词只描述编曲：哪组乐器接旋律、
  原曲的快速音型改成什么织体、低音、打击乐、和声色彩和混音空间。不写“适合循环”“能量恒定”“不要结尾”，
  也不写速度和段落结构——这类约束版本明显不如纯描述版本。
- **筛查：** 按色度特征自动分拣到曲目；用动态时间规整对齐参考，再按和声、节奏、音量、低音、淡化区响度
  多维打分找接缝，每首试剪前三个候选。两段不相关音频之间默认用等功率交叉淡化。
- **审阅：** 审阅页按最弱排序，每首给 20 秒接缝特写和“循环两遍”的完整模拟。
- **集成：** Web Audio 原生 `loopStart/loopEnd` 单文件循环；改编按原曲绑定，不按关卡绑定；换曲 0.6 秒淡出。
- **坑：** 生成音乐会逐渐变快（本项目每遍快 0.5%–0.8%），只能在接缝附近量循环长度；下载的文件可能藏着重复
  片段；平台提示与已知录音相似时直接跳过，不改音频绕检测。

### 6.2 角色语音

- **锚：** 原版对白的分页和文字。配音稿与显示文本分开存：去掉引号、繁转简、错别字表、读音词典；画面上
  照原样显示，语音按本意读。
- **选角：** 先按平台的语言标签过滤，只用母语声线；再按性格挑。用 HTML 试听页逐轮挑，同场出现的角色
  自动查重。库里缺的再用声线设计补。
- **生成：** 本项目旁白用 MiniMax，角色用 ElevenLabs（情绪更丰富），种子按“片段键＋版本号”取哈希固定。
- **筛查：** 本地 whisper 识别后比“漏读字比例”，不比字错率；比之前先把同音字、异体字归一。长音频先在
  停顿处切段再识别，1–2 秒的短片段要人工看有没有识别幻觉。
- **后处理：** 裁静音、保持音高变速（模型的语速参数可能无效）、统一响度。读音错误用同音字替换，不去修单个片段。
- **集成：** 片段按“记录号＋页序号”或“声线＋文字哈希”绑定，文字一改就当无语音页；有语音的页不放逐字音；
  会自己收起的台词窗等语音说完再收；全局暂停时语音和自动翻页一起冻结。

### 6.3 动态肖像

- **锚：** 原版主图、眨眼帧、口型帧和原版布局百分比。
- **生成：** 静帧重绘（本项目 Qwen-Image-Edit，原生 1024，每条三个种子人工挑）→ 修主图的问题（能在源头修
  就不在逐帧后处理里修）→ 视频模型生成待机循环 → 生成一份嘴一直微张、逐帧同步的副本 → 每帧只换嘴部
  羽化椭圆 → 帧插值补出过渡嘴形。
- **循环：** 接缝不要放在主图上——主图是动作的折返点，在那里停顿或加速都看得出来。用“接续前段＋尾端锚定”
  生成过渡段，比剪辑自然。
- **筛查：** 接缝速度、单帧闪线、闪烁、鼻子抖动等脚本只作提醒；每条都看眼部时间条、嘴部放大条和闭嘴／张嘴
  对照图。
- **集成：** 脸和嘴格编进同一支视频，每帧从同一解码帧取出；嘴只在语音有声段开合；被操控的红眼版从一般循环
  派生，不重新生成。

### 6.4 剧情画面

- **锚：** 原版插图、标题和片尾画面的原图哈希，旁白时长与原版停留时间。
- **生成：** 去网点 → 主体重绘 → 外扩到宽屏（重绘与外扩分开做，一次画完整幅边缘会糊）→ 视频模型生成镜头
  或循环 → 帧插值去近重复帧、稳定曝光、修单帧跳变。
- **分层：** 小人物单独抠出，按 4 倍尺寸重绘和做待机，再缩小合成；云层做成可平铺的卷动层，前景做成叠加视频；
  烟、尘、月光这类单向漂移用交叉淡化循环，不用回接循环（否则会“慢飘再快速退回”）。
- **保留原版：** 画框用四向对称重建被人物挡住的部分，没被挡住的地方一律用原图像素；标志、字幕和手写字保留。
- **时间：** 切换点由旁白时长算出来，写进单元测试；旁白一变就要重排切换点并重出视频。
- **坑：** 提示词里有歧义的词会把画面带偏（“藤蔓”把白色画框画成绿叶）；外扩模型会在角落签名、在空洞里画出
  新人。人物的性别、发色和数量要在提示词里写死，并先核对剧本。

### 6.5 地图特效

- **锚：** 原版逐帧图集、每帧起始 tick 和目标格锚点。
- **生成：** 像素图先做 EPX 放大再轻度模糊作输入 → 中性提示词全去噪重绘关键帧，每帧三个种子 → 视频模型把
  关键帧钉在原版起始 tick 上补间 → 从黑底抠透明度 → 收尾处理（重定时、实心化、去抖、尾段淡出）。
- **关键帧：** 逐像素相同的原版帧共用一张重绘（否则闪烁）；相邻帧变化很小就并成一组只钉一张（否则补间整格
  不动）；近空帧和碎散帧不钉，交给补间（否则会被幻觉成别的东西）。
- **抠图参数分族：** 火系和光效的门槛、填洞规则完全不同，集中写在一张设置表里。
- **收尾保留逐帧母版：** 审阅意见尽量只改收尾，不重跑生成；以后重编码也不用重做。
- **意外收获：** 高清化会暴露原版风格本身的定位错误和取证误读，修正时两种风格一起受益。

### 6.6 编码与体积

- 所有中间文件保持无损，只在交付时有损编码；母带要保留，否则以后压缩只能二次转码。
- 本项目最终选择：音乐 Ogg Opus 112 kbps，语音 Opus 32 kbps 单声道，视频 H.264 提高 CRF、preset veryslow。
  没换 AV1：只再小 5%–10%，Safari 和旧设备未必能硬件解码，特效又要频繁跳帧。
- 循环音频编码时前后各接 0.5 秒自身的上下文再裁回，否则编码器把两端当作静音，接缝会跳；用解码后的接缝
  dBFS 设测试门槛。
- 时长按解码样本数算。ffprobe 报的 Opus 时长含 312 样本预跳过。
- 视频看 VMAF 并人工查看 2 倍放大对照；音频没有可靠的客观分数，以试听为准。

## 7. 顺序与依赖

本项目的接入顺序是音乐 → 语音 → 肖像 → 剧情画面 → 地图特效 → 重编码（肖像的小样其实比语音早三天开始，但口型
要等语音的有声段，最后排在语音之后接入），后来回看是合理的：

| 顺序 | 增强 | 为什么放在这里 |
| ---: | --- | --- |
| 1 | 改编音乐 | 只接触音频调度，和其他系统耦合最少，适合先跑通“可选层＋素材包＋下载门”的整条链 |
| 2 | 语音 | 引入自动翻页和“表现决定等待时长”的模式；它的有声段数据随后驱动肖像口型 |
| 3 | 动态肖像 | 依赖语音的有声段；确立了美术风格开关和角色外观，供剧情画面沿用 |
| 4 | 剧情画面 | 复用肖像的开关、角色外观和视频管线；旁白时长又决定开场的切换点 |
| 5 | 地图特效 | 与原版逐帧时间线耦合最深，需要前面积累的视频合成和透明度经验 |
| 6 | 重编码 | 内容稳定后统一压缩一次，避免每次重出素材都重新压 |

两条经验：先做耦合最少的增强来验证供应链；会产生数据给别人用的增强（语音的有声段、肖像的角色外观）要排在
消费它的增强之前。

## 8. 审阅、否决与取消

- **把领域常识写进提示词和检查表。** 本作没有男性角色，第一张插图就把士兵画成了男性；之后所有提示词都写明
  “a young woman”，审阅时逐张核对性别、人数和多余物体。
- **AI 常见失真清单：** 多余物体（第二个月亮、多一只翼龙）、签名和水印、文字被改成简体、画框被吃掉、眨眼
  缺失、口型逐字瞬切、循环卡顿、颜色漂移、近空帧被幻觉成人物。每项都应有对应的检查方法。
- **取消也是结果。** 音效现代化试了两条路线（换成素材库音效、对原版做高清化处理），都不如原版，用户取消。
  取消时在决定日志、RoadMap 和状态表里留痕，清掉试做产物，避免以后被重复提出。
- **A/B 新模型要先看许可。** 本项目的 Qwen-Image 2.1 Turbo 许可只限研究和评估，A/B 只作参考；Pika H3 Flex
  更快但动作幅度太大，也没有换。

## 9. 授权、披露与归档

- 全量前核实：模型许可（是否允许商用或分发、地域限制、是否要求标示 AI 生成）、平台条款、额度和费用。
  本项目的视频模型许可是事后才读的，读完才发现有地域条款，只能由用户事后决定是否接受风险——这一步应该在
  E0 完成。
- 游戏内说明面板逐项写明来源：用了哪些模型和平台、做了什么、非商业同好用途、原版完整保留可随时切回。
- 规格里许可仍未核实的项要显式标 `[TBD]`，不要默认为可用。
- 成品、设计音色和挑选记录都要归档；素材只进私有素材仓库，不进公开仓库历史。

## 10. 角色

沿用第一轮的角色划分（见 [`round-1-remake-blueprint.md`](round-1-remake-blueprint.md) 第 4 节），另加：

| 角色 | 职责 | 不做什么 |
| --- | --- | --- |
| Enhancement Producer | 写评估、定范围、定预算、排顺序 | 不替用户做审美决定 |
| Workbench Operator | 维护工作台，批量生成，跑自动筛查，做审阅页 | 不把原始生成结果放进仓库 |
| Creative Director（通常是用户） | 选路线、选角、逐轮审阅、决定取消 | — |
| Integration Engineer | 生成器、运行时可选层、下载门、回退、测试 | 不为表现改变模拟顺序 |
| Supply-chain / Release | 素材仓库、清单身份、编码、发布说明与来源披露 | 不手工修补发布目录 |

AI 适合承担 Producer、Operator 和 Integration Engineer 的大部分工作；Creative Director 的位置不能交给 AI。
本项目里，AI 写的音乐提示词不如用户自己写的，AI 也看不出数值正常的唇定位失败。
