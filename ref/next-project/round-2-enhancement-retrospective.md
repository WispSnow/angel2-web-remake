## 3. 各项增强的实际经过

### A. 交响改编音乐（1.0.0）

**做了什么：** 「音樂風格　原版／交響」，默认原版。交響模式下 36 首原曲全部换成交响改编，覆盖标题、捲動开场、
关卡剧情、双方回合、出击准备、结局与制作人员表。改编按原曲绑定，不按关卡登记。

**怎么做：** 参考音频按游戏实际播放结构拼好（入场＋循环×2＋淡出尾），用户在 Suno 用 Cover 模式生成并下载；
工作台按色度自动分拣、对齐参考、多维打分找接缝、每首试剪三个候选；用户听完全部接缝后导入私有素材包。

**数字：** 36 首（35 首入场＋循环，1 首整首循环）；33 首自动剪辑中 23 首评为干净、6 首偏弱、4 首没有干净的重复；
改编音乐 72.5 MiB，重编码后 56.6 MiB。

**返工与教训：**

- AI 写的、带“适合循环、能量恒定”约束的提示词明显不如用户写的纯编曲描述，最后删掉了约束版本；
- 等增益交叉淡化在中点凹下 3–5 dB，因为两次生成的音频逐采样不相关，改为等功率；
- 1.0.0 当天：开场等待改编设了 20 秒超时，超时就退回原版。用户指出玩家会把原版当成交响版；线上检查又发现
  第 0 关预取在抢带宽，导致每次都等满 20 秒。最终改为后台提前下载、没有超时、失败留在方框提示，开场预取推迟。
  一天里发布了三次。

### B. 剧情语音（1.1.0）

**做了什么：** 可选的剧情语音，默认关闭，一旦开启就从自动翻页开始。覆盖关前剧情、战场对白、战斗喊话与情境
台词、授职与集体命令、捲動开场字幕和结局尾声；祈禱结果、部署提示、胜利条件面板、战绩卡和制作人员表不配。

**怎么做：** 从原版对白导出配音稿（去引号、繁转简、错别字表、读音词典）→ 五轮 HTML 试听页选角 → 旁白用
MiniMax、角色用 ElevenLabs，库里缺的用声线设计补 → 本地 whisper 识别，按漏读字比例筛查重做 → 裁静音、
变速、统一响度 → 导入。

**数字：** 829 个剧情页里 784 段有语音，45 页登记了不配的原因；全部 2,127 段、88.5 分钟、47.0 MiB，重编码后
21.0 MiB；剧情 33 个身份、战斗 40 个声线、6 个设计音色；ElevenLabs 额度累计用了 17,039（月额度 131,000）。

**返工与教训：**

- 评估原本让 MiniMax 承担大部分角色，第一轮试听后改为角色全用 ElevenLabs，因为情绪表现丰富得多；
- 只用中文母语声线，非母语和明显带地方口音的音色一律不试听就排除；
- 模型的语速参数实测无效，改为离线保持音高变速（角色 1.15 倍）；
- 「主将」被读成“将要”的 jiāng，用同音的「主匠」替换后重生成 39 段；
- whisper 对超过约 25 秒的音频会成段漏识别，对 1–2 秒的短片段会幻听出网站宣传语；
- 换士兵音色时暴露工作台漏洞：只按朗读稿认领旧版本，旧音色的版本被当成现成的。之后要求朗读稿和音色都相符；
- 1,254 段战斗台词没有逐段人工试听，只靠 ASR 筛查——这是有意的取舍，也是剩余风险。

### C. 高清动态肖像（1.1.0）

**做了什么：** 「美術風格　原版／高清」下，对白、胜败回馈、单位详情与结局剧情的肖像换成重新绘制、会呼吸眨眼
的动态版；全景战斗状态框播待机循环；被操控的角色播红眼版；开启语音时口型跟随语音。

**怎么做：** 提案比较了超分、图生图和参考约束重绘三条路线，四轮小样里每轮都换方向，最后定为：Qwen-Image-Edit
重绘主图（每条三个种子人工挑）→ LaMa 修主图唇线 → MiniMax H3 视频模型生成待机，再用“接续前段＋尾端锚定”
生成过渡段做成循环 → 生成一份嘴一直微张的同步副本，每帧只换嘴部 → RIFE 补出过渡嘴形 → 脸和四格嘴形编进同一支视频。

**数字：** 原版 68 条，交付 67 条；循环 104–162 帧；接入时 33.8 MiB，重编码后肖像视频 16.6 MiB；小样六轮共 697 个
任务，首轮全量 GPU 约 4.7 小时，按新主图重出又约 4.7 小时，接续循环一轮约 14 小时。

**返工与教训：**

- 循环最初每圈卡一下：只钉首帧的片段在回到主图前会停顿。先试剪掉静止段，再试加速，最后改用接续生成，66 条全换；
- 抿嘴线先做逐帧后处理，用户嫌繁琐，改为修主图后重出 60 条——能在源头修的不要在下游修；
- 头盔上的「險」被画成简体「险」，用系统字体渲染的字卡作第二张参考图解决；
- 唇定位失败 4 条（找到鼻尖、红发、粉色天空、手指），数值全部正常，看图才发现；
- 浏览器里线稿被缩成点线：全局 CSS 的 `!important` 覆盖了画布平滑设置，Chrome 又不理会平滑质量参数，改为连续 2:1 减半；
- 视频模型的许可在全量和接入之后才读，发现有地域条款，由用户事后决定接受风险。

### D. 高清剧情画面（1.1.0）

**做了什么：** 16 张剧情插图铺满画面并动起来（10 张带独立卷动的云层，1 张静止）；标题画面的框内地景和两名
女子；捲動开场 7 张、结局尾声 8 组和「The end」各做成只播一次或无缝循环的视频。蓝底、画框、标志、字幕、点阵字和
手写字都保留原版像素，计时与推进不变。

**怎么做：** 去网点 → Qwen 重绘主体 → FLUX Fill 外扩到宽屏 → H3 生成镜头或循环 → RIFE 去近重复帧、稳定曝光、
修单帧跳变。有人物的画面分层：人物抠出后按 4 倍尺寸重绘和做待机，再缩小合成；云层做成可平铺的长带；前景做成
上下叠加的透明视频。开场的切换点按旁白时长算出。

**数字：** 剧情插图 10.0 MiB；标题 1.3 MiB；开场 7 段 11.0 MiB；尾声 8 段 32.9 MiB；「The end」0.92 MiB；
剧情视频合计 54.2 MiB，重编码后 27.2 MiB。

**返工与教训：**

- 第一张插图改了三版：士兵被画成男性（本作没有男性角色）→ 人物完全固定、显得呆板 → 分层制作；
- 回接循环让云“慢飘再快速退回”，于是云改成独立卷动层，烟尘月光改用交叉淡化；
- 外扩模型会在角落签名，在人形空洞里画出新人，填天空时画出光芒、黑洞甚至一个女人；
- 第二个月亮、屋顶弹孔被画成卡通爆炸星、尾声多出一只翼龙、提示词里的“藤蔓”把白色画框画成绿叶；
- 中间文件用有损编码时循环接回处会跳，改为全程无损；导出曾按 BT.601 转换却标成 BT.709；
- Safari 把视频画到画布时不理会合成模式，两名女子和有云的插图都立在黑底上，改为先复制帧到画布再合成（1.2.0 修复）。

### E. 高清地图特效（1.2.0）

**做了什么：** 跟随「美術風格　高清」，地图上的炎暴、治疗与休息、状态技术与破邪、回復与冰雪、命中与阵亡、
射击与 `WD`、踩踏、落雷，以及冰封单位的冰壳，共 41 个动作换成高清动画。原版每一帧保留为关键画面，在原来的时间点
出现；特效长度、音效、扣血与结算时点不变；治疗的星芒散去时游戏照常往下进行。

**怎么做：** 用户最初要的是“现代 shader 特效”。先仿照程序化像素特效写了一版火焰，用户看后否决：原版序列帧是
精心绘制的，换成通用程序特效反而降级。改走“路线 C”：原版帧 EPX 放大加轻度模糊 → Qwen 中性提示词全去噪重绘
关键帧，每帧三个种子 → 人工挑选 → 按画面差异规划关键帧 → H3 把关键帧钉在原版起始 tick 上补间 → 从黑底抠透明度 →
收尾处理 → 堆叠视频导出。

**数字：** 35 段视频加 13 张静帧，约 20.4 MiB；特效视频重编码前 29.2 MiB，之后 17.8 MiB；Qwen 重绘 1,409 次、
约 2.4 小时，H3 补间 68 次、约 8.5 小时（按工作台运行记录推算）。

**返工与教训：**

- 同一原版帧分开重绘会闪烁，必须共用一张；判断“相同”要比像素，不能比文件字节（PNG 带时间戳）；
- 相邻帧变化很小却各钉一张，会让补间整格不动，只能并成一个关键帧；
- 近空帧会被幻觉成别的东西（治疗特效第 38 帧被画成一名女法师），提示词里写“face”会把火团画成南瓜灯脸；
- 第二轮审阅六项意见全部只改收尾、不重跑生成，因为收尾保留了逐帧母版；
- 高清化暴露了原版风格本身的错误：炎暴右偏、治疗星芒往右下漂。1.3.0 又发现直线射击与 `WD` 的旧取证把
  收尾误读成“全线从头重播”，高清下像每个目标被打两次；反汇编后改为逐格前进的尾迹，两种美术风格一起更正。

### F. 素材重编码与宿主选单（1.2.0）

用户认为游戏包偏大，要求全部一起压缩。音乐改 Ogg Opus 112 kbps，语音改 Opus 32 kbps 单声道，高清视频提高 CRF、
用 preset veryslow；文件名、曲目长度、循环点、旁白时长和视频帧数都不变，原版像素图逐字节不变。素材包从
303.7 MiB 降到 191.8 MiB（−37%）。

| 素材 | 重编码前 | 重编码后 |
| --- | ---: | ---: |
| 交响改编 | 72.5 MiB | 56.6 MiB |
| 原版音乐 | 45.2 MiB | 29.9 MiB |
| 语音 | 47.0 MiB | 21.0 MiB |
| 剧情视频 | 54.2 MiB | 27.2 MiB |
| 肖像视频 | 32.9 MiB | 16.6 MiB |
| 地图特效视频 | 29.2 MiB | 17.8 MiB |
| 素材包合计 | 303.7 MiB | 191.8 MiB |

两个坑：发布前的完整端到端测试发现第 0 关循环接缝跳变从约 −34.5 dBFS 恶化到 −19.8 dBFS（编码器把文件两端当作
静音），改为前后各接 0.5 秒上下文再编码、再裁回；语音工作台当初没留无损中间档，只能按记录重建再编码——母带
必须保留。

同一版本把画面下方的宿主工具列收进右下角的小宝石选单，点开即暂停，页面上只剩游戏画面。

### G. 取消与搁置

- **音效现代化（11-20 取消）：** 在第 0 关 13 条音效上试了两条路线：素材库的 67 个候选“和原版差异太大”；对原版做
  修削波、去底噪、补泛音和音频超分“效果都不太好”。音效沿用原版，游戏内 RoadMap 的「重編音樂與音效包」改为
  「交響改編音樂」，状态表记下取消原因，工作台、服务器上的试做文件和下载的模型权重全部清除。
- **模型 A/B：** Qwen-Image 2.1 Turbo（许可只限研究和评估，画风偏写实，紫眼变棕）和 Pika H3 Flex（快 20%–25%，
  但待机动作约大 1.6 倍、闭眼长到约 1 秒）都没有换。

### H. 同期的复刻线

第二轮期间，第一轮的规则工作没有停：

- 10-26／27：第 3、9、11 关平衡修复（`REMAKE-182`–`184`）和水战士分裂后的存档修复，随 1.0.0 发布；
- 11-19：调试中心可直接切换美术风格、语音和音乐风格，成长档案改为“预设／随机职业成长”；
- 11-20：角色图鉴可对照原版与高清肖像，RoadMap 标出已实装的方向；
- 11-23：两个怀旧开关「敗退保留經驗」「原版冰雪」，默认关闭，是唯一会把结算改回原版的设置；
- 11-25：项目从「Web 復刻版」改称「Web 重製版」。名称的变化正好对应第二轮：加入大量原版没有的内容之后，它已经
  不只是复刻。

## 4. 跨项目的观察

### 4.1 第一轮的投资在第二轮兑现

- **模拟与表现分离：** 五类增强没有一项需要改动模拟、PRNG 或存档；存档身份从 1.0.0 到 1.3.0 一直是 v133。
- **证据身份：** 原版图集哈希、逐帧起始 tick、对白分页和旁白时长，直接变成增强素材的锚和生成器的拒绝条件。
- **资源供应链：** 私有素材仓库、资源清单和按关分包让 141 MiB 的新素材（1.1.0）不需要新的发布机制。
- **调试面：** 实验室和调试中心让每条特效、每段剧情都能单独重放和审阅。

### 4.2 工作台复用让速度加快

肖像阶段摸索出来的东西被后面直接沿用：Qwen 重绘的参数、H3 的“接续前段＋尾端锚定”循环、RIFE 去重复帧、
ComfyUI 运行旁注、审阅页样式、`export → --import → resource-manifest` 的导入链。剧情画面和地图特效各自只需要
解决自己的新问题（分层与云层、关键帧规划与抠图）。

### 4.3 用户是 Creative Director

几乎每一次方向性的改变都来自用户的一句话：提示词改成纯描述、角色全换 ElevenLabs、修主图而不是修逐帧、
程序特效降级、允许余韵、取消音效现代化、开场不能悄悄退回原版。AI 负责把这些判断变成可执行的流程，但没有一次
能替用户做出判断。

### 4.4 自动指标的边界

ASR 漏读率、接缝评分、像素差异和 VMAF 都很有用，但只能筛掉明显的坏结果。唇定位失败、多出来的月亮、画成男性的
士兵、循环里的一下停顿，都是看了才知道。

### 4.5 增强反过来修正了复刻

把特效放大到 4 倍、逐帧对照原版之后，发现了原版风格自己的定位偏差和取证误读。增强并不只是在复刻之上加东西，
它也是一次更细致的原版审计。

## 7. 讲述素材

### 7.1 一条可以讲的故事线

1. **起点：** 一款已经忠实复刻、能通关的 DOS 游戏，为什么还要“增强”，又怎样保证不破坏复刻；
2. **第一步选音乐：** 耦合最少，先用它跑通“可选层＋素材包＋下载门”；用户写的提示词胜过 AI 写的；
3. **一天做完语音：** 凌晨试听选角，早上上线，晚上补齐战斗台词；ASR 怎么当质检员，又在哪里会骗人；
4. **肖像的路线之争：** 四轮小样四次换方向，最后为什么把脸和嘴编进同一支视频；
5. **剧情画面的分层：** 从“男兵”到“呆板”到分层；云为什么要单独卷动；
6. **特效的转折：** 程序特效被否决，原版帧成为关键画面，AI 只负责中间；
7. **收尾：** 压缩 37%、取消音效现代化、改名“重制版”。
