# Web 复刻规则决策记录

日期：2026-07-15  
状态：设计评审中，`implementationFrozen=true`  
原版事实基线：`original-gdd.md` Draft 0.47

## 规则分层

本文件只记录 Web 复刻的产品选择，不改写原程序事实。后续实现应把规则分成三层：

1. `originalFacts`：原程序代码、数据和资源实际表现，作为不可变取证基线。
2. `stableRemake`：默认游玩规则；修复已确认的原版 bug，并保证存档与随机流稳定。
3. `legacyStrict`：可选的原版怪癖兼容模式；只复现安全且确定的差异，不模拟越界写内存等未定义行为。

Mod 规则只能覆盖 `stableRemake` 的显式配置项，不能修改 `originalFacts` 的证据记录。

## 已确认决策

### REMAKE-001：转职属性刷新但不治疗

原版的 `0744h` 提交函数只写新职业并把累计经验清零；紧接着的常规装载再按“新职业 + 经验 0”派生等级、攻击、防御、最大生命、移动和可用行动。因此“提交函数没有立即重算”是低层时序事实，玩家可见结果仍是转职完成后职业属性更新。

`stableRemake` 将这两步合成一个不可观察中间态的原子事务：

- 写入目标职业；
- 当前经验归零；
- 立即按目标职业零经验行重算等级、攻击、防御、最大生命、移动和职业行动；
- 当前生命保持原值，不按新最大生命补满，也不增加生命。

全部 31 条可达转职边中，目标职业首行最大生命均不低于来源职业转职前的第三行最大生命，因此原版数据不会产生“当前生命高于新最大生命”的额外钳制问题。

### REMAKE-002：普通射手原地最优时仍应射击

原版普通射手 AI 会在敌人曼哈顿距离 2 的八个候选落点中选择地形防御最高者，行动者当前格也可参选。若当前格胜出，重定位函数因为没有实际换格而返回失败，外层随即跳过射击；行为 1 则有独立的原地射击路径。

`stableRemake` 把“当前格就是已验证的最佳射击位”视为重定位成功，直接从原地射击；`legacyStrict` 保留跳过射击。该修正不改变玩家射程、候选评分或伤害公式。

### REMAKE-003：远追应对称考虑敌人四邻并使用行动方语义

原版默认远追只检查 `enemyCell + 50`，即 50 列棋盘中敌人下方的一格，完全漏掉上、左、右。行为 2 在追逐前还固定以模式 `A` 建图；side 2 单位因此使用了 side 1 的占用语义作预检查。

`stableRemake`：

- 对称考察敌人上、下、左、右四个合法空邻格；
- 使用当前行动方的阵营/占用语义构建预检查与移动图；
- 保留“本次只追逐移动、不追加攻击”的行为边界；
- 在合法候选之间继续使用明确、可测试的范围梯度与固定平局顺序。

`legacyStrict` 则保留 `+50` 偏向与行为 2 的模式 `A` 门控。

### REMAKE-004：毒不能把生命降到 0

原版状态链执行 `floor(currentLife / 2)`，所以序列可能为 `7→3→1→0`；到 0 后又不调用死亡移除器。这是确认过的代码行为，但作为默认规则属于 bug。

`stableRemake` 使用：

```text
currentLife = max(1, floor(currentLife / 2))
```

毒仍在原有状态 tick 时点结算并递减持续时间，但不会杀死或移除单位。`legacyStrict` 可保留原版“0 生命仍占格”的安全确定行为。

### REMAKE-005：普通物理伤害不受防魔影响

原版由战斗动画开关分成两条普通伤害路径：地图逐点路径会错误读取防魔，全屏路径不读取。该分歧保留在 `originalFacts`，但不是默认规则。

`stableRemake` 规定：

- 普通攻击与反击都是物理伤害，无论使用地图表现还是全屏表现，都忽略防魔；
- 表现设置不得改变伤害、状态或随机规则；
- 每个伤害事件必须显式标记为物理或魔法；所有魔法伤害都读取防魔并被其阻挡，不能因使用地图或全屏表现而绕过；
- 原版炎暴“伤害不检查防魔、事后却清防魔”的路径在 `stableRemake` 中按魔法伤害修复为先阻挡再消耗；
- 冰雪等不造成伤害的魔法效果另用 `effectType` 表达，其位移/免疫规则不冒充伤害类型；
- 魔弓的两段伤害、防魔消耗时点，以及 `WD` 等特殊魔法是否在阻挡后消耗防魔，仍保留各动作已经确认的多段结算顺序。换言之，统一的是“魔法伤害必受防魔检查”，不是把所有动作强行压成同一个单段处理器。

### REMAKE-006：保留魔弓的双半伤结构

魔弓选中目标承受两次半伤。防魔阻挡第一次并被消耗，第二次仍会结算；其他受线形效果波及且有防魔的单位挡住本次半伤并失去防魔。默认复刻保留该规则。

### REMAKE-007：Web 存档保存确定性随机状态

原版 `.TST` 是玩法快照，不保存 PIT 相位、随机状态或输入日志，因此同一存档后重复同样操作，不保证得到相同伤害、AI 选择或等价路径。这不表示存档内容不稳定，只表示它不是确定性重放检查点。

`stableRemake` 规定：

- 模拟层使用固定、版本化的伪随机算法，不直接使用墙钟、帧率或音频完成时点；
- Web 原生存档保存 PRNG 算法版本、完整状态和调用序号；
- 同时保存规则版本及有序 Mod/内容哈希；
- 需要战局重放时另存语义动作日志，普通存档不强制携带完整日志；
- 导入原版 `.TST` 时不伪造不可恢复的 DOS 随机未来，而是从规范化 legacy payload 哈希确定性初始化 Web PRNG；同一原版存档在相同规则/Mod 下将产生稳定的 Web 后续结果；
- 渲染、动画和声音不得消费模拟层随机数。

### REMAKE-008：保留无消费者兼容字段

`DATA.field5`、单位动态记录 `04h/06h` 和其他已确认无规则消费者的兼容字段，在导入、保存和导出时原样保留，但默认不赋予战斗效果。Mod 若使用这些字段，必须声明自己的 schema 与版本，不能声称是原版语义。

### REMAKE-009：同一动作不因阵营或控制方式改变规则参数

用户于 2026-08-02 明确决定：Web 复刻默认规则不保留原版“同一技术由 AI 使用时另取一套
范围或数值参数”的不对称。同一个语义 action ID 应代表同一套能力；玩家手动、我方自动
和敌方 AI 的差异只属于决策策略，不属于动作本身。

原版两张技术表的选择范围参数并不一致：

| 动作族 | 玩家表 | AI 表 | 原版差异 |
| --- | --- | --- | --- |
| 落雷 `1L..4L` | `4/5/6/7` | `3/4/5/6` | AI 全部少 1 |
| 炎暴 `1F..4F` | `5/6/7/7` | `4/5/6/6` | AI 全部少 1 |
| 冰雪 `1C..4C` | `2/3/3/4`（自中心玩家路径不读） | `2/3/4/5`（AI 候选门） | 都不改变固定施法者中心；后两阶只影响 AI 是否找到候选 |
| 治疗 `1H..3H` | `5/6/7` | `5/6/7` | 无差异 |
| 回復 `1I..3I` | `4/5/6` | `4/5/6` | 无差异 |

其余具有玩家/AI 同名入口的技术也已逐项比对：`1V..3V`、`1D..3D` 和八项状态动作的
选择范围完全相同；`WD` 只有 AI 专用入口，不属于同名动作对照。因此没有遗漏其他
“AI 范围少 1”的普通技术族。

射击最大距离本身没有敌我差异，但原版 AI 的两项伤害区间被单独削弱：弩兵玩家为
`70..89`、AI 为 `50..89`；魔弓兵玩家基础 roll 为 `50..69`、AI 为 `50..59`。弓兵
双方均为 `30..49`。

`stableRemake` 规定：

- 同一 action ID 的选择距离、最小距离、效果半径、范围形状、目标合法性、伤害/治疗/
  状态公式、防魔消费、多段结构和提交时点均与阵营及人工/AI 控制无关；
- 以玩家可见动作表和已经建立的语义 action definition 作为统一参数来源，不取敌我两表
  的较大值，也不按阵营动态加减；因此敌方 `1F` 使用与玩家相同的范围 `5`，`1H` 仍为
  双方原本就相同的范围 `5`；
- 落雷和炎暴使用上表玩家侧参数；冰雪不开放目标格选择，玩家和 AI 都固定以施法者
  当前格建立效果。AI 表的距离只用于施放前的敌方候选门，不成为技能 action 的中心参数；
- 弩兵和魔弓兵由 AI 使用时采用与玩家相同的伤害区间；魔弓仍保留 `REMAKE-006` 的双半伤
  结构，只统一基础 roll；
- AI 仍可在技能池、选技能、选目标、移动、评分、平局顺序和失败兜底上与人工操作不同；
  难度对单位属性的既有修正也不由本条取消；
- 没有玩家同名入口的 Boss、部件和逐关脚本动作可保留其专用规则，但必须使用独立 action
  ID 或明确的内容效果，不能暗中覆盖普通动作定义。

`legacyStrict` 保留原版玩家/AI 分表和射击数值差异；冰雪在两种规则集都保持原版的
施法者自身中心。Mod 若改变普通动作
参数，默认同时作用于双方；需要阵营专属能力时必须声明新的语义 action ID 和规则身份。

本决策在 M02 只直接改变第 1 关敌方修女的 `1F` 范围来源；`1H` 数值不变。落雷/冰雪的
敌方入口、弩兵和魔弓兵当前不在 M02 实现范围，以上内容先作为后续切片的设计真值记录，
不据此提前解冻。

### REMAKE-010：校正 D/59 弓兵的休眠眼部坐标错误

原版表 C 的 `DS:0C84` 为 `D/59` 弓兵记录眼部原点 `(40,24)`、口部原点 `(64,32)`。
资源 frame 1 是 `16×16` 的睁眼覆盖片：它在 `(40,24)` 与主肖像不匹配，在 `(56,24)`
则逐像素完全一致。原版剧情语料直接引用的 50 个肖像 id 不含 `59`，单位详情又只绘制
frame 0，因此该错误在发布版可达流程中保持休眠；全角色复刻动画首次让它变成可见错位。

`stableRemake` 将 `D/59` 的眼部原点改为 `(56,24)`，三张眼部覆盖片统一使用该位置；
口部仍保持原版 `(64,32)`。生成目录必须同时记录原始坐标、应用坐标和本决策 ID，
不得修改 `reverse/` 中的原始事实，也不得把这条例外推广到其他肖像。

### REMAKE-011：第 1 关出击准备采用现代构图

用户于 2026-08-02 明确决定：第 1 关出击准备页采用三列五行人物卡、战场预览小地图、
人物详情和底部主行动组成的现代构图，不再以原版名单热区和像素坐标作为实现约束。

原版构图、热区、坐标和调色板继续保留为 `[OF]` 证据；现代表面是 `[DD]`，不得反写
原版事实。完整布局、输入、窄屏、减少动态与验收合同见
`design/remake-gdd/systems/deployment-stage1.md`。

### REMAKE-012：用语义激活状态替代原版逐槽 AI 行为

用户于 2026-08-02 明确决定：`stableRemake` 的敌方 AI 不再以原版逐槽行为编号作为运行时
策略。原版职业行动分派和行为 `0..12` 继续完整保留在 `originalFacts`，默认复刻关卡则
使用适合现代 SRPG 的语义状态机：守卫、军团警戒和追击。

`stableRemake` 规定：

- 守卫不主动离开当前格，但当前位置有合法攻击或技术目标时可以行动；
- 军团警戒在敌方阶段开始时检测成员本回合能否造成伤害，以及此前被我军攻击／敌对技术
  成功提交的事件；普通攻击计入合法移动落点，伤害技术只计当前位置，治疗不触发，军团
  外单位的范围也不触发；任一成员触发后整团同阶段、不可逆地进入追击；
- 追击允许先移动再普通攻击；技术只能从回合开始位置施展，当前位置没有合法技术时可
  改选移动后普通攻击或只移动推进；射击继续服从其独立动作合同；
- AI 不预看 PRNG，按确定击杀、紧急治疗、有效伤害、一般治疗、推进的固定优先级选择；
- 生命低于 `40%` 且没有确定击杀或紧急治疗时可以原地休息；不实现远离敌军的撤退移动；
- 激活军团和延迟行动回合属于模拟真值，必须保存并确定性恢复；表现只投影结果。

第 1 关的首个关卡配置为：槽 `45/46` 组成第一军团 `forward-patrol` 并开局追击；槽
`40/41/42/43` 组成第二军团 `castle-guard` 并以警戒态开始；芳（槽 `16`）不属于两个
军团，以主将守卫开始。第一军团或芳能够攻击我军时不会连带解除第二军团警戒。若第二
军团在回合 `N` 解除警戒，芳在回合 `N` 仍守卫，从回合 `N+1` 的敌方阶段起追击，以
避免主将先于卫队冲到前线。该延迟在军团激活后不可撤销。

`legacyStrict` 可继续使用原版逐槽行为和职业随机池，但不得把其结果写回
`originalFacts`。Mod 可以声明新的激活策略、军团与评分器；改变这些配置必须改变规则／
内容身份。

2026-08-09 应用户要求再次复核并在设计 GDD 明列两套优先级：原版普通近战只最大化
攻击者落点地形防御，法师系先从职业／成长层池抽一个动作再选目标；`stableRemake` 仍按
本决策的确定性效用顺序运行。此次记录没有撤销 `REMAKE-012`，若要把原版排序改为默认
复刻规则，须另立决策。

### REMAKE-013：冰封不可被攻治、外圈不外推，破邪可解除

用户于 2026-08-03 明确决定：原版冰雪造成的大范围行动禁用缺少反制窗口，目标在跳过
本阵营阶段期间仍能被普通攻击、射击和技术持续伤害，使其只能被动挨打。该原版行为继续
保留在 `originalFacts`；`stableRemake` 将冰雪写入的逐单位行动禁用位命名为玩家可见的
“冰封”状态，并在同期间将单位从攻击与治疗的合法目标中排除。

`stableRemake` 规定：

- 冰封持续到目标跳过紧接着的一次本阵营阶段后解除；它不占八槽普通状态；
- 冰封不能叠加。再次命中已经冰封的单位不移动、不刷新或延长解除时点，也不消费其
  防魔；
- 原版位移比较把范围值 `0` 也视作比最外圈的 `1` 更低，因此会把最外圈单位推出技能
  范围。默认复刻要求目的格范围值仍大于 `0`：内圈单位仍可被推到最外圈，已经位于
  最外圈的单位只冰封、不移动，也不触发位移经验或随机调用；
- 冰封单位不能选择、移动、攻击、反击、射击、施术、休息或进入 AI 行动队列；
- 冰封单位不能成为普通攻击、射击、单体伤害技术或治疗的合法目标；玩家选目标、我方
  自动与敌方 AI 使用同一门禁，拒绝的动作不消费行动或 PRNG；
- 冰封单位若被以其他目标为中心的范围伤害或范围治疗覆盖，伤害与治疗均为 0；不消费
  防魔、不改变生命、不触发死亡、击杀奖励或治疗经验。未来的持续伤害也必须跳过冰封；
- AI 不能用冰封单位触发军团“本回合可造成伤害”的警戒解除条件；
- 唯一可以直接选中冰封单位的恢复类动作是“破邪” `TR`。原版 `TR` 选择距离为 7，
  会清防御下降、攻击下降、混乱、施毒与禁咒，但不读取冰雪的独立禁用数组；
  `stableRemake` 在保留这五项净化的基础上额外清除冰封。表现完整结束并原子提交后冰壳
  消失，尚未行动的目标可在当前本阵营阶段恢复行动；
- 地图上的原版冰壳持续投影整个冰封状态，直到自然解除或破邪提交，其他范围演出不能
  暂时隐藏它。

`legacyStrict` 保留原版“行动禁用但仍可受伤／受治疗、最外圈可被推出范围、破邪不能
解除”的结算。Mod 若改变持续时间、可叠加性、位移边界、目标门禁、范围免疫或净化
关系，必须声明新的规则身份。

### REMAKE-014：敌方技术提示保留原文并对焦效果中心

用户于 2026-08-03 试玩第 1 关后确认：敌方施术缺少可辨识提示且镜头不在释放点时，

### REMAKE-024：逐关职业记录只初始化未成长角色，不覆盖已转职职业

原版模块 27 进入普通战斗时先导入战役 roster，再把 B 模板 side 1 的非零职业记录写回
对应槽位。native stage `1/2/4` 的 B 模板都为槽 `24` 葛蒂拉斯写入职业记录 `6`
“魔術士”；因此原版即使已经把她转职为邪法師、魔法師或巫師，进入这些关卡仍会把职业
改回魔術士，同时保留累计经验。这是原版装载顺序的确定事实，不是 Web 内容声明应继续
制造的角色成长回退。

`stableRemake` 把该非零记录解释为角色首次进入战斗时的职业基线：只有战役槽缺失，或仍
保持新战役默认的士兵／零经验状态时，才把葛蒂拉斯初始化为魔術士；一旦 roster 已保存
实际成长状态，后续关卡必须完整继承职业与累计经验，当前生命仅在新职业最大生命以下
钳制。由魔術士到邪法師、魔法師或巫師的合法转职都可跨第 2、4 关保存、部署和恢复，不得
因 B 模板、调试夹具或存档校验退回魔術士。地图单位图形按继承后的语义职业从共享目录
加载，不能把未登记的高阶职业静默画成士兵或缺失纹理。

v13–v15 战中档保存了不可变入关 roster；若旧运行时已经把当前 roster 与战场单位都错误
写成魔術士，v16 迁移从该快照恢复原职业，同时保留当前累计经验和当前生命（仍受恢复职业
最大生命钳制）。完成档没有入关快照，无法在邪法師、魔法師、巫師之间无歧义反推，不做
猜测性迁移。

`legacyStrict` 将来可按原版顺序强制写回记录 `6`，但必须与 `stableRemake` 使用不同规则
身份。Mod 若改变角色首次职业或允许其他模板覆盖，必须显式声明初始化条件与存档语义。

### REMAKE-025：工兵构筑使用可达玩家路径，并把动态地形纳入规则与存档

模块 29 的玩家 `1K/2K` 分支在选定空格后先沿 mode `M` 的路径移动工兵，再以其新位置
为中心按 `+50/-50/+1/-1` 调用邻格助手。助手只跳过逻辑地形槽 `0`，其余邻格写入该关
配置的构筑源 token；中心格不变。动作表中另有一组 `1K/2K` 包装器会横向写入五个连续
token，但正常玩家分支在 `0000:761A..762F` 直接跳到 `0000:76C0`，不会调用这些包装器；
普通 AI 类别也没有产生构筑动作的技术池。复刻版不能把不可达包装器误作玩家效果。

原版邻格助手使用线性偏移，在地图左右边界可能跨行；更坏的越界结果取决于相邻 DOS
内存，不是可移植的关卡规则。原版地图重绘直接读取已修改的地形缓冲，而当前 Web 地图
底图是静态图片；若只覆盖画面、不更新模拟和存档，会令移动、地形防御、AI 与读档互相
矛盾。

`stableRemake` 规定：

- `1K` 复现正常玩家可达流程：固定 seed `5` 的 mode `M` 选择空格、播放普通移动，随后
  同时把几何上的下、上、右、左四个邻格中非槽 `0` 的格改成该关 `iron-plate` 动态地形；
  中心格、单位、生命、经验、状态与 PRNG 不变，行动位在成功后消费；
- 邻格必须同时满足 `0 <= x < width`、`0 <= y < height`；越界方向直接跳过，不跨行、
  不访问地图外内存。处于合法邻格上的单位不阻止铺设，后续立即按新地形计算；
- 动态地形是模拟状态。地形检查、移动代价、合法范围、地形防御、攻击、AI 规划和地图
  覆盖图统一读取同一份覆盖表；战中档保存有序的语义覆盖 `{position, kind}`，恢复时验证
  边界、唯一性和关卡支持的 kind，不能保存 DOS token 或浏览器贴图路径作为领域身份；
- 原版没有独立构筑图形、声音、描述符或等待。原版表现模式只播放已有的逐格移动，提交
  后立即以该关原始 40×44 铁板 tile 覆盖邻格；不得添加烟尘、闪光或人为停顿。动画速度
  只能缩放移动墙钟，不能改变提交时点或地形结果；
- 工兵仍走原版 ordinary AI 类别，不自动使用 `1K/2K`。竞技场可以由玩家直接验证
  `1K`，但不能为了展示而给敌方工兵新增原版不存在的构筑决策。

`legacyStrict` 将来可另行提供线性 `+50/-50/+1/-1` 的行边界跨越语义，但仍必须把索引
限制在已分配的 `50×50` 地图缓冲内，不模拟相邻 DOS 内存破坏；休眠的横向五 token
包装器只能作为取证工具入口，不能成为正常玩家菜单动作。Mod 若改变 seed、邻格顺序、
跳过槽、动态地形种类或视觉 token，必须改变规则／内容身份。

### REMAKE-026：防魔 AI 孤项使用玩家动作定义安全修复

原版魔導師第三层 AI 池为 `3H/2I/AA/FM`，但 33 项 AI 动作参数表没有 `FM` 行。

不因本决定自动映射为 `OJ`。

### REMAKE-049：落雷双相电波恢复两层，并修复单位标记层的高字节比较

原版落雷的电波每次绘制调用两个写入器，都写 `DS:58A5h` 的 `10×7` 地图特效 sprite 层：

- **扫描层** `0000:6599 → 0000:97DC → 0000:65A5`：对范围值非零且落在当前扫描带的格写入
  `范围值 − 当前阈值` 作为 sprite 码，`0000:7EDD` 按 `帧 = 码 − 1` 贴图、码 `0` 不画。
  不读取阵营，也不要求格上有单位。因为范围图中心值最高，画面表现为自中心向外扩散、
  每圈落后一次绘制的爆闪。
- **标记层** `1000:6E46`：对范围值非零、落在同一扫描带、且阵营等于 `DS:1EF6h` 的格，交替
  绘制逐级固定的两个 tile 码。`2L/3L/4L` 指向各自资源末两帧的“角色被电击”专用美术，
  `1L` 的 `MAGIC/31` 没有人物美术，改用序列中最盛的两帧。

逐级帧预算证实两层划分：`2L/3L/4L` 满足 `帧数 = 波宽 + 2`（`7=5+2`、`6=4+2`、`13=11+2`），
`1L` 为 `12` 帧、波宽 `9`。

`[OF]` 标记层在发行版里永远不会绘制：`1000:6E52` 用 `mov al,[es:di]` 读范围值时 `AH` 仍是
`DS:01A9h` 范围图段的高字节（`2FH`），随后 `1000:6E5F` 却做 `cmp ax,[0x5228]` 的字比较，
结果恒大于波宽 `4/5/9/11`，`ja` 恒跳过。全模块只有此处出现“字节读后紧跟字比较”，同语义
判定在 `0000:65A5` 写法正确；`DS:01A9h` 只被 `0000:FFF6` 写入一次立即数 `2FCH`，实模式下
高字节不可能为 `0`。

`stableRemake` 同时绘制两层，并按设计意图修复该比较，使标记层真正叠加在扫描带内的敌方
占用格上。判定条件按原生语义保留差异：扫描层要求码 `1..波宽`（码 `0` 不画），标记层要求
码 `0..波宽`。逐级资源、波宽、tile 码、绘制次数、`2` tick 等待、`(范围图最大值−1)+波宽`
轮数、固定图形等待与提交时点全部不变；本决定只影响画面，不改变伤害、经验、PRNG、存档
语义或规则身份。

`legacyStrict` 可只画扫描层以复现发行版的实际画面。Mod 若替换逐级资源、波宽或 tile 码，
必须改变内容身份。
