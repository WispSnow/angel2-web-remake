# 普通攻击、反击、生命、经验与累计成长

日期：2026-07-14

## 结论

模块 29 的普通攻击链已经从选定攻击者/目标一直追到地形防御、伤害、反击、状态写入、生命归零、死亡移除、经验累加和第三成长行后的外推规则。新战斗的难度经验播种、双方属性重建和生命回满顺序也已由 `battle-lifecycle.json` 的签名闭合。以下公式均为原生机器码直接确认。

机器可读结果为 `reverse/parsed/native/combat-formulas.json`，重复导出命令：

```sh
node reverse/tools/angel2-combat-formulas.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/parsed/native/unit-descriptors.json \
  reverse/parsed/native/combat-formulas.json
```

导出器会验证 44 段关键代码签名、35 项击杀经验表、23 项第三行后成长表和完整回合状态链；任一地址不再匹配便失败。

## 战斗对象和属性

普通攻击入口 `0000:90D8` 使用：

- `77BFh`：攻击者棋盘格；
- `77C1h`：防守者棋盘格；
- `31BFh/31C1h`：装入状态与难度/状态修正后的有效攻击/防御；
- `31C7h`：当前 `DATA` 行等级；
- 单位状态 `+00h`：当前生命；
- 单位状态 `+02h`：累计经验；
- 单位状态 `+0Ch`：最高位在地图结算路径中阻止移动和逐点扣血。

攻击入口会先由 `0000:9123` 把攻击者棋盘单位槽字节 OR `80h`。所以攻击会消耗该格单位的行动标志，即使最终伤害为 0；伤害动画不是行动消耗的触发点。

## 随机数

`0000:95D2` 从 PIT 通道 0 的 I/O 端口 `40h` 读取一个字节，若结果大于调用者给定的 `DX` 就重读。普通攻击传 `DX=3`，随后加 4，因此每次调用的结果域严格是 `4..7`。

这证明值域，但不能仅凭机器码断言四个结果在现代统计意义上均匀。复刻原版体验时应先把它建模成独立的 `random4to7()`；若以后要求逐周期 DOS 硬件复现，再替换随机源。

## 地形防御

`0000:946A → 1000:41A1` 用棋盘地形字节和当前兵种 profile 取出一个百分数。攻击者与防守者分别计算：

```text
terrainDefense = floor(effectiveDefense * terrainPercent / 100)
```

因此地形值不是直接加到防御上的点数，而是当前有效防御的百分比加成。后续 `MAP` 轮次已确认它来自第二张 23 槽逻辑 profile；物理第 24 字是重叠字。token→瓦片→逻辑槽映射已闭合；对 DS:`2E7D` 的全部六个战斗读取点审计未发现原版名称路径，因此槽以数字 ID 记录，见 `movement-terrain-rules.md`。

## 新战斗的难度经验播种

模块 29 新战斗入口只在 `CONTINU=='N'` 时执行难度播种；编号 `WAR` 恢复不会重复执行。除场景 3、8、11 外，`0000:4ABE` 以 `LV_HARD+1` 为次数重复调用 `0000:538B`。后者选中 side 2 的 57 个动态槽，并让回调 `0000:539B` 对每个活动单位执行：

```text
experience = nextCumulativeExperienceThreshold + 1
```

所以难度 0 也会让敌军跨过一次阈值，四档并非“前三档属性相同”。每次写经验后，`0000:540D` 重新选择前三行职业数据或应用第三行后成长；最终 `0000:536B/537B` 分别重建双方并把当前生命回满到最终最大生命。

第 0 关由该顺序得到：

| 难度 | 九名敌方士兵：等级/经验/攻/防/生命 | 哈釘：等级/经验/攻/防/生命 |
| --- | --- | --- |
| 過關斬將 | `2/101/42/24/170` | `2/181/60/33/230` |
| 勢均力敵 | `3/201/45/27/180` | `3/361/65/36/260` |
| 困難重重 | `4/301/46/27/190` | `4/461/66/36/270` |
| 無法無天 | `5/401/70/40/300` | `5/561/100/54/420` |

士兵/骑兵基础移动仍为 4/8。第 0 关行为 12 的本次路线移动覆盖为 5，是另一条关卡专用规则。

## 最高难度敌方属性加成

通用单位装载链在应用职业/等级属性和场景专用覆盖后调用 `1000:8BD1`。该函数只在 GO 原符号 `LV_HARD==3` 且当前阵营为 side 2 时修改：

```text
baseAttack    += floor(baseAttack / 2)
currentAttack += floor(currentAttack / 2)
baseDefense   += floor(baseDefense / 2)
currentDefense+= floor(currentDefense / 2)
maxLife       += floor(maxLife / 2)
```

移动、等级、当前生命和经验不在此函数中修改；新战斗稍后的回满步骤会把当前生命写成已经加成的最大生命。由于加成发生在场景 37 的 Boss 统一覆盖之后，其三部位会从攻 100、防 10、最大生命 10,000 变为攻 150、防 15、最大生命 15,000。`LV_HARD` 的四个原版可见名称依次为“過關斬將/勢均力敵/困難重重/無法無天”。

### 装载顺序：状态修正先于难度倍率

`1000:8BD1` 不是只在新战斗播种时跑一次，而是每次按棋盘格装载单位属性时的最后一步。
近调用包装 `0000:502A` 与远调用包装 `0000:5058` 的函数体完全相同：

```text
0000:502A → 1000:8C0F   读棋盘格得到职业短码与行动位
          → 0000:5087   选择阵营指针表并写 DS:31C9
          → 0000:51EC   → 0000:5256  按累计经验选 DATA 行，写基础攻 31CF / 基础防 31D1
                        → 1000:8C2D  有效攻 31BF = 31CF、有效防 31C1 = 31D1，
                                     再按 +08h/+0Ah/+10h/+12h 的 bit 15 做 ±20
          → 1000:8B60   场景 37 的 side 2 统一覆盖（直接改写 31BF/31CF/31C1/31D1/31C3）
          → 1000:8BD1   LV_HARD==3 且 side 2 时对 31BF/31CF/31C1/31D1/31C3 各 += 值/2
```

普通攻击链正是这样取数的：`0000:93F2/942E → 0000:955D → 0000:502A`，随后把 `31BF`
读进攻方/守方攻击、把 `31C1` 读进防御并用于地形防御百分比。

由此得到两个必须复刻的推论：

- 难度 3 的 side 2 单位，状态 `±20` 会跟着 `×1.5` 一起放大。因为
  `(v ± 20) + floor((v ± 20)/2)` 与 `v + floor(v/2)` 恰好相差 30，
  「無法無天」的敌方攻击下降／防御下降是 **降低 30 点**，攻击提升／防御提升是
  **提高 30 点**；side 1 与其余三档难度仍是 20 点。
- 场景 37 的统一覆盖排在 `1000:8C2D` 之后且整字改写，所以该关 side 2 三部位的
  有效攻／防完全不受四个 ±20 状态影响。这一条与
  `../../design/remake-gdd/vertical-slices/stage-37.md` 现有的「各降低有效攻／防 20」
  记载冲突，冲突与来源见该文件的待决条目，尚未据此改动实现。

`1000:8C2D` 的 `sub` 没有下限夹取，`1000:8BD1` 用的又是逻辑右移 `shr`，所以基础值
低于 20 的单位吃到下降状态后会得到 16 位回绕的巨大无符号值；伤害公式 `0000:94B0`
的饱和判断是无符号 `jnc`，因此这些单位在原版里表现为「伤害恒为 0」。复刻当前对有效
攻／防取 `max(0, …)`，这条回绕未复刻，属已知差异。

## 伤害公式

令 `r1,r2 ∈ {4,5,6,7}`，则先攻伤害为：

```text
primaryDamage =
  max(0, attacker.attack - defender.defense - defender.terrainDefense)
  + r1 + r2
```

随机总加成为 `8..14`。这是原版一个必须保留的细节：`0000:9490` 加第一次 `4..7`，紧随其后的 `0000:94E3` 又把第二次 `4..7` 加到 `77D3h` 的先攻伤害，而不是反击伤害。反击基础伤害为：

```text
counterDamage = floor(
  max(0, defender.attack - attacker.defense - attacker.terrainDefense) / 2
)
```

该反击基础值没有普通随机加成。完整普通攻击计算链没有命中/闪避或暴击分支；它总会产生一个非负伤害值。此结论只覆盖普通物理攻击，不外推到魔法或“技”。

## 反击条件和职业特例

先攻结算后，只有同时满足以下条件才进入反击：

1. 先攻后双方生命均不为 0；
2. 攻击者短码不是 `0G`，即巨斧战士；
3. 防守者的逐单位禁用字节为 0。

所以巨斧战士的普通攻击会压制反击。防守者禁用字节来自双方各 75 字节数组；它同时参与单位可选择性和 UI 状态，但业务名称尚未完全恢复，当前不把它擅自命名成眩晕、待机或已行动。

若防守者是短码 `2E` 的兽骨骑士，`0000:94E3` 直接读取一次 PIT 值；最低位为 1 时把反击伤害改成完整的 `primaryDamage`，并在地图动画路径设置专用表现标志。它是 50% 候选分支，但精确概率仍依赖 PIT 采样时序。

## 两种伤害呈现路径

`DS:1119` bit 0 选择两套表现：

| 路径 | 选择值 | 生命结算 | 原生边界 |
| --- | --- | --- | --- |
| 地图动画 | bit 0 = 0 | `0000:783D` 每动画一步扣 1 点，最低为 0 | 状态 `+0Ch` bit 15 会跳过每次扣血 |
| 全屏战斗动画 | bit 0 = 1 | `A096/A0C6/A0F6/A10C/A122` 对镜像生命一次饱和减法，再写回 `+00h` | 已恢复的直接减法不检查 `+0Ch` bit 15 |

第二行是原版代码真实存在的路径差异，不应在复刻时悄悄统一。后续实机测试要确认该状态是否只会出现在不会进入全屏战斗的对象上；在此之前应把差异作为兼容开关/原版行为测试保留。

两条路径的视听层现已另行闭合：地图受击 `UN/62 + E/38`、地图死亡 `MAGIC/12`、全屏职业 `M_00/Y_00` direct/+50 选择、五槽职业音效、先攻/反击与 `E/11` 死亡同步见 `ordinary-combat-presentations.md` 和 `combat-presentations.json`。数值公式仍以本文件为规范，两份清单通过 `77D3h/77D5h` 伤害输入连接，不重复计算。

普通伤害链的死亡扫描 `0000:96C2` 遍历 2,500 格，对当前生命为 0 的单位调用移除路径并清当前棋盘格。反击判断发生在先攻后的存活检查之后，所以被先攻击破的单位不会反击。完整回合毒伤链不调用这个扫描器；被毒减至 0 的单位仍留在棋盘并可被选择/休息，详见 `status-lifecycle.md`。

## 水戰士受击分裂

地图普通攻击路径 `0000:927A` 与全屏普通攻击路径 `0000:9296` 都在先攻、可选反击和职业附加状态之后调用 `0000:931B`；射击、技术与逐关伤害路径不调用该函数。处理器重新装载原始防守者格 `DS:77C1`，只在该格仍存在且防守者短码为 `0N/水戰士` 时继续。因此水戰士作为主动攻击者承受反击不会触发分裂；先攻致死也不会留下可见分裂体。

`0000:9372` 扫描全部 2,500 个棋盘格，统计阵营字节和单位槽字节都与原防守者相同的格数。已有数量达到 4 时停止；否则 `0000:939E` 依次尝试原防守者格的上 `-50`、下 `+50`、左 `-1`、右 `+1`，选取第一个空且移动规则不为 `98/99` 的格，复制原格的阵营字节与单位槽字节后立即返回。结论是：

- 每次符合条件的普通近战受击最多新增 1 个分裂体，场上总数最多 4 个；
- 相邻格按上、下、左、右固定优先级选择，四格均非法时不分裂；
- 处理器不读取 PIT 或其他随机源，合法时必定分裂；
- 没有独立分裂动画或声音调用，新格由棋盘写入直接出现；
- 所有分裂格保留同一单位槽号，因而共享该槽的生命、经验和八个状态字；行动高位属于逐棋盘格字节，只在创建时从原格复制；
- 任一格对应的共享生命归零后，`0000:96C2` 会在全棋盘扫描中清除指向该零生命槽的全部分裂格。

机器规格见 `combat-formulas.json#waterWarriorSplit`，关键签名为 `0000:931B/9372/939E`。

## 普通攻击附加状态

普通攻击附加的四种状态均直接覆盖为 `8003h`，但只由主动攻击触发。模块 29 的 `0000:92DC` 在一次普通攻击（包括后续可能发生的反击）结算链中只调用一次（地图／全屏两条互斥路径的调用点为 `0000:928F/92AF`）；它从原始攻击者职业与防守者单位加载状态，反击分支只计算伤害，不再次调用该处理器。因此，具有普通攻击附加状态的单位在被动还击命中时不会给主动攻击者附加状态。每个完整玩家+自动+敌方回合结束后，原生倒计时执行 `8003h → 8002h → 8001h → 0000h`；重复主动命中会刷新为 `8003h`。

| 攻击者 | 短码 | 防守者状态偏移 | 已确认效果 |
| --- | --- | ---: | --- |
| 魔剑战士 | `1G` | `+12h` | 该位生效时有效防御 -20 |
| 兽骑士 | `1E` | `+10h` | 该位生效时有效攻击 -20 |
| 邪剑战士 | `2G` | `+0Eh` | 写入与技术 `LA/混亂` 相同的状态槽；进入 AI 装载时把行为强制覆写为 `FFh` 并走职业相关的移动后结束动作 |
| 丛林战士 | `0H` | `+14h` | 写入与技术 `IP/施毒` 相同的状态槽；每次完整回合边界使当前生命变为 `floor(当前生命/2)` |

另外，状态 `+08h/+0Ah` 的 bit 15 分别使有效攻击/防御 +20；`+10h/+12h` 分别使有效攻击/防御 -20。`1000:8C2D` 写入的这个加减量本身是固定 20 点，不是百分比，但它在装载链里排在难度加成之前，所以最高难度的 side 2 单位实际相差 30 点，见下一节。

## 经验奖励

`1000:8CDD` 明确执行 `unitState[+02h] += award`。先攻者和反击者的奖励根据目标是否已被死亡扫描移除而分支：

| 情况 | 经验奖励 |
| --- | --- |
| 先攻命中，目标存活 | `目标等级 + random4to7()` |
| 先攻击破目标 | `击杀表[目标短码] + random4to7()` |
| 反击命中，目标存活 | `floor((目标等级 + random4to7()) / 2)` |
| 反击击破目标 | `击杀表[目标短码] + random4to7()` |

因此反击只有在未击杀时经验减半；反击击杀仍取完整职业击杀值。

两条原版表现路径的 PIT 取值顺序并不相同。地图路径 `0000:927A` 先调用 `0000:91F1`
结算先攻经验，再在发生反击时调用 `0000:9161` 结算反击经验；全屏路径 `0000:9296`
完成死亡扫描后按 `0000:9161 → 0000:91F1` 的反序调用。两路公式和值域一致，但同一串
硬件采样可能分配给不同一方。Web `stableRemake` 必须另选不受表现开关影响的固定顺序。

## 累计经验与第三行后成长

普通战斗奖励只做加法，不扣减经验。`0000:5256` 总是先装 `DATA` 第一行，再在累计经验达到第二、第三行 `field0` 时依次替换，因此这些是累计阈值。

达到第三行后，`1000:8E85/8E62` 不读取 `DATA` 第四、第五行，而是从第三行阈值开始循环：

```text
nextThreshold = thirdRowThreshold
repeat:
  nextThreshold += thresholdIncrement
  if currentExperience < nextThreshold: stop
  effectiveAttack += attackIncrement
  baseAttack += attackIncrement
  maxLife += maxLifeIncrement
  growthRowCount += 1
```

该外推不增加防御。23 个职业有专属步长：
