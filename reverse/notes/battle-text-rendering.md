# 战斗文字绘制：字体、光标与右栏文字布局

日期：2026-08-19

## 结论

模块 29 的右栏身分列、五行数值、状态剩余回合、回合框与底部关卡名不是面板图，也不是
宿主字体：它们全部由 `0000:EA04` 一个 `$` 结尾的 Big5 字符串绘制器画出。本轮用 16 段
代码、5 段数据签名闭合了字体绑定、码表查找、光标前进量、两种外框形状、墨色/外框色、
数值与身分栏格式化、回合样板、面板底纹和关卡名底条。

`unit-detail-hud-presentations.md` 之前把「native glyph rasterization」列为未解项，
现已关闭。机器规格位于 `../parsed/native/battle-text.json`，合并字体位于
`../parsed/native/battle-text-font.json`。重复导出命令：

```sh
node reverse/tools/angel2-battle-text.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/extracted \
  reverse/dumps/bios-font-8x8.bin \
  reverse/parsed/native/battle-text.json
```

## 战斗字体绑定

`0000:5006` 用 `BX=0Dh`（启动指针表第 14 项 `UN.SWF`）连读两条记录，并把它们分别写进
绘制器的码表远指针 `DS:F88B/F88D` 与字模远指针 `DS:F88F/F891`：

| 记录 | 内容 |
| --- | --- |
| `UN/58` | 419 个 Big5 双字节码加 `0000` 终止项 |
| `UN/59` | 419 个 `16×15`、每字 30 字节的位图字形 |

底部关卡名是唯一的例外：`0000:4F41` 会临时把两个远指针换成该关卡自己的
`NUM`／`CHA` 记录，画完再换回来，和剧情逐字渲染用的是同一套子集机制。

查找由 `0000:EAE5` 线性扫描码表完成，上限 `0BB8h` 字节、哨兵 `2424h`。**未命中时它
返回扫描停下的那个索引**，也就是会画出一个无关字形；复刻改为跳过该格但保留光标前进，
理由记在 `web-remake-rule-decisions.md` 的 `REMAKE-117`。

## 半角字形来自 BIOS ROM

`0000:EC6C` 不读任何游戏资源：它按 `F000:FA6E + 字符 × 8` 直接取 BIOS 的 `8×8` ROM
字模，并把**每一行存两遍**，得到 `8×16` 的半角格。`CS:ECAD` 是紧凑模式开关，发布版
默认 `'Y'`；写成 `'N'` 时不做行加倍（`8×8` 落在 16 行格的上半），并改用另一套外框。

因此数字、`/` 与 `?` 用的是 IBM PC 的 `8×8` 字面，不是原版自带字形。该表属于宿主
BIOS 数据，复现方式是从 DOSBox-X 直接导出 `F000:FA6E` 起的 2,048 字节：

```sh
node reverse/tools/angel2-battle-text.mjs --emit-dump-com reverse/work/DUMP.COM
SDL_VIDEODRIVER=dummy dosbox-x -nolog -fastlaunch -exit \
  -c "mount c reverse/work" -c "c:" -c "DUMP.COM"
```

产物固定在 `reverse/dumps/bios-font-8x8.bin`（`sha256`
`30458156768e070bc34ec72ed3485f002620da4619e4b4bab956779249aca363`），提取器每次都会
核对它的摘要。

## 光标与外框

`0000:EA04` 逐字节读入，规则如下：

| 输入 | 行为 |
| --- | --- |
| `24h` `$`、`0Dh`、`00h` | 结束 |
| `7Ch` `\|` | X 回到起点、Y `+20` |
| `09h` 制表 | X `+72` |
| `20h` 空格 | X `+8` |
| 其余 `≤ 7Fh` | 画半角格，X `+9`（紧凑模式 `+8`） |
| `> 7Fh` | 取下一字节组成 Big5 对，画全角格，X `+16` |

**空格前进 8 而绘制出的半角格前进 9**，所以「五个字符的数值栏」在前导零变成空格后
实际宽度会缩短 1 像素／位。

外框不是阴影，而是把字形按行偏移 OR 成的膨胀掩码：全角在 `0000:ECCC` 用偏移 `0/1/2`
得到 17 行，半角在 `0000:ED03` 用偏移 `0/2` 得到 16 行（行已加倍，两者等价）。每个字
画三遍——掩码在 `(x, y)` 与 `(x+2, y)`，字形本体在 `(x+1, y+1)`。紧凑模式在此之前
另加四遍色 0 掩码 `(x-1,y)`、`(x+3,y)`、`(x,y-1)`、`(x,y+1)`。

墨色取 `DS:F93C`、外框取 `DS:F93E`；战斗全程为 15（白）与 0（黑）。

## 右栏文字布局

- **身分列**：`0000:EFFE` 把职业**靠右**填进 `DS:5DEF` 的八字节缓冲，`0000:F051` 把
  单位名**靠左**填进 `DS:5DFB`，两者都以半角空格补齐。因此职业末格永远贴着 `(552,124)`
  的全角斜线，两字职业从 `x=516` 起而不是从 `x=484` 起；单位名固定从 `(564,124)` 起。
  八字节即四个全角字，发布版没有更长的职业或人名。
- **五行数值**：`DS:5E64..5EA2` 的五条样板本身就是完整字符串（`生命00000/00000 ` 等），
  由 `0000:8C30` 画在 `(488,154/175/196/217/238)`。`0000:EF56` 把数值转成五位十进制后
  把前导零改成空格，整栏为空时补回最后一位（所以 0 显示为四空格加 `0`）。**数值不是
  靠右对齐到面板内缘的**：它跟在标签后面，按上述前进量落点。
- **回合框**：`DS:600B` 的 `第  10  回合` 只有中间三个字符会被替换（`0000:892B` 取
  转换缓冲的后三位），起点 `(516,327)`。
- **状态剩余回合**：按 `DS:5F8D/5F9D` 的图标槽紧凑排列，数字画在 `(图标X-6, 图标Y+20)`，
  且这一处用紧凑模式。

## 面板底纹与两条不画的矩形

`0000:8962` 先用 `DS:5FD1` 的 `20×2` 图案（行 0 `AAh`、行 1 `55h`）在 `(480,150)` 起
以 2 行步长重复 86 次，**用色 0 打 50% 棋盘点阵**，再画外框与五行分隔框。底纹不是不透明
底：它压在刚画完的战术小地图上，所以小地图会从点阵缝隙里透出来。

`0000:89DC` 逐行只画四个矩形：色 14 的横线、色 0 的上缘阴影、以及左右两条色 0 内缩线。
`DS:5F49`（色 15 的行底白线）与 `DS:5F7B` 虽然被写入 y 值，**整个模块镜像里没有任何一处
把它们的地址送进矩形绘制器**，因此原版每行没有下缘白线。

## 底部关卡名

`0000:4C44` 在画 `A/0` 底角图之前先铺两条矩形：`DS:3051` 是 `(0,332,480,18)` 色 14、
`DS:305B` 是 `(80,333,320,16)` 色 1。随后 `A/0` 的 frame 6/7 落在 `(0,331)` 与 `(400,331)`
盖掉两端，所以玩家看到的只有 `x=80..399` 之间 `y=332` 与 `y=349` 两条金线。

`0000:4F41` 用当前关卡号查 `DS:30BA` 的 `(关卡, SAY 记录)` 表；记录为 0 表示该关没有
关卡名。命中后把 `SAY` 记录读进 `DS:309C`，换上同号 `NUM`／`CHA` 字体子集，把光标放在
`(120,333)` 再调用绘制器。**横向位置完全由数据决定**：34 条记录里 28 条以一个制表符
开头（`120 + 72 = 192`），其余用空格自行缩排。表中 38 关出现两次，前一条 `SAY/161`
（`瑪姬的墓園`）先命中。

## 一套字体，九个数组

`raw-glyph-assets.md` 之前只闭合了 `A/23`→`A/24` 一对码表。实际上九个 `16×15` 字形
数组全都有配对码表，并且它们与 176 组 `NUM`／`CHA` 子集**共用同一套字模**：

| 码表 | 字形数组 | 字形数 |
| --- | --- | ---: |
| `A/8` | `A/7` | 415 |
| `A/12` | `A/13` | 60 |
| `A/23` | `A/24` | 228 |
| `UN/7` | `UN/8` | 129 |
| `UN/9` | `UN/10` | 258 |
| `UN/41` | `UN/42` | 29 |
| `UN/58` | `UN/59` | 419 |
| `B/92` | `B/93` | 136 |

（`UN/39`+`UN/40` 的 95 项部署错误字模另有自己的表格式，见
`error-and-outcome-presentations.md`，未并入本次合并。）

把这八对与全部 176 组子集按 Big5 码合并后共 **1,253 个不同字符、0 处冲突**——没有任何
一个字符对应到两张不同位图。提取器把这条不变量作为断言，合并结果同时是复刻运行时字体
图集的唯一来源。

## 实现边界

- 字体与光标属于表现层。数值仍由模拟层给出，HUD 只做格式化后绘制，不得反向驱动规则。
- ROM 半角字模是宿主 BIOS 数据而非游戏资源，因此以导出摘要固定，不随游戏素材版本变化。
- 关卡名的原版内边距只对原版记录成立；复刻自己的关卡名若与记录不同，落点回退到
  「一个制表符」的多数写法。
