# 战场范围、目标选择与地图特效层

日期：2026-07-15

## 结论

原版没有用一套彩色 sprite 覆盖层显示移动、攻击、射击或技术范围。模块 29 维护一张 DS:`01A9h` 指向的 `50×50` 临时范围图；每个可见格的字节进入 `CH`。字节非零时照常绘制完整地形，字节为零时把同一块 `40×44` 地形的四个位平面逐行与 `11h/44h` 交错掩码相与，只保留 25% 像素。因此玩家实际看到的是“合法格保持原亮度、其他格被黑色网点压暗”。

这张图同时是交互真值：移动、普通攻击、射击、技术和工兵选格循环的主操作都先调用 `0000:785E`，只接受当前格范围字节非零；随后再执行空格、阵营或技术专用验证。退出选择后，`1000:3A7C` 把 2,500 字节全部填为 1，恢复全图原亮度。

机器规格位于 `../parsed/native/range-presentations.json`。核验图 [`../renders/range-presentations/terrain-bright-vs-dither.png`](../renders/range-presentations/terrain-bright-vs-dither.png) 左侧是实际 `B/0` 地形 token 17 的非零态，右侧是原生 `11h/44h` 位掩码后的零值态，均放大四倍。重复导出命令：

```sh
node reverse/tools/angel2-range-presentations.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/decoded/B \
  reverse/parsed/native/battle-templates.json \
  reverse/parsed/native/range-presentations.json \
  reverse/renders/range-presentations/terrain-bright-vs-dither.png
```

导出器校验 34 段代码、1 段数据、模块整体哈希、B/0 四个位平面及 B/1 模板，且断言每块 1,760 像素中恰有 440 像素被保留。

## 五张逐格图与两套可见缓存

模块初始化 `0000:FFD4` 固定了主要棋盘段：

| 层 | 指针/地址 | 运行时段 | 尺寸 | 当前格寄存器 |
| --- | --- | --- | --- | --- |
| 地形 token | DS:`01A7h` | `2EAFh` | `50×50` 字节 | `CL` |
| 范围临时图 | DS:`01A9h` | `2F4Ch` | `50×50` 字节 | `CH` |
| 单位槽图 | DS:`0022h` | `3086h` | `50×50` 字节 | `DL` |
| 阵营/占用图 | DS:`0024h` | `3123h` | `50×50` 字节 | `DH` |
| 地图特效可见缓存 | DS:`58A5h` | 当前 DS | `10×7` 字节 | 单独读取 |

`0000:7E2A` 按同一线性格读取前四项。`7E6C` 为 A000/A800 两个 VGA 页各保存四份 `10×7` 缓存：地形、阵营、单位槽和范围字节。当前页任一源字节变化才重画该格；所以范围图从零变非零或反向变化都会直接触发重绘。

DS:`58A5h` 不参与这四字节比较，也不是范围图。它是另一个地图特效 sprite 层，其写端通过把地形缓存置 `FFh` 强制合成。此前把它称为“范围/命中叠层缓存”的结论现已撤销。

## 零值与非零值的确切画法

`0000:82A4` 只检查 `CH` 是否为零：

- 非零：清掉 `CH`，由 `388Ah` 把地形 token 对应的四个位平面完整写入。如果“地圖方格”打开，单平面入口 `3960h` 改走 `3DCAh` 的格线边缘版本；范围值的具体大小不改变颜色或图案。
- 零：清掉 `CH`，由 `38F5h` 对四个位平面调用 `427Ah`。偶数行的五个源字节分别与 `11h` 相与，奇数行分别与 `44h` 相与；未保留位写为调色板索引 0。

位顺序为 MSB first。`11h=00010001b`、`44h=01000100b`，每字节各保留两位，且逐行错开，所以保留比例严格为 1/4。这不是半透明、不透明颜色填充或额外素材；以后兼容实现若使用 Canvas/WebGL，可做等价像素效果，但原版模式的判定必须仍是 `scratch != 0`。

## 中性态、刷新与输入门

`1000:3A7C` 把全范围图填成 1。它在战斗主循环初始化、完整回合开始、三类行动菜单返回、移动/射击/技术/工兵取消或结束，以及多条脚本移动/表现链后调用。因此中性态不是全零，而是全 1：所有地形完整显示。

进入目标或落点循环前，`0000:7C00` 会分别对 A000/A800 两页更新光标/视口线性格并重画 `10×7` 战场。循环中的主操作按以下顺序验证：

1. 指针 X 不超过 440，当前格位于战场区；否则 `785Eh` 返回 0。
2. 读取 DS:`01A9h[DS:5A09h]`，为零则拒绝。
3. 通过当前动作额外的占用、阵营或技术目标规则。

次操作把动作状态写成 `CT`，并由对应流程恢复选格前的单位格、视口原点和指针位置；外层再把范围图填 1。范围图因此同时是表现输入和规则输入，不能让 HUD 自行重算一份近似范围。

## 普通攻击

玩家普通攻击 `0000:7097 → 1000:3EF7` 先清零范围图，再依次检查当前格 `-50、-1、+50、+1` 四个正交邻格。内部近调用偏移 `0571h` 必须按 Borland 内部代码段基址换算到文件偏移 `13F41h`；它只接受：

```text
sideOccupancy[neighbor] != 0
AND sideOccupancy[neighbor] != 1
```

合格格写范围值 1，同时保存四个方向目标和总数。因此普通攻击不是任选四邻空格，也不允许攻击我方：

- 0 个目标：播放原生无目标反馈，取消攻击。
- 1 个目标：`7148h` 从四个方向槽取唯一非零格，自动锁定，不打开手动选格循环。
- 多于 1 个：`7113h` 进入手动选择；主操作仍以范围字节非零为必要条件。

这闭合了原 GDD 中“普通攻击射程、方向/形状与地图光标约束”的遗留项。

## 移动

`0000:7310` 读取当前单位移动值，按普通 `M` 或水戰士 `0` 模式调用通用范围传播器。精确代价、阻挡、剩余范围梯度和水戰士例外仍以 `movement-terrain-rules.md` 为准；本专题新增表现/输入结论：

- 传播图所有非零值在画面上完全等价，均保持原亮度；数值梯度只供寻路/规则消费者使用。
- `734Ch` 要求范围字节非零且单位槽图为 0，才接受为落点。
- 返悔流程可能恢复原位置后重新生成移动图；最终离开移动包装器时统一填 1。

## 射击

`0000:716D` 按当前职业短码写 seed：

| 职业 | 短码 | seed | 最终可选曼哈顿距离 |
| --- | --- | ---: | --- |
| 弓兵 | `3A` | 5 | `2..4` |
| 弩兵 | `0I` | 8 | `2..7` |
| 魔弓兵 | `1I` | 6 | `2..5` |

其他调用者默认 seed 5。`1000:3FA8` 使用模式 2 的统一代价传播，随后 `4014h` 把射手自身及 `±1/±50` 四邻清零，所以最小距离为 2；通用传播的“seed 含起点”语义使最大距离为 `seed-1`。地形规则 `0/99` 仍会阻断传播。

玩家选择器 `71E8h` 还要求阵营/占用字节大于 1，因此只能确认范围内的敌军格。旧文档中写作“最大距离 5/8/6”的值是传入 seed/原表显示口径；按原生逐格传播和点击结果，实际离起点的最大曼哈顿步数为 `4/7/5`。数值和表现规则不变，只纠正距离口径。

## 技术与工兵

一般目标技术先保存施法前单位格、视口和指针，`7996h` 取技术选择距离，`1000:40C2` 强制范围模式 0 并调用通用传播器。`76DCh` 要求：范围非零、格上有单位、`ANGEL2_VALIDATE_TECHNIQUE_TARGET` 接受当前动作的阵营/类型规则。`C1..C4`、`JO` 等直接以自身为中心的分支绕过手动选择。

`K1/K2` 工兵构造固定 seed 5、模式 `M`；`772Dh` 要求范围非零且单位槽为空，然后沿路径移动到所选格，再按动作码编辑其四个正交邻格。两类流程取消/结束后都恢复全 1 中性范围图。

## DS:`58A5h`：独立地图特效 sprite 层

DS:`58A5h..58EAh` 是发布镜像中初始为零的 70 字节可见缓存，唯一直接写函数为 `1000:853A`，外层为 `84E0h`：

1. AX 作为 `50×50` 线性效果原点，除以 50 得 X/Y。
2. SI 描述符头依次读 `xOffset、yOffset、width、height`，随后读 `width×height` 个 word。
3. 每个非零 word 的低字节经原点与偏移换算到棋盘坐标；只在 DS:`5390h/5392h` 所定义 `10×7` 视口内写入。
4. 可见索引为 `(boardY-viewY)*10+(boardX-viewX)`；写入同时令 A000/A800 两份地形缓存字节为 `FFh`，强制重画。

两个消费者语义不同：

- `7EDDh`：`1..127` 先减 1，再以动态描述符 `0205h` frame 绘到当前格的两个 VGA 页；0、`83h` 和所有高位码不走该 sprite 路径。
- `8273h`：仅处理高位码；低七位为 1、2、3 时都把单位文字/编号前景字段 DS:`F93Ch` 设为调色板 15。

因此它携带技术/地图效果 sprite 码及其文字可读性覆写，绝不是“`50×50` 范围图投影到 `10×7`”。`81h..83h` 的原设计名称和动态描述符 `0205h` 的低层字段名仍保留为 U，但不再妨碍分层实现。

## 实现边界

本轮仍只写原版规格，不开始 Web 开发。以后实现必须保留：

1. 范围临时图属于模拟状态；表现层只根据零/非零选择完整或网点地形，主操作也读取同一份图。
2. 地图特效层 DS:`58A5h` 与范围图分离；技术动画不能覆盖、替代或反向驱动选择合法性。
3. 忠实模式保留普通攻击单目标自动锁定、射击先清自身/四邻、取消后全 1 恢复，以及网点掩码的精确相位。
4. native tick 已闭合为标称 10.000151 ms；动态描述符与高位 tile code 的原设计名称仍不影响选格、像素掩码和图层边界的 C 级结论。
