# 射击表现与线形伤害修正

日期：2026-07-15

## 结论

弓兵、弩兵和魔弓兵的射击不读取 DS:`1119h` bit 0，因此不受“全屏战斗”设置影响：无论普通攻击使用棋盘或全屏模式，射击始终在战场棋盘上表现。

弓兵/弩兵共用 `UN.SWF/60` 的八帧扩张命中圈；魔弓兵通过隐藏分发项 `3V` 走线形效果，仍使用 `UN/60`，并在动画前请求播放 `MAGIC.SWF/83`。迅龙骑士闪避的判定在玩家与 AI 两侧同构，但原程序的无伤表现不对称：玩家射击使用 `UN/60`，AI 射击却调用普通受击的 `UN/62 + E/38`。

本轮还纠正了一个旧数值结论：线形处理器不是对所有单位只施加一次“一半伤害”。选中目标位于路径表索引 0，先在增长阶段受一次 `floor(base/2)`，增长完成后又明确再受一次；所以选中目标的实际伤害为 `2*floor(base/2)`，其他符合阵营过滤的线上占用格才只受 `floor(base/2)`。

机器可读结果为 `../parsed/native/shooting-presentations.json`。重复导出命令：

```sh
node reverse/tools/angel2-shooting-presentations.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/converted/audio/manifest.json \
  reverse/extracted reverse/decoded reverse/renders/planar \
  reverse/parsed/native/shooting-presentations.json
```

## 通用命中圈

`1000:747C` 先聚焦选中格，载入 `UN/60`，然后通过 DS:`6CDEh` 的 `1×1` 动态描述符运行：

```text
tile code: 0, 1, 2, 3, 4, 5, 6, 7, 8, 0
meaning:   空, 帧0, 帧1, 帧2, 帧3, 帧4, 帧5, 帧6, 帧7, 空
wait:      每次 6 native ticks
```

固定画面阶段为 10 次绘制、60 ticks。代码中没有直接音效请求。完成全部图形帧后，只有 DS:`6B60h == 'Y'` 才按 DS:`5230h` 逐点扣生命；每成功扣 1 点会重画并等待 1 tick。所以迅龙骑士闪避分支仍播放完整图形，只是把扣血门禁临时改为 `N`。

帧联系表：`../renders/contact-sheets/shooting/UN-0060-shot.png`。

## 迅龙骑士闪避不对称

PIT `40h` 端口 bit 0 为 1，且目标职业为 `0E/迅龙骑士`时：

- 玩家入口 `0000:722B` 调用 `1000:747C`：`UN/60`、60 ticks、无直接音效、无伤害。
- AI 入口 `1000:1F7B` 调用普通地图受击 `1000:6B58`：`UN/62`、90 ticks、两次 `E/38` 请求、无伤害。

这不是文档推断：两个分支在发行二进制中确实直接调用不同的 far 入口。复刻的“原版兼容”模式应保留；若 Mod 希望两侧统一，应另列开关。

## 魔弓线形动画

`1000:7E09` 从选中目标开始沿范围图的前驱标记回溯，把“目标→…→射手”写入 `1000:028Bh` 的最多 100 个 word。多个等价前驱的方向顺序会受 PIT 影响，所以非水平/垂直直线在多条离散路径可用时不能用固定 Bresenham 结果代替。

`1000:64A6` 载入 `UN/60`，再载入并通过 `0000:0220` 请求播放 `MAGIC/83`（5000 Hz，0.8824 s）。然后分两阶段：

1. 增长阶段从路径末尾的射手格向索引 0 的目标格逆向扫描。每新到一格，先对其有效占用者施加一次半伤害，再使描述符尾迹前进，刷新并等待 20 ticks。
2. 到达目标后，对索引 0 再施加一次半伤害；随后将后续 8 个描述符阶段逐一覆盖全线，每阶段刷新并等待 20 ticks。

若路径表含 `L` 个格，图形阶段的固定等待总量为：

```text
(L + 8) * 20 native ticks
```

DS:`6888h` 指向九个 `1×1` 描述符，原始 tile code 为 `1,2,3,4,5,6,7,8,82h`。`1..8` 对应 `UN/60` 八帧；末尾 `82h` 的高位渲染语义尚未完成命名，必须保留原值，不能直接当作普通“第 130 帧”。

死亡移除在整条线动画完成后才由 `0000:63CF` 处理。线形逐点伤害调用 `0000:783D`，因此防魔会挡住增长阶段的半伤害；`1000:6532` 随后调用清除器。选中目标还有一次显式的第二次半伤害，所以有防魔时只承受这一半；其他有防魔的线上目标本次承受 0，随后同样失去防魔。

## 证据边界

- 已验证 19 段代码签名、3 段数据签名、两个图形记录和两个直接音效记录。
- 已确认帧序、等待 tick、音效请求点、玩家/AI 闪避不对称、线形增长/收尾顺序与目标双次半伤害。
- native tick 已闭合为标称 10.000151 ms；仍为 U 的只有 raw tile code `82h` 高位在底层渲染器中的原设计名称。
- 本文只负责射击表现；其他技术、状态和特殊逐关事件现分别由各自表现专题闭合。
