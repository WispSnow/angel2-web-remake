# ANGEL2 图像、音频与规则表格式

日期：2026-07-14

## 内嵌压缩流

许多索引记录以 5 个 little-endian `u32` 偏移开头。每个有效偏移指向一条独立流：

```text
u16 解压后长度
u8  压缩标志：0 = stored，非 0 = LHA LH7
u8[] 数据
```

原生解压器位于恢复模块偏移约 `75BFh`，字符表和距离表参数与 64 KiB 字典的 LH7 一致。`angel2-lha-frame.mjs` 为裸流补最小 LHA 头并交给 `lha` 解码，随后严格校验输出长度。

## 位平面图像包

大多数解压流自身又是单色图目录：

```text
u16 directoryBytes
u16 offsets[directoryBytes / 2]

每张图：
  u16 height
  u16 rowBytes
  u8  bits[height * rowBytes]   # MSB first

最后一个 offset 指向 u16 FFFFh
```

同一记录的流 0–3 布局相同时，它们是 16 色图像的四个位平面；流 4 布局相同时是透明遮罩，置位表示透明。流 0–3 对应颜色索引 bit 0–3。

## 原生调色板

原作会向 VGA DAC 端口 `3C8h/3C9h` 写入 16 组 RGB，每通道为 0–63。恢复模块偏移 `31E0h` 的函数完成这一写入。至少已确认：

- `gameplay`：数据位于模块偏移 `9CA8h`；角色战斗帧颜色合理。
- `intro`：数据位于模块偏移 `9A10h`；部分 `BK` 场景呈灰紫/棕色。

因此 PNG 是“索引图 + 指定调色板”的预览，不应在调色板映射完成前当作唯一母版。无损母版仍是四个位平面和调色板表。

## `B.SWF` 的特殊结构

记录 0–87 形成 44 个偶/奇对：

- 偶数记录：四个位平面，每路解压后 29,184 字节；第五路缺失。
- 奇数记录：一条解压流，恒为 8,506 字节。
- 模块 27 确认场景 `0..38` 分别使用奇数记录 `1,3,...,77`。每条为 128 个 `u16` 地形描述偏移、三张 `50×50` 字节图和五组 `75×u16` 数组，总长恰为 8,506 字节。
- 偶数记录每个位平面的前 28,160 字节是 `128 × 220` 字节的图块区。模块 29 `47EAh` 以 `rawToken × 00DCh` 计算源偏移，`3960h/427Ah` 每个位平面复制 44 行、每行 5 字节，因此每块精确为 `40×44` 像素。
- 每个位平面的末尾 1,024 字节均为零：44 个偶数记录×4 个平面共 176 段完全一致。原生 `token×220` 的最大访问也止于偏移 28,159，因此这一区域是图块寻址范围外的零填充，不是遗漏图像。
- 原生视口按 10 列、7 行绘制，水平步长 40 像素、垂直步长 44 像素。完整 `50×50` 战场静态拼图因此是 `2000×2200` 像素。
- `UN.SWF` 记录 56 解出的第二张 2,200 字节页是小地图颜色表。模块 29 对 `50×50` token 图逐格扫描，以 3 像素为步长；token 0 跳过，其余 token 经同一描述偏移取得 VGA 调色板索引并画成 `3×3` 色块，形成 `150×150` 地形小地图。side 图的 1/2/255 另叠加黑框和彩色内芯，当前/预览 10×7 视口分别使用黑/白边框。

旧的“456 个 `32×16` 图块”假设已被原生地址计算推翻，不再作为格式结论。当前已按确切几何导出 44 组、每组 128 张图块，并为 44 个映射场景生成无越界引用的完整战场图、地形小地图和占用叠加图；五个编号存档另有真实视口重构。manifest 位于 `reverse/renders/battle-maps/confirmed/`、`minimap/`、`minimap-occupancy/` 与 `save-minimap/`。奇数流的完整布局、逐关特殊单位和 token 映射证据见 `battle-template-format.md`。

## 音频

### Creative Voice

以 `Creative Voice File\x1A` 开头。71 条均可由 FFmpeg 识别为单声道 unsigned 8-bit PCM，并已转为 PCM 16-bit WAV；采样率和时长逐条写入音频 manifest。

### Softstar RIX OPL

以字节 `AA 55` 开头，即 little-endian `55AAh`。AdPlug 的 `CrixPlayer` 使用同一签名，并标识为 Softstar RIX OPL Music Format。59 条均已由 `adplay` 成功渲染为 44.1 kHz、16-bit、双声道 WAV，同时保留逐字节一致的 `.rix` 文件。

## `DATA.SWF` 与 `MAP.SWF`

两者都恰好是 39 条对齐记录：

- `DATA.SWF`：`39 × 70` 字节；每条可分成 `5 × 7 × u16`。
- `MAP.SWF`：`39 × 96` 字节；每条物理分成两个 `24 × u16` 窗口，运行时各 profile 实为 23 个逻辑槽，第 24 字与下一对象重叠。

经过与 `ref/修改.txt` 的全表比对，`DATA` 七字段可强推定为经验阈值、攻击、防御、生命、移动、未知、等级；其中攻略经验值是原值除以 50 的修改版，不能用于复刻。五组应视为固定等级行，而非五种独立属性层级。完整验证、职业记录号和转职图见 `unit-data-and-promotions.md`。

原生消费者现已确认：第一张逻辑 profile 是移动规则，普通值域为 `1..5/98/99`；第二张是地形防御百分比，普通值域含 `1..50/99`，按有效防御乘百分比后除 100。记录 38 第一窗口末字 `4130h` 与第二张指针表短码 `0A` 同址，证明物理第 24 字不是地形槽。原始 token 已能在每个场景中同时绑定到同号 `40×44` 可见图块和一个逻辑槽。DS:`2E7D` 的六个读取点没有名称/HUD消费者，故规范槽 ID 保持数字；字形中的地形词只作为未绑定候选。完整证据见 `movement-terrain-rules.md`。
