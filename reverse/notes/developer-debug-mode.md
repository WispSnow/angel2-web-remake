# 模块 29 发布版开发／调试模式

日期：2026-10-02

## 结论

战斗模块 29 带有一套**发布版可达**的开发／调试模式。旧笔记把主门 DS:`132F` 记成“初值 `N`、
模块内没有写入者、发布版不可达”，这是错的：`0000:11CC` 就是写入者。玩家社区流传的
“S+W+F+数字键盘 1+3+5”与“CapsLock+M 音乐盒”都与代码一致（用户 2026-10-01 转交的玩家反馈与
原版实机截图）。

- 开启：在战斗中按住数字键盘 1、3、5（且 2、4、6 都未按住），依序按下 S、W、F。
- 寿命：只到本场战斗结束；战斗中读取 `WAR` 记录不会关闭它。
- 用法：在待机战场按住 Caps Lock 再按功能键；进入目标／移动选格、转职选单等子状态后，不必按 Caps Lock。

调试功能包括：单位编辑、职业数值与地形数值编辑器（退出时**写回磁盘**的 `DATA.SWF`／`MAP.SWF`）、
双方全体生命设定、任意单位施放技术、AI 行为编辑、经验与生命微调、全员再行动、即时胜利、
直达结局、音乐盒、范围图读数、第 37 关首领数值显形和 PCX 截图。

同一轮核查还纠正了几处旁证：

- 地形编辑器保存着 24 个逻辑地形槽的原版名称；
- 职业编辑器给 `field5` 的标题是「魔防」；
- 行为编辑器给 13 种 AI 行为值都起了名字；
- `1V/2V/3V` 的开发名是「VIRT」，`1V/2V` 只能从调试施法到达；
- W 截图在七个界面里不经主门就会触发；
- K 是不经主门的鼠标／键盘模式切换。

机器结果在 `reverse/parsed/native/debug-mode.json`，重复导出命令：

```sh
node reverse/tools/angel2-debug-mode.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/parsed/native/debug-mode.json
```

导出器固定模块 29 哈希，逐段核验 48 段代码签名，并从数据段原样读出下列内容：

- 5 组一级选单与 8 组技术二级选单；
- 32 项音乐盒名单与 15 个单曲循环记录；
- 13 项行为名、24 项地形名与职业编辑器表头；
- 四张 EDIT 热区表。

## 开启与寿命

模块初始化 `0000:1146` 用 `0000:D192` 把 `0000:1160` 插进自己的 INT 09h 处理器 `0000:D2E0`，
并用 `0000:D1B7` 把计时器回调 `0000:11F2` 挂进 INT 08h。因此 `1160` 在**每一个键盘中断字节**
（按下、松开、自动重复）都会运行：先做 K 键切换 `11D2`，再进组合键检测 `116C`。

`116C` 读原始键位表 DS:`F6A9+扫描码`（1 = 按住，2 = 已松开）：

```text
116C  数字键盘 2/4/6（50h/4Bh/4Dh）任一为 1 → 返回
      数字键盘 1/3/5（4Fh/51h/4Ch）任一不为 1 → 返回
      S（1Fh）为 1          → DS:132C = 1，返回
      132C = 1 且 W（11h）为 1 → DS:132D = 1，返回
      132D = 1 且 F（21h）为 1 → DS:132E = 1，DS:132F = 'Y'
```

细节：

- S 仍被按住时直接返回，不检查 W／F，所以必须先松开 S，W 才算数；W 对 F 同理；
- 三个步骤标志在本次模块运行内从不清零，所以三步之间可以松开数字键再重新按住；
- 发布版没有任何关闭路径，也没有屏幕提示；
- DS:`132C..132F` 不在 `WAR` 存档的十四段序列化里（见 `save-slot-format.md`）。
  模块 29 每场战斗都由 `GO.EXE` 重新解压装入，所以离开战斗后调试模式就消失；
  战斗中读档不会重置它。

## 分发器与生效位置

调试按键分发器是 `0000:30CE`：先比较 `DS:132F == 'Y'`，再依次调用 F2、F3、F4、F5／F6、W、F10、F1、
U／D、S、2 的处理器，最后远调用音乐盒 `1315:0004`。它的调用点决定了按键在哪些状态下有效：

| 调用点 | 界面状态 | 额外条件 |
| --- | --- | --- |
| `0000:B793` | 待机战场光标主循环（`4A0D → B78C`） | `B78C` 只在 Caps Lock（DS:`F6E3`）按住时进分发器；不按 Caps Lock 时走正常的 F1–F4／Esc／Tab／E／M 快捷键 |
| `0000:54BC` | 攻击、射击、移动（含飞龙追加移动）、传送、技术、建造的选格步进 | 无需 Caps Lock |
| `0000:0766` | 转职职业选择画面 | 无需 Caps Lock |
| `0000:5960`／`0000:5CB9` | 通用浮动选单 | 指针停在选单的两个拖曳把手上且未点击 |

敌方阶段、AI 调度与模块 27 部署都不调用分发器。因此玩家流传的 “CapsLock+M” 是**待机战场**
的写法：M 本身在分发器里不检查 Caps Lock，但 Caps Lock 决定了分发器是否被调用。

## 单位编辑（我 EDIT／敵 EDIT）

`0AA9`／`0A94` 分别以 side 1（名表 DS:`362C`、职业数组 DS:`56DA`）／side 2（DS:`32AD`、DS:`55AE`）
进入 `0ABE`。

**画面**

- 整屏铺色 8，4 页 × 15 项、按列优先排列，共 60 个槽，槽 60–74 不可达；
- 每项 `160×50`，各项原点 X ∈ {8,192,376}、Y ∈ {10,70,130,190,250}；
- 项内依次是职业棋子框、行为框、0 起槽号和原始名表名字；
- 名字为深色表示在场，白色表示不在场；
- 右侧四个无标签页签，`(584,300)` 是 `EXIT`；
- 热区表：DS:`0A76`（页签与 EXIT）、DS:`0AAA`（名字）、DS:`0B42`（棋子）、DS:`0BDA`（行为），都用严格内部判定。

**操作**（只能用鼠标指针；键盘主／次键作用在当前指针位置；编辑循环不读方向键，也没有退出键）：

- 点在场单位的名字：立即从棋盘移除（只清两张图），画面保持；
- 点不在场单位的名字：画面关闭，并在下一次待机战场点格时**把该单位放到光标格**，
  生命回满，其他状态沿用记录；不检查占用、地形或重复，槽 0 因为是“无待放置”哨兵而永远放不回；
- 棋子框：次键 +1、主键 −1，在 0 到 38 之间不回绕，直接写职业数组；
- 行为框：在 0 到 11 之间步进。

**原版缺陷**

- 两个画面的行为框都写 side 2 行为表 DS:`5644`；
- 标签指针 9 指向表自身，值 11 读到伪指针；
- 悬停重画读一张无人写入的表，因此总显示「正常」；
- 改职业后不压生命；
- 移除后按 EXIT 会在下一次点格时把最后点过的槽放回，并且放回到“最后一次关闭的画面”所属的一方；
- 通用槽显示内部占位名（`xxxx12`、`xxxxxx`）。

**存续**

- `WAR` 存档会带上全部编辑结果；
- 胜利、撤退与读档后的 `1000:05E5` 把 DS:`56DA` 复制回战役职业数组，因此 我 EDIT 改的职业会带进后续关卡；
- 敵 EDIT 的修改只留在本场战斗。

## 截图与其他不经主门的行为

PCX 写出器 `1918:0004`：

- 总是读 VGA 第 0 页，写 `640×400`、4 平面、RLE 的 PCX v5；
- 会把属性调色板设为恒等；
- 调用方不检查失败，总是递增文件编号。

各截图入口：

- **W 键（不经主门）**：`31FA` 本身不检查 `132F`。以下七处直接调用它，按住 W 就写 `A##.PCX`：
  - 存读档对话框 `36B0`；
  - 浮动选单 `5759`、`5D3F`；
  - 射击选格 `71F5`；
  - 移动选格 `7359`（含飞龙追加移动）；
  - 半龍传送 `74AC`；
  - 设置对话框 `1000:2A33`。

  W 同时是发布版“上”的别名，所以这是正常游玩也可能触发的副作用。尚未实机核对。
- **模块 25 与模块 37**：剧情 `KY` 等待中按 W 同样截图，并结束等待，没有门。
- **P 键**：由 DS:`132F != 'N'` 门控，只在全景战斗动画中截图。
- **K 键**（`11D2`，不经主门）：在 `Y`／`N` 之间切换 `MOUSE_USE`（DS:`FB1A`）。
- **Ctrl+Q**（`D3D1`，不经主门）：跳到 `0000:0129`，推测是紧急退出战斗模块。
