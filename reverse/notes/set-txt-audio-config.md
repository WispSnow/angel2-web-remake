# `SET.TXT` 与 Sound Blaster 数字音频配置

状态：格式和发布样本语义已闭合。`SET.TXT` 只控制 Sound Blaster 兼容数字采样/VOC 驱动，不是 RIX/OPL 音乐设置，也不是战斗存档里的四个分类音效开关。机器规格见 `../parsed/native/set-config.json`。

## 发布文件

`ref/ANGEL2/SET.TXT` 固定为 8 字节：

```text
59 31 33 0D 0A 1A 91 00    Y13.....
```

SHA-256 为 `ef90f2dc69eb0c44a6cef3675b5a5c63efe6c4f13c59a05a047a26b3e416c66d`。九个恢复出的运行模块都只读取前三字节：

1. byte 0 若不等于 ASCII `Y`，写内部 `N` 并立即返回，后两项不再读取；
2. byte 1 先减 ASCII `0`，作为基址 word 表索引；
3. byte 2 同样减 ASCII `0`，作为 IRQ word 表索引；
4. byte 3 以后的 `0D 0A 1A 91 00` 不进入配置语义。

因此发布值 `Y13` 精确表示：启用数字音频，基址索引 1，IRQ 索引 3。

## 两张原生表

九份加载器都携带完全相同的两张表：

| 索引 | I/O 基址 |
| ---: | ---: |
| 0 | `210h` |
| 1 | `220h` |
| 2 | `230h` |
| 3 | `240h` |
| 4 | `250h` |
| 5 | `260h` |
| 6 | `270h` |
| 7 | `280h` |
| 8 | `290h` |
| 9 | `300h` |
| 10 | `FFFFh` 终止值 |

| 索引 | IRQ |
| ---: | ---: |
| 0 | 2 |
| 1 | 3 |
| 2 | 5 |
| 3 | 7 |
| 4 | 10 |
| 5 | 11 |
| 6 | `FFFFh` 终止值 |

发布文件由此解为基址 `220h`、IRQ 7；驱动派生的中断向量为 `0Fh`。

模块 23 的示例加载器位于 `0000:0D56`，表位于 DS:`0488h/0496h`。模块 `21/23/25/27/29/33/35/44/46` 都有一份结构相同、地址不同的加载器；模块 37 没有 `SET.TXT` 字符串或加载器签名。不能仅凭这项缺失外推模块 37 的硬件角色。

## 声卡身份确认

这不是仅由 `220h` 经验猜出的设备名称。模块 23 底层驱动同时给出完整 Sound Blaster DSP 指纹：

- 对 `base+6` 写 1/0 复位，再等待 DSP 返回 `AAh`；
- `base+Ch` 是 DSP 写入/状态端口；
- `base+Eh` 的读状态有效后，从 `base+Ah` 取数据；
- 发送 DSP `E0h,AAh` 并要求返回补码 `55h`；
- 以 `IRQ+8` 安装实模式中断向量，并通过主 PIC 端口 `21h` 清除/恢复对应掩码位。

对应入口为模块 23 `91F2h/9315h/937Bh/93A4h/94BFh/954Eh/9590h`，七段硬件代码签名已写入机器规格。

IRQ 表虽然还列出 10/11，但当前驱动仍统一使用 `IRQ+8` 且只操作主 PIC；这对 AT 级联 IRQ 并不是完整实现。Web 复刻应把它们保留为原版表证据，不模拟成可靠的 DOS 硬件行为。发布样本选择 IRQ 7，不触及该边界。

## 与游戏内声音设置的关系

模块启动顺序把 RIX 驱动初始化与 Sound Blaster 驱动初始化分开调用。`SET.TXT` 的 `Y/N` 只门控后者；标题和战斗的 RIX 选曲、启停与五档音乐音量属于另一条 OPL 路径。

战斗存档还保存四个上层请求门：说话、移动、战斗、按键。有效 VOC 播放通常需要同时满足：

1. `SET.TXT` 启用且底层数字驱动初始化成功；
2. 该调用路径对应的分类音效开关开启。

部分原版调用直接进入播放请求，没有经过某一分类开关；它们仍会在底层受 `SET.TXT` 门约束。因而不能把 `SET.TXT` 当成四开关的序列化副本，也不能用它解释音乐音量。

`0000:0220` 与 `0000:0224` 的差别现也可以闭合：前者直接提交已载入 VOC；后者先检查 DS:`10EDh` bit 0（战斗音效分类）再提交。两者最终进入同一个底层数字播放请求，不是不同混音通道。

## 原版异常与 Web 导入策略

原生加载器没有长度、ASCII 或索引范围检查。启用标志为 `Y` 时，非法 byte 1/2 会直接造成表外内存读取；IRQ 索引 6 会取得 `FFFFh`。这属于未定义硬件/内存行为，不是应复刻的玩法。

安全导入规则应为：

- 少于 3 字节直接拒绝；
- byte 0 非 `Y` 时按“数字音频关闭”接受，不读取索引；
- byte 0 为 `Y` 时只接受 ASCII 端口索引 `0..9` 和 IRQ 索引 `0..5`；
- 尾随字节不参与语义，可保留为来源元数据；
- 浏览器运行时不模拟 I/O 端口、DMA、PIC 或 IVT，只保留解码值用于兼容来源说明，并用 WebAudio 播放已提取 VOC。

## 可重复命令

```sh
node reverse/tools/angel2-set-config.mjs --extract \
  ref/ANGEL2/SET.TXT reverse/unpacked/lzexe-modules \
  reverse/parsed/native/set-config.json
```

提取器核验原文件哈希、十个运行模块哈希、九份 93 字节加载器、九份相同查找表、模块 37 的加载器缺席，以及七段 Sound Blaster 硬件代码签名。当前所有断言均通过，`implementationFrozen=true`。
