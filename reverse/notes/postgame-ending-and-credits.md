## 结论与控制流

主线终战之后的原生流程已经闭合为：

```text
场景 37 胜利
  → 模块 25 / 内部场景 49：SAY 70
  → 模块 33：22 张角色战绩卡
  → 模块 35：四段条件结局
  → 模块 27/29：场景 38“异世界”追加战
  → 模块 46：七页制作人员表
  → UN/54 “The end”永久动画
```

机器可读规格位于 [`../parsed/native/ending-presentations.json`](../parsed/native/ending-presentations.json)。生成器验证 22 段原生代码/数据和 12 个直接资源；本文件只把结构化结果整理成 GDD 可读形式。

模块 46 是终端状态。入口在调用 `0000:03CE` 后虽然还排列着写入 `nextModule=27,nextStage=38` 的代码，但 `03CE` 必然进入 `0000:0725` 的无限循环；即使该调用异常返回，`0000:0430` 仍是自循环。因此 `0000:0101–0128` 的两次父状态写入不可达，不能实现为“通关后自动重玩追加战”。

- `A/9`：卡片背景；
- `D/<角色画像记录>`：角色画像；
- `C/<随机记录>`：装饰图，取 `PIT randomBelow(31)`，结果 28 改为 29；
- `M_00/<当前职业记录>`：该职业左侧普通全景战斗图形的 frame 0；模块 33 直接使用
  启动资源索引 5 和当前 `ME_DATA` 记录，不走普通战斗中魔劍戰士的 `Y_00/41` 重映射，

竖条由模块横向复制 80 次铺满 640 像素宽画面。此前机器规格只登记 `A/D/C` 而漏掉
`0000:0718–0776` 的 `M_00` 读取与绘制；现已由模块 33 `0000:06C2–0849` 签名补正。

`KILL_ALL` 的名字这次得到证实：它确实只统计击杀。模块 29 在 `0000:91DE` 结算完主动攻击伤害后，于 `0000:91F1..91FE` 重新装载防守者格并读 `DS:31C9`（`0000:5087` 把它写成该格的阵营占用值 0／1／2）。防守者存活时走 `0000:9200`，按目标等级发经验并在 `0000:921B` 返回；防守者已被击杀而清格时走 `0000:921C`，按职业击杀奖励发经验，并在末尾执行全模块唯一一次 `KILL_ALL` 写入：

```text
9252: 8b 1e cb 31           mov bx,[31CB]      ; 主动方槽号
9256: 03 db                 add bx,bx
9258: 8b 87 8f 03           mov ax,[bx+038F]   ; KILL_ALL[slot]
925C: 40                    inc ax
925D: 89 87 8f 03           mov [bx+038F],ax
9261: c3                    ret
```

镜像的反击经验函数 `0000:9161` 结构完全相同（对主动方格做同一套阵营判定，击杀走 `0000:918E`），但两条分支都没有这段尾巴，`0000:91C4` 直接返回。全模块对 `[bx+038F]` 只有 `0000:9258/925D` 一处读写，普通攻击结算 `0000:90D8` 在整个映像中只有 `1000:18D9` 一个调用点，射击与技术走各自的行动例程。因此：**只有主动发起的普通攻击造成击杀才加一，反击击杀、未致死的普通攻击、射击、技术都不加**。模块 33 的可见标签仍是“战绩”。

`0000:9252` 用主动方自己的槽号索引，没有阵营判定，所以 side 2 单位的普通攻击击杀也会写进同一个 75 项数组。该边界已登记，尚未决定 Web 是否复现。

每张卡最多停留 200 次外循环，每次等待 2 个原生 tick，即 400 tick；任一语义动作键都可提前翻到下一张。

## 模块 35：四段条件结局

模块 35 使用 `UN/9` + `UN/10` 的 258 项结局字形。每张结局画面使用 `UN` 中相邻的两个 `320×350` 记录，分别绘制在 640 像素宽画面的左右半边。

### 每对插画各自带一份调色板

**八张结局画面不共用 gameplay 调色板**：模块 35 在 `DS:033E` 保存八个 16 色 VGA DAC 表指针（`DS:034E..04CD`），并用挑选 `UN` 记录的同一个变体索引 `DS:032C` 取表，画完左右半边后才淡入：

```text
053E: 8b 1e 2c 03           mov bx,[032C]      ; 变体索引
0544: 8b b7 2e 03           mov si,[bx+032E]   ; 该对的首个 UN 记录
0569: ba 00 00 bb 00 00     ; 左半边 x=0，随后 057F 的 inc si 画右半边
05A4: 8b 1e 2c 03           mov bx,[032C]
05AA: 8b b7 3e 03           mov si,[bx+033E]   ; 该对专属调色板
05B0: e8 87 19              call 1F3A          ; 64 步淡入
```

| 变体 | 插画 | 调色板 | 段落 |
| ---: | --- | --- | --- |
| 0 | `UN/4–5` | `DS:03AE` | 骑兵 |
| 1 | `UN/13–14` | `DS:040E` | 战士 |
| 2 | `UN/0–1` | `DS:034E` | 法师 |
| 3 | `UN/17–18` | `DS:046E` | 存档次数 > 100 |
| 4 | `UN/19–20` | `DS:049E` | 存档次数 ≤ 100 |
| 5 | `UN/11–12` | `DS:03DE` | 战士雕像 |
| 6 | `UN/2–3` | `DS:037E` | 战绩总和 > 100 |
| 7 | `UN/15–16` | `DS:043E` | 战绩总和 ≤ 100 |

gameplay 调色板的索引 7、8、9、10、12、13（`186,170,154`／`0,0,26`h 系蓝紫绿）在这八张表里一个都不存在，所以用 gameplay 渲染会把整幅画变成高饱和噪点。这八张画面必须来自
`reverse/renders/ending-presentations/`，不能直接用 `reverse/renders/planar/UN/` 的位平面母版。

十六个结局记录的第 5 条流逐字节相同（sha256 `0ca096b9…`），且原生是整屏拷贝而非精灵掩码绘制，因此这些画面按不透明处理。

### 结局音乐在入口就已切换

分支音乐由战绩总和选择子决定，但**在四段之前就已加载并播放**，因此四段全程都在同一首曲子上；不能实现成“第四段才换曲”。`0000:0454` 的派发顺序为：

```text
0454: e8 d8 02              call 072F   ; 统计三族并套用两个 100 阈值
0457: e8 16 00              call 0470   ; 按 [04D2] 取 MUSIC/40 或 UN/49
045A: ff 36 ab 00           push [00AB] ; 0470 刚填好的缓冲区
045E: 6a 00 6a 02 6a 01     push 0, 2, 1
0464: 9a 3c 06 88 06        call far ...:063C   ; 模块 33 播放 UN/6 用的同一入口
046C: e8 2c 00              call 049B   ; 到这里才开始播四段
0470: 83 3e d2 04 01        cmp word [04D2], 1  ; 战绩总和选择子
0475: 74 12                 je 0489
0477: ... b9 28 00 bb 08 00 ; cx=40, bx=MUSIC.SWF
0489: ... b9 31 00 bb 0d 00 ; cx=49, bx=UN.SWF
```

机器登记见 `ending-presentations.json` 的 `module35ConditionalEpilogue.entryMusic`；第四段变体上的 `music` 字段只表示“由该段条件选出”，其 `musicNote` 明确说明启动时点在模块入口。

### 尾聲文字：没有文字框，逐字打字

`0000:0529..05FC` 整段只做三件事：淡黑、绘制左右两半插画、淡入调色板，然后
`0000:05B3` 把光标设为 `(112,170)` 并调用 `0000:069E` 画文字。**全流程没有任何面板、
边框或底色填充**，模块 35 也只加载插画对、`UN/9`＋`UN/10` 字形表和音乐——它手上根本
没有可用的文字框素材。可读性由逐字描边保证。

排版（`0000:069E`／`06C3`）：

- 光标起点 `(112,170)`；`|`（`7Ch`）令 X 回到 112、Y `+20`；`$`（`24h`）结束；
- Big5 双字节绘制后 X `+16`，半角字节只令 X `+8`；八段文字里出现的半角字节只有
  `20h` 与 `7Ch`，即居中完全靠数据中的半角空格拼出来，不是几何居中。

每个全角字画三遍（`0000:1AD2..1B18`），`0000:1D1C` 先把字形与其下移 1、2 行的自身
OR 成 `16×17` 位图：

```text
1AD2: 8b 16 88 1b   mov dx,[1B88]   ; X
1ADE: 8b 0e 0c 1c   mov cx,[1C0C]   ; 阴影色 = 0
1AE5: e8 b4 fd      call 189C       ; 平滑位图画在 (X,Y)
1AF0: 83 c2 02      add dx,2
1AFE: e8 9b fd      call 189C       ; 再画在 (X+2,Y)
1B05: 42 / 1B0A: 43                 ; X+1, Y+1
1B0F: 8b 0e 0a 1c   mov cx,[1C0A]   ; 墨色 = 15
1B16: e8 83 fd      call 189C       ; 清晰字形画在 (X+1,Y+1)
```

`[1C0A]=15`、`[1C0C]=0` 在模块 35 内没有任何写入点，是编译期常量。八张结局调色板的
索引 15 全是纯白，索引 0 是各自画面的近黑灰。相对墨色位置，阴影等价于把同一字形重复
画在 `(±1, −1/0/+1)` 六个偏移上——已逐像素验证两种画法对八段文字结果完全相同。

**逐字节奏**：`0000:0725` 在每个全角字之后无条件 `mov cx,18h; call 0E26`，即等待 24
个 native tick ≈ 240 ms（`[1919]` 即模块 35 的 `DS:F5B3` 等价计数器）。半角字节走
`06CD..06F3` 分支，不等待。所以尾聲文字是**逐字打出来的**，既不是一次全部出现，也不是
开场那种滚动。

`0000:0717/071E` 本想在动作标志置位时跳过该字的等待，但两条 `je` 的目标都是紧随其后的
等待指令本身，所以发布版永远不跳过；而 `0000:069E` 返回前也没有任何地方清除这两个标志。
作者意图明确，复刻按 `[SR]` 修复：打字途中第一次按键把余下文字一次补完，第二次按键才推进
段落。

### 段落等待包含打字时间

`0000:0529` 在**段落开始**（插画尚未载入时）就把 `[0310]` 清零，而逐字等待全部发生在
该计数器运行期间。因此一段的实际时长是 `max(逐字时间, 段落上限)`：

| 段落 | 全角字数 | 逐字 tick | 上限 tick | 实际 |
| --- | ---: | ---: | ---: | ---: |
| 骑兵／战士／法师 | 90／71／71 | 2160／1704／1704 | 2374 | 2374 |
| 战士雕像 | 46 | 1104 | 0 | **1104** |
| 存档次数 >100／≤100 | 84／80 | 2016／1920 | 2243 | 2243 |
| 战绩总和 ≤100／>100 | 69／93 | 1656／2232 | 2540 | 2540 |

这更正了此前"战士雕像段只有一瞬闪现、原版漏填等待参数"的结论：该段的 46 个字本身就把
画面按住约 11 秒，上限 0 只是意味着打完即走，不需要复刻方自拟可见下限。

### 2. 固定战士雕像

此段没有条件分支，插画为 `UN/11–12`：

> 為了慶祝瓦爾克麗又一次的勝利，女帝便在城門外，興建了一座戰士雕像。  
> 但雕像的身份無人知曉．．．

其等待上限参数为 0（`0000:04C4` 的 `mov word [0DED],0000`）。注意这只表示"打完字立刻走"，不表示这一段看不见——`0000:05BF` 的逐字绘制在等待循环之前就已经占用了 1104 tick，见上文"段落等待包含打字时间"。`0000:05CD` 的等待循环是

```text
05CD: 80 3e f6 18 00        cmp byte [18F6], 0     ; 动作标志 A
05D2: 75 10                 jne 05E4
05D4: 80 3e f7 18 00        cmp byte [18F7], 0     ; 动作标志 B
05D9: 75 09                 jne 05E4
05DB: a1 10 03              mov ax, [0310]         ; 本段进入时清零的 tick 计数
05DE: 3b 06 ed 0d           cmp ax, [0DED]
05E2: 72 e9                 jb 05CD
```

无号 `jb` 在上限为 0 时立即失败，所以打完字之后这一段确实不再额外等待。早期结论把它记成"只有一瞬闪现、属于原版漏填参数、复刻需要自拟可见下限"是错的：`[0310]` 从段落开始就在走，46 个全角字的逐字等待本身就把画面按住约 11 秒，玩家能完整读完这两句。复刻不需要为这一段引入任何非原版下限。

## 模块 46：制作人员表与永久终幕

### 字幕资源

- `B/88`：20 个职务帧——工作人员、总监督、企划、音乐、程式设计、兵种设计、数值设定、封面・海报、美术、人物、地形、战斗、过场、战场编排、说明书、插图、美编、文案、测试、协力。
- `C/33`：22 个姓名帧——李永进、姜崇熙、苏泓漳、施文鸿、郭柄宏、梅期皓、杨鸿仁、林大甲、江志煌、洪信智、林珈汶、谢晓慧、萧建宏、卓文祺、周胜忠、林耀元、刘荣华、连谷川、丁淑姿、林正欣、李佳泽、王柏森。
- `UN/55`：与 `UN/6`、`UN/49` 同属 `AA55` 头的音乐数据，不是终幕图像或控制表。

姓名是从像素帧人工转录，PNG 是权威证据。`C/33` 第 2 帧现确认为“苏泓漳”：原生位图中间字和末字的三点水部件均可辨认，且作曲者罗马字资料 `HongZhang Su` 与“泓漳”相互印证。便于检查的图集为 [`../renders/contact-sheets/B-0088-credits.png`](../renders/contact-sheets/B-0088-credits.png) 与 [`../renders/contact-sheets/C-0033-credits.png`](../renders/contact-sheets/C-0033-credits.png)。

原生代码组成七个虚拟字幕页。每次翻页固定进行 400 次 CRTC 起始地址移动，每步加 `0x50` 并等待 2 tick；没有输入跳过检查。七页之后还会额外翻动一次，再进入最终画面，因此共有八次转场。部分姓名帧会跨页复用；职务帧 16“美编”没有被七个页面组合函数引用，而职务帧 17“文案”有引用，这是原版页面编排，不应自动修正。

### 字幕与终幕的调色板

模块 46 也不用 gameplay 调色板：`0000:00E9` 在进入字幕前把 `DS:00AF` 写进 DAC，`0000:041B`／`0000:042A` 再用 `DS:01F6` 淡出字幕、淡入终幕。

- `B/88`、`C/33` 的 42 个字幕帧只画调色板索引 0（各表均为纯黑），因此渲染结果与调色板无关，仍可沿用 `reverse/renders/planar/`；
- `UN/54` 用满 16 个索引，必须按 `DS:01F6` 渲染。用 gameplay 表会把太阳画成黄色、山画成红色、爱心画成绿色。

### `UN/54` 终幕循环

字幕结束后，模块 46 把 `UN/54` 帧 0 绘制在 `(160,27)`，再把帧 1–4 作为 `(352,161)` 的小角色叠加动画。每个外循环的确定顺序为：

1. 等待 1、400、1 tick；
2. 帧 1，等待 10；帧 2，等待 80；
3. 重复 10 次“帧 3 等待 10、帧 4 等待 10”；
4. 帧 2 等待 10；帧 1 等待 10；
5. 永久重复。

这里没有退出输入检查。忠实模式应把它视为 DOS 原版的终端状态；Web 复刻若添加“返回标题”只能作为明确标注的现代便利功能。

## 可重复验证

```sh
node reverse/tools/angel2-ending-presentations.mjs --render \
  reverse/unpacked/lzexe-modules/raw/0035-unpacked.bin \
  reverse/unpacked/lzexe-modules/raw/0046-unpacked.bin \
  reverse/decoded \
  reverse/renders/ending-presentations
node reverse/tools/angel2-ending-presentations.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/unpacked/lzexe-modules/raw/0033-unpacked.bin \
  reverse/unpacked/lzexe-modules/raw/0035-unpacked.bin \
  reverse/unpacked/lzexe-modules/raw/0046-unpacked.bin \
  reverse/parsed/native/unit-descriptors.json \
  reverse/extracted \
  reverse/parsed/native/ending-presentations.json
```

`--render` 输出 16 张结局插画和 5 帧 `UN/54`，每张都按其所属模块淡入的原生 DAC 表着色；
`pnpm content:stage49` 与 `pnpm content:credits` 只从这里取图，并在调色板不匹配时报错。

提取器断言 22 张可达角色卡、8 段结局文字、8 张结局调色板、20 个职务帧、22 个姓名帧、全部等待/跳过规则和模块 46 的不可返回控制流。
