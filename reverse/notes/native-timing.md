# 原生计时器与 Web 逻辑 tick

日期：2026-07-15  
状态：发布程序的标称 native tick 已闭合；宿主抖动与 VGA/音频漂移保留为观测参数。

## 结论

原版等待原语使用的一个 native tick，就是当前运行模块本地计数器的一次递增；
模块 29 使用 `DS:F5B3`。发布程序的九个运行模块（21/23/25/27/29/33/35/
44/46）都把 PIT 通道 0 设为 mode 3、除数 11932，因此标称频率与周期为：

```text
1193182 / 11932 = 99.9984914516 Hz
1000 / 99.9984914516 = 10.0001508571 ms
```

Web 忠实层应保留所有整数 tick 计数，并使用 **10 ms 逻辑量子**。累计调度可
保留小数误差，但不得把帧数、等待次数或规则结算点改写成宿主帧率。

## 安装链

以下以模块 29 为定址示例；机器审计对九个发布运行模块重复验证了同构链。

1. 模块 29 启动 `0000:003D` 先调用 `0000:1145`。
2. `0000:1145 → D1B7 → D25E` 保存旧 INT 08h，并安装游戏包装器
   `0000:D281`。
3. 包装器先调用保存于 `DS:F5DC` 的旧处理器，再由 `0000:D2A0` 把
   `DS:F5B3` 加一。
4. 启动代码随后无条件请求内嵌驱动操作 `FFh`。驱动 `1CED:069D` 保存当时
   的 INT 08h、写 PIT0 控制字 `36h` 与除数 11932，并安装 `1CED:1445`。
5. 驱动的链回量子与 PIT 除数同为 11932，计算出的倒计数为 1，因此每次新
   IRQ0 都链回游戏包装器；`DS:F5B3` 也就每次 IRQ0 加一。
6. `0000:D3B6` 忙等到 `DS:F5B3 >= CX`，然后把计数器清零。全运行镜像中
   对 `F5B3h` 的引用只有生产器与这个消费者。
7. 退出时程序卸载驱动/包装器，并以除数 0 恢复 PIT0；对 8253/8254 而言
   这表示 65536 计数的 DOS 默认周期。

## 时间换算示例

| 原生等待 | 标称时长 | 10 ms Web 逻辑时长 |
| ---: | ---: | ---: |
| 4 tick | 40.0006 ms | 40 ms |
| 8 tick | 80.0012 ms | 80 ms |
| 60 tick | 600.0091 ms | 600 ms |
| 90 tick | 900.0136 ms | 900 ms |
| 300 tick | 3.00005 s | 3.000 s |
| 7092 tick | 70.9211 s | 70.920 s |

这也与程序的可见用途一致：逐字等待 8 tick 约 80 ms，射击 60/90 tick 约
0.6/0.9 秒，Logo 上限 300 tick 约 3 秒，完整滚动开场的 7092 tick 约 71 秒。
若误按 BIOS 默认 18.2065 Hz 解释，这些等待会放大到约 5.49 倍，与用途不符。

## 保留边界

已闭合的是发布镜像的标称 PIT 配置、INT 08h 链与游戏计数器语义。以下仍是
宿主或硬件观测，不应混回玩法规则：

- 物理 PIT 晶振容差与模拟器调度抖动；
- VGA 回扫等待和全屏命令解释器内部渲染子步的实际耗时；
- VOC/RIX 播放设备、解码与缓冲产生的漂移；
- 直接读取 PIT 端口的随机/等价路径分支在某台机器上的统计分布。

机器规格：`../parsed/native/native-timing.json`。复算命令：

```sh
node reverse/tools/angel2-native-timing.mjs --extract-all \
  reverse/unpacked/lzexe-modules/raw \
  reverse/parsed/native/native-timing.json
```
