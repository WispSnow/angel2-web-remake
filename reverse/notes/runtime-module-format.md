# `UN.SWF` 运行模块格式

## 结论

`UN.SWF` 不只是图像/音频混合资源；记录 21–47 中有 10 组可重构的运行模块。`GO.EXE` 以共享变量 `WK_EXE` 选择一个头记录，`LOAD_V` 读取该记录后依次调用 `UPK`、`OVER`、`RUNTO`，最后进入模块入口。

初始 `WK_EXE` 值为 23，因此首个模块由头记录 `UN/0023` 与压缩块 `UN/0024` 组成，入口为相对装载基址的 `0602:000E`。

## 头记录

头记录为 little-endian：

| 偏移 | 类型 | 含义 |
| ---: | --- | --- |
| `00h` | `u16` | 重定位项数 |
| `02h` | `u16` | 后续压缩块数 |
| `04h` | `u16` | 入口 IP |
| `06h` | `u16` | 入口相对段 |
| `08h+` | `count × {u16 offset, u16 segment}` | 需要加装载基段的段值位置 |

当前 10 个头均为 8 字节、重定位数为 0。块数通常为 1；记录 29 声明 3 块。每个后续记录是一个单 LH7 流，解压到不超过 32 KiB；`UPK` 每完成一块便把目的段增加 `0800h`，等价于在平面映像中按 `8000h` 字节间隔放置。

`OVER` 会遍历重定位表，把每项指定的 `segment:offset` 处段值加上实际装载基段。`RUNTO` 用头中的入口 IP 和相对段构造远调用目标。

合计 12 个 LH7 块，重构平面映像共 256,983 字节。逐个头记录给出的入口均出现相同的 29 字节序列：

```text
06 0E 1F 8B 0E 0C 00 8B F1 4E 89 F7 8C DB 03 1E
0A 00 8E C3 FD F3 A4 53 B8 2B 00 50 CB
```

该序列与 `unlzexe 0.8p1` 的 LZEXE 0.91 识别签名逐字节一致。入口不是游戏业务代码，而是把自解压器尾部复制到高地址后跳入 `002Bh` 的 LZEXE 启动桩。因此 256,983 字节只是“LH7 外层已解、LZEXE 内层仍压缩”的装载映像。

## 第二层：LZEXE 0.91 解包

工具为每个无头装载映像合成最小 MZ 头，把第一层入口写入 `CS:IP`，交给 `unlzexe` 恢复原始 MZ、重定位表与未压缩 load image。10/10 模块均成功，原始业务入口统一恢复为 `0000:0000`。

解包后不再只有自解压入口。Ghidra 在 10 个模块中恢复出大量 16 位函数；最大模块 29 单独已有 1,196 个函数，并直接引用 `DATA.SWF`、`MAP.SWF`、`WAR0.TST`、`JUST.TST` 与战斗 UI/音乐资源。由此已经恢复 31 条原生转职边及完整 `.TST` XOR/RLE 读写链；模块 29/33 还分别提供了独立的 `DATA` 等级行消费者。这是当前后续代码逆向的主输入。

## 可复现导出

```sh
reverse/tools/angel2-runtime-modules.mjs --extract \
  reverse/extracted/UN reverse/decoded/UN reverse/unpacked/runtime-modules
# 可选：导入仍含 LZEXE 的第一层映像，只用于核对启动桩
reverse/ghidra_scripts/import-runtime-modules.sh
reverse/tools/angel2-lzexe-modules.mjs --unpack \
  reverse/unpacked/runtime-modules reverse/unpacked/lzexe-modules
reverse/ghidra_scripts/import-unpacked-runtime-modules.sh
```

第一层 `manifest.json` 记录每个头、块号、LZEXE 入口、映像长度和 SHA-256。第二层 `manifest.json` 记录解包长度、业务入口、重定位数和 raw image SHA-256；每个模块的 JSON 还保留完整 MZ 重定位表。`unpacked-exe/` 是恢复出的 MZ，`raw/` 是以 `0000:0000` 导入 Ghidra 的 load image。
