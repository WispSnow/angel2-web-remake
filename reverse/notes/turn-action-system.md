# 回合阶段、行动消耗与场景 37 三部位调度

日期：2026-07-14

## 结论

模块 29 已能确认标准战斗使用“玩家阵营阶段 → 我方自动单位阶段 → 敌方阵营阶段”的阵营制顺序，不存在按单位速度交错行动的调度器。单位能否再次行动不是存放在 24 字节单位状态中的计数，而是直接编码在 `50×50` 单位槽图的每格字节中：低 7 位是单位槽号，高位 `80h` 是该格本阶段已行动。

攻击、射击、技术、休息和其他成功提交的终结动作都会设置该格高位。移动只把低 7 位槽号从原格搬到目标格，本身不设置高位；取消路径会恢复位置或清除高位。休息不是纯“跳过”，它先恢复最大生命的 15%（向下取整并封顶），再消耗行动。玩家还能通过 `全部休息 / 跟隨主將 / 自由行動 / 全面徹退` 四项集体命令提前离开剩余手动阶段；它们分别批量休息、交给 AI 或返回同关部署，并非无副作用的统一“结束回合”。

场景 37 的頭和两只手位于三个独立格、三个独立槽，模板逐槽 AI 行为均为 0；AI 优先表明确包含 `2P/3P`。三份单位状态也各自通过调度器的 `31B7h=0` 检查，因此三者存活时，每个敌方阶段恰有三个独立的专用行动提交：頭一次、每只手各一次。这里确认的是“每部位一次专用行动”，不能把三次都先写成普通物理攻击。

机器结果位于 `reverse/parsed/native/turn-actions.json`，重复导出命令：

```sh
node reverse/tools/angel2-turn-actions.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/parsed/native/unit-descriptors.json \
  reverse/parsed/native/battle-templates.json \
  reverse/parsed/native/turn-actions.json
```

导出器验证 23 段关键机器码、39 项 AI 职业优先表，以及场景 37 的三个活动部位和逐槽行为值。`31B7h` 是单位状态中的另一字段，不来自 `B.SWF` 行为表。

## 棋盘单位字节

`DS:0022h` 指向 2,500 字节单位槽图，`DS:0024h` 指向对应阵营图。单位格字节的原生用法是：

```text
unitCell & 0x7f   = unit slot/index
unitCell & 0x80   = action spent for this side phase
```

`1000:22C9` 遍历全部 `50×50` 格，只对 `sideMap[cell] == selectedSide` 的格执行 `unitCell &= 7Fh`。所以行动位属于棋盘实例而非职业记录；同职业、甚至共用描述符的两个单位仍有各自的行动位。

玩家选择入口 `0000:55D3` 与阶段可用性扫描 `1000:41C3` 要求：

1. 当前格属于 side 1；
2. `80h` 行动位未设置；
3. 装入后的逐单位禁用值 `31B7h` 为 0；
4. 装入后的自动/AI 行为值 `3BF6h` 为 0。

`31B7h` 同时阻止反击和单位选择；冰雪处理器 `1000:69FA` 已确认是其写入来源之一，
故当前称为“逐单位行动禁用值”。原版未提供玩家可见状态名称，不能把它并入八槽普通
状态。`3BF6h` 会被 AI 分发复制为行为号，非零值用于自动/特殊单位。

## 标准阶段顺序

主循环 `0000:48FE` 的相关顺序为：

1. 检查失败、胜利和其他战场退出条件。
2. `1000:41BC` 返回是否仍有可选择且未行动的 side 1 单位；存在时继续玩家输入循环。
3. 不再有玩家可操作单位后，`1000:1542 → 1557 → 1595` 用 side 1 运行同一 AI 调度器，处理剩余的友方自动/特殊单位。
4. `0000:4E03` 执行阶段间显示和状态整理。
5. `1000:147E` 选择 side 1，并清除其全部行动位，为下一次玩家阶段准备。
6. `1000:14A6` 选择 side 2，先清除敌方行动位，再运行敌方 AI；随后执行仅限场景 26 的额外事件，并再次清除 side 2 行动位。
7. 再次检查失败/胜利；未结束时调用 `0000:4DCD`，先增加回合数，再统一结算毒伤和双方八个状态字的倒计时，随后运行逐关回合事件并回到玩家阶段。

所以普通战斗是阵营阶段制，状态则每个完整三阶段回合只 tick 一次，而不是每个阵营阶段一次。毒伤、八槽倒计时和零生命边界详见 `status-lifecycle.md`。已恢复主链以“没有符合选择条件的 side 1 格”为玩家阶段推进条件；目前没有在这条主链中发现独立的速度/先制值或单位交错队列。输入分发已进一步确认集体命令可主动满足或绕过这项推进条件，具体如下。

逐单位行动禁用值使用不同生命周期：`0000:4E03 → 1000:3664` 在玩家／我方自动阶段后
清 side 1 的 DS:`3C93h`，`0000:4DCD → 1000:366B` 在下一回合入口清 side 2 的
DS:`3CDEh`。所以冰雪目标只跳过一次本阵营阶段；它不随八槽状态在完整回合末递减。

## 集体命令与提前推进

DS:`3F3Eh` 的集体命令菜单包含：

| 命令 | 阶段副作用 |
| --- | --- |
| `全部休息` | `0000:6DEA` 扫描全部 2,500 格；对 side 1、未行动、行为值为 0 的手动单位逐个恢复最大生命 15% 并设置行动位，然后主循环照常进入我方自动和敌方阶段 |
| `跟隨主將` | 当前选中单位先设为已行动，再写入临时领队格和领队模式，立即运行剩余 side 1 AI 调度 |
| `自由行動` | 不启用临时领队，立即运行剩余 side 1 AI 调度 |
| `全面徹退` | 确认后写退出标志 `Y`，返回模块 27、当前关卡，重新进入部署 |

因此“提前结束玩家阶段”已经确认，但不能抽象成无条件 `endTurn()`：`全部休息` 会治疗并消耗所有剩余手动单位，另两项会让剩余单位按 AI 规则行动。行动菜单中的 `結束` 则只结束当前单位移动后的动作。精确输入、菜单与右侧面板入口见 `input-and-battle-ui.md` 和 `input-ui.json`。

## 玩家动作的行动消耗

| 动作 | 原生入口 | 行动位行为 |
| --- | --- | --- |
| 移动 | `0000:7A8C` 搬移路径 | 清原格，把 `unitCell & 7Fh` 写到目标格；移动本身不消耗终结动作 |
| 普通攻击 | `0000:9123` | 对攻击者格 OR `80h`；即使伤害基础为 0 仍消耗 |
| 射击 | `0000:719B` | 成功结算后对行动格 OR `80h` |
| 休息 | `0000:7528 → 1000:5D12` | 恢复 `floor(maxLife×15/100)`、生命封顶后 OR `80h` |
| 技术 | `0000:75E4` 等 | 成功路径统一 OR `80h` |

`0000:7BE5` 是多个行动菜单分支复用的提交帮助函数。移动或目标选择被取消时，`693B/6A55/6B6A` 等路径会恢复先前棋盘格并清除高位；因此不能在“开始移动”时永久消耗行动。

单个玩家休息与 AI 休息共用 `1000:5D12` 的地图表现。该函数载入 `MAGIC/0`，按
DS:`60E0h` 的五项描述符播放 tile code `1..5`，每项等待 15 native tick；这五项与治疗
家族公共尾段 DS:`608Ah` 的前五项逐描述符相同。可见五项结束后才恢复
`floor(maxLife×15/100)` 并封顶，随后用 DS:`611Eh` 的 tile code 0 空白描述符等待 15 tick，
返回玩家／AI 调用者提交行动位。整条休息链没有 `E/36` 或其他声音请求。

`全部休息` 是原版例外：`0000:6DEA` 直接扫描、恢复并设置全部合格 side 1 格的行动位，
没有调用 `1000:5D12`，所以不会为每名单位依次播放 `MAGIC/0`。机器规格已将两条边界写入
`turn-actions.json#actionCommitPoints.rest.presentation`。

## AI 调度与随机延后

`1000:1595` 按 DS:`1036h` 的 39 项短码优先表逐类处理单位。表覆盖全部普通与特殊短码，最后两项正是 `2P` 与 `3P`。

对每个短码，`1000:15F4` 扫描 2,500 格，仅接受：当前阵营相符、高位未设置、短码相符、逐单位禁用值为 0 的单位。PIT 低位会让候选在本次扫描中暂缓；但只要仍发现候选，外层就继续扫描，直至没有未行动候选。因此该随机分支只改变本轮 AI 单位的处理先后/尝试时机，不会令单位永久丢失或额外获得一次行动。

各 AI 行为最终由 `1000:2032` 给当前行动格 OR `80h`。胜负条件可在单位行动后中断调度，这是“每个符合条件的存活单位一次”的唯一常规提前终止边界。

## 场景 37：頭与双手

静态模板与运行时调度交叉结果：

| 部位 | 格 | 槽 | 短码 | 模板行为 | 每敌方阶段 |
| --- | ---: | ---: | --- | ---: | --- |
| 左手 | `(22,12)` / 622 | 54 | `3P` | 0 | 一次专用行动 |
| 右手 | `(24,12)` / 624 | 55 | `3P`（内部职业值 39 回退） | 0 | 一次专用行动 |
| 頭 | `(23,11)` / 573 | 56 | `2P` | 0 | 一次专用行动 |

`1000:17A7` 以頭自身格为中心，按“高級回復 → 高級冰雪”交替，然后设置頭格行动位。`1000:17EE` 对每只手独立扫描 side 1 目标格；每个候选以 `randomBelow(5)==0` 筛选，没有选中时继续扫描/重试。两手共享“究級落雷 → 究級炎暴”的开关，然后各自设置当前手的行动位。两个开关原始值均为 0，函数先 XOR 1，因此首次次序已确认。

两只手虽共用 `3P` 行为和全局的效果交替位，但它们的棋盘格、单位槽、生命和行动位都独立。因此全员存活时是三个行动提交：頭一次回復/冰雪，双手合计一次落雷和一次炎暴；不是“頭统一代替双手行动”，也不是同一只手连动两次。击破某部位后，其格被移除，后续敌方阶段自然少一次行动。完整公式与资源号见 `special-unit-behavior.md`。

## 场景 26 的阶段外特例

敌方封装器 `1000:14A6` 在普通 AI 后调用 `1000:24A5`。后者只在场景号 26 时连续两次执行场景级额外效果；它不使用某个敌方格的行动位。每次先播放 `MAGIC/21→MAGIC/14` 及纵列扫过，共 385 native ticks，再把行优先找到的首个 side 1 单位所在纵列中、17 格扫描带内的 side 1 单位向下移到最远三格内的首个空位。该效果无伤害/状态，只同步修改阵营图与单位槽图。完整列选择、描述符和二次执行语义见 `wd-and-stage26-special-effects.md`。复刻时必须把它建模为敌方阶段尾事件，而不是给某个单位增加两次普通行动。
