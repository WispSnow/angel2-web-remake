# 部署、战斗输入、菜单与 HUD

日期：2026-07-15

## 结论

模块 27 与模块 29 的部署/战斗交互已经恢复到可以写入原版 GDD 的程度。两模块各自安装 INT `09h` 键盘中断处理器，从端口 `60h` 读取 PC/AT Set-1 扫描码；按下/释放分别在原始键位数组写 `1/2`，再把选定扫描码映射为方向、主操作、次操作等共享动作标志。部署导航、战场光标、菜单和侧栏消费这些语义动作，鼠标与键盘最终进入同一命中测试或动作分发层。

这条边界对以后 Web 复刻很重要：浏览器键盘、指针、手柄和无障碍输入应先绑定到语义动作，不能把 `AG2.JS3` 的 DOS/Joymouse 字节直接当成 DOM 键码。原版发布程序的键盘绑定与当前 Joymouse Keyboard 4 Way 配置均已闭合：配置低七位先索引 `JS3.EXE` 的 128 项 Set-1 表，再进入本文件的消费者；高位是逐动作重复开关。未选用设备模式的 DOS 硬件轮询与 `E0` 前缀细节只保留为适配层取证，不改变语义规则。

机器结果位于 `reverse/parsed/native/input-ui.json`。重复导出命令：

```sh
node reverse/tools/angel2-input-ui.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0027-unpacked.bin \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/parsed/native/input-ui.json
```

导出器验证 40 段输入/UI 机器码、两份各 14 项且完全相同的实体键盘映射、19 个部署热区、7 组行动菜单、12 个战斗侧栏热区、17 个侧栏动作、14 个设置项和 4 组设置驱动的战术桌换帧。

## 共享语义动作

模块 27 的 `MOUSE_USE` 在 DS:`2A42h`；方向标志在 `244Ah..244Dh`，主操作在 `244Eh`，次操作在 `244Fh`。模块 29 的 `MOUSE_USE` 在 DS:`FB1Ah`；八方向标志在 `F58Ch..F58Fh/F6F0h/F6F2h/F6F8h/F6FAh`，主操作在 `F590h`，次操作在 `F591h`。

在战斗中，主操作是选择/确认，次操作是取消/返回。在部署地图中语义不同：主操作向前一处 `FFh` 空部署格循环，次操作向后一处循环；次操作不是通用的“取消部署”。这说明复刻必须按交互状态解释动作，不能把“次操作”全局硬编码为取消。

## 发布版实体键盘绑定

模块 27 的原始键位状态数组位于 DS:`2567h+scanCode`，映射表位于 DS:`2410h`；模块 29 分别位于 DS:`F6A9h+scanCode` 和 `F552h`。两份发布版映射逐字节相同：

| 语义动作 | Set-1 扫描码与键位 |
| --- | --- |
| 上 | `48h` 数字键盘 8 / Up；`11h` W |
| 下 | `50h` 数字键盘 2 / Down；`2Ch` Z |
| 左 | `4Bh` 数字键盘 4 / Left；`1Eh` A |
| 右 | `4Dh` 数字键盘 6 / Right；`1Fh` S |
| 主操作 | `1Dh` Ctrl；`52h` 数字键盘 0 / Insert；`39h` Space |
| 次操作 | `38h` Alt；`53h` 数字键盘小数点 / Delete；`1Ch` Enter |

战斗模块另直接消费四个斜向键：`47h/49h/4Fh/51h`，即数字键盘 `7/9/1/3`（Home/Page Up/End/Page Down）。快捷键为：Esc 系统菜单、Tab 集体命令、E 音效、M 音量，F1–F4 依次是全部休息、跟随主将、自由行动、全面撤退。

模块 29 还保留一组发布版不可达的开发/调试组合键。DS:`132Fh` 在发布程序中初始化为 `N`、模块内没有写入者，因此主门始终关闭；若外部补丁把它改为非 `N`，Caps Lock+J 会把战斗结果写成 999 并进入正常胜利/逐关事件分发，Caps Lock+数字键盘 `*` 会直接以 `nextModule=33` 离开战斗。它们是残留调试入口，不属于正常玩家操作。

## 部署界面

名单采用三列、每列五行，共 15 项一页；旁边是三行页签 `Ⅰ/Ⅱ/Ⅲ` 和独立的 `結束`。鼠标命中表位于模块 27 DS:`0E40h/0ED8h`：

| 区域 | 原点规律 | 尺寸 | 值 |
| --- | --- | --- | --- |
| 名单三列 | X=`57/201/345`，Y=`59/119/179/239/299` | `80×24` | `0..14` |
| 页签 | X=440，Y=`35/65/95` | `80×24` | `0/1/2` |
| 完成 | X=540，Y=35 | `80×24` | `5341h` |

原生命中测试使用严格内部边界，不含矩形外沿。键盘导航则是五个循环列：三个 5 行名单列、一个 3 行页签列、一个 1 行完成列。`0000:0FC8` 把导航索引转换为表坐标再加 `(60,20)`，随后复用同一热区与动作层。

交互副作用：

- 名单主操作：加入当前 `FFh` 格，或撤下非固定单位。
- 页签主操作：切换 I/II/III 页。
- `結束` 主操作：生成 `JUST.TST` 并离开部署。
- 部署地图主/次操作：分别选前一/后一处 `FFh`，均循环；不存在 `FFh` 时当前部署格置 0。

名单来源、固定单位、满员和撤下规则见 `battle-lifecycle.md`；本文件只负责输入与表现入口。

## 战场光标与视口

可见战场是 `10×7` 格，每格 `40×44`。键盘八方向每次移动一个逻辑格，然后重新居中并夹取视口。鼠标战场内部为 X=`40..432`、Y=`26..325`：

```text
boardX = floor((pointerX - 40) / 40) + viewportOriginX
boardY = floor((pointerY - 23) / 44) + viewportOriginY
```

Y 计算器本身可得到 `0..9`，但外层内部区域判定把实际可见输入限制在七行 `0..6`。边缘区为上 `<26`、下 `>=326`、左 `<40`、右 `>=433`。指针处于边缘时，只在“地圖捲動”打开或主操作按住的条件下滚动一格，并始终夹取到地图与视口边界。

战场内部主操作会更新焦点并尝试选择 side 1、未行动、未禁用且行为值为 0 的单位；次操作取消当前选择/范围叠加并恢复中性光标状态。

## 通用行动菜单

通用菜单的键盘上/下会循环，主操作确认，次操作返回 `X`；鼠标悬停使用逐行生成的 `136×24` 热区，主操作返回该行代码，次操作同样返回 `X`。菜单最多六行，并会移动位置以避开当前指针/右侧信息面板。

| 菜单状态 | 原文与动作码 |
| --- | --- |
| 基础 | `移動 M / 攻擊 A / 休息 H` |
| 基础移动后 | `攻擊 A / 結束 N / 返悔 X` |
| 射击职业 | `移動 M / 攻擊 A / 射擊 S / 休息 H` |
| 移动后仅射击 | `射擊 S / 結束 N / 返悔 X` |
| 移动后可攻可射 | `攻擊 A / 射擊 S / 結束 N / 返悔 X` |
| 技术职业 | `移動 M / 攻擊 A / 技術 C / 休息 H` |
| `0F` 额外移动 | `移動 M / 放棄 N` |

这里的 `結束` 只结束当前单位移动后的动作，不结束整个玩家阵营阶段；`返悔` 恢复行动前位置并清除行动位。内部返回值还包括取消/重试 `CT` 和已完成 `OK`。

## 集体命令与玩家阶段提前结束

集体命令菜单位于 DS:`3F3Eh`：

| 命令 | 原生效果 |
| --- | --- |
| `全部休息` | 遍历 2,500 格；所有 side 1、未行动、行为 0 的手动单位恢复最大生命 15%（向下取整、封顶）并设置行动位；随后进入正常的我方自动与敌方阶段 |
| `跟隨主將` | 把当前选中单位设为已行动和临时主将，立即以领队凝聚模式让其余 side 1 单位交给 AI |
| `自由行動` | 不设置临时主将，立即把其余 side 1 单位交给 AI |
| `全面徹退` | 确认后写退出标志 `Y`，转到模块 27 和当前关卡，重新进入同关部署 |

因此原版确实有提前结束剩余手动阶段的入口，但并非无副作用的通用“结束回合”：最直接的 `全部休息` 会为所有剩余手动单位结算休息恢复；另外两项会把剩余单位交给 AI。`全面徹退` 也不是目标判定失败，尽管二者最终都会回到同关部署。

撤退确认原文为：

> 哦！．．．要撤退嗎？｜必竟是沒辦法的事，雙方的實力差太多了．

该反馈使用 `A/18` 上方窗口与 `D/46` 肖像；非标点 Big5 字符按编码模 15 请求 `MAGIC/57..71` 短声，主操作可快进。确认菜单为“確 定 / 取 消”：确认返回模块 27 的同关部署，取消恢复战斗。完整逐字与输入时序见 `error-and-outcome-presentations.md`。

> 唉啊！．．．要休息了嗎？｜請再考慮一下吧！

退出反馈同样使用 `A/18`、`D/46`、逐字短声和“確 定 / 取 消”菜单；确认才进入模块 0，取消恢复战斗。主操作确认按“按鍵”设置请求 `MAGIC/81`，副操作取消不发该声。

- `音效開關`：`說話 / 移動 / 戰鬥 / 按鍵`，四个独立开关。

### 战术桌物件随设置换帧

`0000:B7C6` 证明右上战术桌并非只绘制一张静态图。程序先把 `A/0006 frame 19` 画在 `(480,0)`，随后按固定顺序用同记录的局部矩形帧覆盖底图。四个可由玩家直接切换的游戏功能使用的就是对应设置字节，而不是另有一套仅供 UI 使用的状态：

| 设置 | 原生字节 / 发布初值 | 关闭帧 | 开启帧 | 覆盖原点 / 尺寸 | 可见物件变化 |
| --- | --- | ---: | ---: | --- | --- |
| `戰鬥動畫` | DS:`1119h` / 1 | 20 | 21 | `(504,11)` / `32×33` | 剑收回 / 剑拔出 |
| `地圖方格` | DS:`111Ah` / 0 | 24 | 25 | `(600,65)` / `32×11` | 右侧烛台局部变化 |
| `地圖捲動` | DS:`111Bh` / 1 | 26 | 27 | `(568,106)` / `40×31` | 地图卷起 / 展开 |
| `人物圖像` | DS:`1118h` / 1 | 30 | 31 | `(608,111)` / `16×3` | 最右下器物的短状态条变化 |

同一重绘链还按发布初值为 DS:`7FACh=1` 选择 frame 29 覆盖 `(584,39)`，为 DS:`7FB0h=0` 选择 frame 22 覆盖 `(528,77)`；它们不对应上述四个玩家直接开关。音效与音乐热点分别打开多项设置面板，保存、读取、目标、集体命令和系统入口也不因一次点击改变成另一张开关图。因此 Web 版只应让这四组已绑定的物件帧随表现偏好同步，不能凭图像相似度替其他热点发明二态。

机器结果见 `input-ui.json` 的 `sidePanel.visualComposition`；`0000:B7C6/B7F1/B812/B833/B854/B875/B896` 七段签名同时锁定底图、覆盖顺序、设置字节、帧号与坐标。

## 单位 HUD

`0000:7C27` 绘制战场、右侧 HUD 和小地图。单位详情开关启用时，焦点停在非空单位格四个更新 tick 且格号与上次不同，`0000:8492` 才刷新详情；移出单位或战场区域会关闭详情并恢复侧栏/小地图。

详情精确表现已由 [`unit-detail-hud-presentations.md`](unit-detail-hud-presentations.md) 和 `../parsed/native/hud-presentations.json` 独立闭合。原生 `640×350` 坐标中，详情占 X=`480..639`；动态 `D` 肖像 frame 0 为 `112×112`、原点 `(488,8)`，身份行明确按“职业／单位名”绘制。五行可见标签和原点为生命 `(488,154)`、攻击 `(488,175)`、防御 `(488,196)`、等级 `(488,217)`、经验 `(488,238)`，肖像旁另有 100 像素生命/经验竖条。

八个状态字 DS:`31A7h..31B5h` 的 bit 15 有效时，程序以对应 `A/17` frame `0..7` 紧密填入四列两行，并在 `(iconX-6, iconY+20)` 绘制低 15 位剩余值。第 37 关的 side 2 在发布版中把九个五字符数值字段全部替换为 `?????`，但不改变真实状态。完整面板现为 C；DS:`3192h` 到所有导出 `D` 记录的完整映射继续作为独立资源索引边界保留。

## 范围明暗与目标输入门

范围表现已由 [`battle-range-and-target-presentations.md`](battle-range-and-target-presentations.md) 和 `../parsed/native/range-presentations.json` 独立闭合。DS:`01A9h` 指向 `50×50` 临时图：非零格完整绘制原地形，零值格把四个位平面逐行与 `11h/44h` 相与，只保留 25% 像素。所有手动落点/目标循环先以同一字节非零为必要条件，再检查空格、阵营或技术专用目标规则；取消/结束后全图填 1，恢复中性亮度。

DS:`58A5h` 是另一张 `10×7` 地图特效 sprite 缓存，由技术描述符经 `1000:84E0/853A` 投影产生，不是移动/命中范围。以后输入层不得读取这张 sprite 缓存判断合法性。

## 实现边界（供后续阶段使用）

本轮没有开始开发。以后实现应保持三条边界：

1. 输入层只产生方向、主操作、次操作、菜单与系统命令等语义动作；物理键、鼠标和手柄映射可替换。
2. 模拟层处理选中、移动、行动位、休息、AI 接管、撤退、存读档与退出状态；HUD 和动画不能反向决定规则。
3. 表现层消费模拟快照和事件，保留 `10×7` 视口、热区、菜单状态、四 tick 详情延迟和设置可见性。

## 已闭合边界与剩余低层项

1. 当前 `AG2.JS3` 的 Keyboard 4 Way 路径已完成 12/12 项“动作→内部索引→Set-1→语义”验证；完整表见 `js3-config-format.md` 与 `AG2-JS3.json`。其字节仍不得直接解释成 Web 键码。
2. 单位详情、范围明暗、目标输入门与独立地图特效层均已闭合；普通受击/死亡、胜负与错误操作的直接表现时间线也已由各专项闭合。
3. DS:`7FADh` 的原设计名称仅保留为不可恢复的历史未知；发布版可观察行为已经闭合为不可达 no-op。
