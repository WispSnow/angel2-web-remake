## 纠错结论

模块 27 `0000:00DC–00F7` 曾被读成“`MUSIC/29` 交接预载”“`MUSIC/25` 场景 6 桥接预载”，这是错的。那段代码是

```text
00E4  mov ax,001Dh          ; 29
00E7  cmp word [DS:02B6],6  ; 当前场景
00EC  jnz  00F1
00EE  mov ax,0019h          ; 25
00F1  mov di,0008h
00F4  call 03C0h            ; 写父接口 word[0008]
```

`0000:03C0` 是“把 AX 写进父接口偏移 8”的通用写入器，全部十个运行模块都用同一形式登记
**下一模块号**（退出前写 0 即离开游戏）。因此 `1Dh/19h` 是模块 29／模块 25，不是 `MUSIC`
记录号；模块 27 与 `MUSIC` 容器（索引 8）之间只有 `0000:06A1` 一处真实调用。模块 29 内部
另有真正的逐关回合选曲表：

- `DS:1D98`：完整回合开始、玩家阶段使用的基础曲号；
- `DS:1E46`：我方自动阶段结束、敌方 AI 开始时使用的基础曲号（场景 37 不查此表，见下文专节）；
- `1000:32D1–338E` 与 `1000:3796–37E7`：先载入/提交 `N+1`，再以衔接循环参数提交 `N`。

因此多数战斗音乐不是一首，而是“奇数短入场 → 偶数长循环”的相邻记录对。第 0 关的完整结论是：

| 时点 | 短入场 | 循环主体 | 证据 |
| --- | --- | --- | --- |
| 关前剧情 | — | `MAGIC/73` | 模块 25 逐关剧情表 |
| 妮雅入场、战场对白、玩家/我方自动阶段 | `MUSIC/7` | `MUSIC/6` | `DS:1D98` stage 0；用户 2026-07-19 实机确认 `7 → 6` |
| 敌方 AI 阶段 | `MUSIC/5` | `MUSIC/4` | `DS:1E46` stage 0 |
| 下一完整回合回到玩家阶段 | `MUSIC/7` | `MUSIC/6` | `0000:4DCD → 1000:371D` 每回合重走玩家表 |

## 场景 37 敌方阶段专属曲

敌方阶段起始 `1000:3680`（由 `0000:4E03` 链在 `0000:4E1F` 远调用）只在 `1000:36BB`
选一次曲，被调用的 `1000:36E6` 并不是无条件查表：

```text
36E6  cmp word [2E77],25h    ; 当前场景 == 37？
36EB  jz  36F7
36ED  mov si,1E46            ; 其余场景：查敌方逐关表（1000:39A8 同样以 DS:2E77 为键）
36F0  call 39A8
36F3  call 3796              ;   再提交“奇数入场→偶数循环”曲对
36F6  ret
36F7  mov ax,[0365] / mov es,ax / mov di,0
36FF  mov cx,30h             ; 记录 48
3702  mov bx,0Dh             ; 容器下标 13 = UN.SWF
3705  call far 0000:FD8E
370A  push [0365] / push 0 / push 1 / push 1
3714  call far <RIX>         ; 与 1000:3796 同一驱动入口；命令 1、模式 1
371C  ret
```

因此“究極女神”一关的敌方阶段不播 `MUSIC/5→4`，而是以命令 1、模式 1 单曲无限循环
`UN/48`（Softstar RIX，3,634 字节，单遍约 9.81 秒）：没有奇数短入场，也不走 `1000:3796`
的曲对提交。`1000:36E6` 除 `1000:36BB` 外没有任何近／远调用者；逐一扫描十个运行模块里
`mov bx,0Dh` 读 `UN.SWF` 的位置，立即数记录 48 只出现在这里（其余表驱动读取是模块 35
的结局插画），所以它是只在本关出现的专属敌方曲。玩家阶段的
`1000:378C` 没有场景分支，下一完整回合仍按 `DS:1D98` 重走 `MUSIC/33→32`。场景 38 不命中
该分支，其敌方阶段照常查表得到 `5→4`。

容器下标来自模块 29 启动时 `1000:03D6` 写进 DS:`FB2F` 的描述表（DS:`00C6`）：`0000:FD8E`
以 `BX*2` 取项，表内依次为 `A/C/D/E/MAGIC/M_00/Y_00/SAY/MUSIC/NUM/CHA/BK/B/UN`，
即 8 = `MUSIC.SWF`、13 = `UN.SWF`。同一张表也纠正了原开发别名表的容器：`1000:338F` 的
别名试听以模式 1 → `BX=8`、模式 2 → `BX=4`，所以 `T01..T08.RIX` 是 `MAGIC/72..79`（模块 25
的剧情曲），此前目录误标为 `UN/72..79`（`UN.SWF` 只有记录 0..62）。

旧目录把 stage 37 列在曲对 `4/5` 的敌方用途里，是只读了逐关表、漏看 `1000:36E6` 首条比较
所致；用户 2026-09-22 反馈原版本关有一首只在此出现的敌方行动曲，据此复核闭合。

## 出场准备界面音乐

出场准备（名单）界面归模块 27 独有，它在画名单之前就给 RIX 驱动提交自己的循环曲，不沿用
关前剧情或上一关战斗的曲子：

| 地址 | 作用 |
| --- | --- |
| `0000:0584` | `cmp word [DS:0FF6],0`：当前空部署格为 0 的关卡直接跳过整段交互名单，因而**不播放**这条曲子 |
| `0000:06A1` | `cmp ax,5` / `ja`：场景不大于 5 载入 `MUSIC/16`，否则载入 `MUSIC/17`（两条都走容器索引 8） |
| `0000:0591` | 以驱动命令 1、模式 1 提交缓冲，即单曲无限循环，不是“奇数入场→偶数循环”曲对 |

生命周期是明确的模块边界，不是淡入淡出：模块 25 在关前剧情结束时以命令 0 关闭 RIX 驱动，
模块 27 启动时用命令 `FFh` 重新初始化再起本曲；名单确认后模块 27 只用命令 2 清掉待接续曲，
音乐持续到模块 27 进程退出，随后由模块 29 起本关战斗曲对。场景 42 走 `MUSIC/17` 分支。

`MUSIC/15` 与 `MUSIC/16` 的原始 RIX 字节完全相同，因此听感相同不能证明 `MUSIC/15` 也有场景绑定。
