# 状态生命周期、中毒与原版零生命边界

日期：2026-07-14；零生命边界复核：2026-08-20

## 结论

模块 29 已把八个单位状态字的施加、消费、净化和倒计时连接到标准战斗回合。状态不是在每个阵营阶段递减，而是在完整的“玩家 side 1 → 我方自动单位 → side 2 AI”结束后、下一次玩家阶段开始前统一处理一次。

其中施毒的原生效果不是固定扣血，也不是最大生命百分比：每次完整回合边界直接执行：

```text
currentLife = floor(currentLife / 2)
```

毒伤先结算，随后同一边界才递减状态计数。`8003h` 因此会触发三次减半，并依次变为 `8002h → 8001h → 0000h`。

机器可读结果位于 `reverse/parsed/native/combat-formulas.json` 的 `statusLifecycle`，重复导出命令为：

```sh
node reverse/tools/angel2-combat-formulas.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/parsed/native/unit-descriptors.json \
  reverse/parsed/native/combat-formulas.json
```

导出器现验证 41 段普通战斗/状态关键代码签名，并逐字节枚举死亡扫描器的全部直接调用点。

## 完整回合边界

标准战斗主循环 `0000:48FE` 在 side 2 AI 阶段之后先检查失败/胜利。若战斗尚未结束，便由 `0000:4DCD` 开始下一完整回合：

1. 执行行动位/显示整理并重绘战场；
2. `DS:2F83h += 1`；
3. 绘制新回合数字；
4. `1000:35DC → 3633` 扫描全棋盘并结算毒伤；
5. 对 side 1 指针表 `45D0h` 和 side 2 指针表 `4BECh` 分别调用 `1000:35F2`，统一递减状态；
6. `1000:42A8` 分发逐关回合事件；
7. 返回下一次玩家阶段。

所以状态持续单位应写成“完整回合边界 tick”，不能写成“己方三回合”或“敌我各阶段一次”。状态在某个完整回合内越晚施加，距离第一次 tick 越短；例如 side 2 在敌方阶段末施加的 `8003h` 会很快遇到第一次边界结算。

## 八个状态槽

| 偏移 | 原版名称 | 施加值 | 已确认消费者 |
| ---: | --- | ---: | --- |
| `+08h` | 攻击提升 | `8003h` | 有效攻击 `+20` |
| `+0Ah` | 防御提升 | `8003h` | 有效防御 `+20` |
| `+0Ch` | 防魔 | `8001h` | 各技术路径的保护；地图路径还阻止移动/逐点扣血 |
| `+0Eh` | 混乱 | `8003h` | AI 装载时强制行为 `FFh`；普通职业防御撤退，射击/技术/女帝职业随机移动后结束动作 |
| `+10h` | 攻击下降 | `8003h` | 有效攻击 `-20` |
| `+12h` | 防御下降 | `8003h` | 有效防御 `-20` |
| `+14h` | 施毒 | `8003h` | 每完整回合边界把当前生命除 2 向下取整 |
| `+16h` | 禁咒 | `8003h` | 阻止玩家技术菜单；技术职业 AI 改走普通 AI |

所有施加器都直接覆盖完整状态字，而不是 OR 或累加。重复施加会刷新为 `8003h`；防魔刷新为 `8001h`。

`+08h/+0Ah/+10h/+12h` 的 `±20` 由 `1000:8C2D` 写进有效攻／防，而它排在难度加成
`1000:8BD1` 之前（完整装载顺序见 `ordinary-combat-formulas.md#装载顺序状态修正先于难度倍率`）。
因此 `LV_HARD==3` 的 side 2 单位实际相差 30 点，side 1 与其余难度才是 20 点。

## 通用倒计时

`1000:35F2` 对每个阵营的 58 个状态指针逐一处理 `+08h..+16h` 的八个偶数偏移。每个状态字使用同一公式：

```text
if (word & 0x8000) {
  counter = (word & 0x7fff) - 1
  word = counter == 0 ? 0 : (0x8000 | counter)
}
```

因此：

```text
8003h → 8002h → 8001h → 0000h
```

防魔的 `8001h` 若没有被某个效果提前消耗，会在下一完整回合边界清零。

## 破邪/净化

`1000:8D4C` 对五个负面槽采用两种原生写法：

- 防御下降、攻击下降、混乱：只清 bit 15，保留低 15 位计数；
- 施毒、禁咒：直接写入 `7FFFh`。

通用倒计时只处理 bit 15 为 1 的字，因此这些值之后保持不变。但它们不是永久免疫标志：任何后续状态施加器都会把完整字重新覆盖为 `8003h`。

## 混乱的 AI 行为覆写

混乱名称和写入器均已确认，普通邪剑攻击与玩家技术 `LA` 会写同一个 `+0Eh` 槽。`1000:2300` 装载当前 AI 决策输入时，以 `SI=31A5h+8` 间接组成 DS:`31ADh`；若 bit 15 为 1，就把逐槽行为值 DS:`0D3Fh` 覆写成 `00FFh`。此前的直接地址审计只查找立即数 `31ADh`，因而漏掉了这条寄存器算址读取；“混乱为空效果”的旧结论作废。

`FFh` 在职业主链中有两种明确结果：

- 普通职业 `1000:18A1`：调用防御撤退 `1000:1D67`，在本单位正常移动范围内选空格、要求四邻无敌军，再最大化地形防御百分比；有格则移动，无格则原地，之后都直接消耗动作，不攻击。
- 射击职业 `1000:192C`、技术职业 `1000:19DD`、女帝/龍 `1000:1A68`：调用 `1000:212D/216E`，按格号从 0 向 2499 扫描非零移动范围格，选择首个 PIT bit 0 为 0 的候选；若不是原格则移动，然后直接消耗动作，不射击、不施法。

玩家单位选择器 `0000:55D3` 的四项判据确实不读取 `+0Eh`，所以混乱单位仍能通过选择门；但
被接受的格随即进入 `0000:66F4`，该处用与 `1000:2300` 完全相同的 `SI=31A5h+8` 算址重读
DS:`31ADh`：

- bit 15 为 0 时落到 `0000:6733`，即正常的手动动作流程；
- bit 15 为 1 时先 `mov ax,1Ch` 调 `0000:C97E`，用当前单位画像播出 DS:`84BBh[1Ch]`→
  DS:`86ABh` 的「我的頭好昏，無法思考．」，再 `9A 9600 4711`（线性 `1000:1506`）把该单
  位单独交给 AI 分发：`1000:1506` 写 DS:`1F16h`、调 `1000:2300` 装载（这里再次覆写
  `FFh`）并执行职业分派 `1000:1681`。返回后 `0000:560E` 写 DS:`1F16h = FFFFh`，命令菜单
  始终不会打开。

因此“混乱只影响自动阶段、手动单位仍可正常操作”的旧结论作废：玩家点一下被混乱的单位，它
就会先说话再自行乱走并消耗行动。这条 `0000:66F4` 的读取与 `1000:2300` 属于同一类算址读
取，早期只查立即数 `31ADh` 的审计同时漏掉了两处。`0000:66F4` 直接调 `0000:C97E`，不经过
`1000:254F`，所以这句台词不受“ＡＩ對話”开关 DS:`111Ch` 控制。原版没有阵营反转，也没有让
普通职业攻击友军的路径。机器结论见 `../parsed/native/ai-rules.json` 的
`rules.playerConfusionRoute`。

## 中毒降到 0 生命的原版边界

2026-08-20 对完整模块重新做调用图审计：`1000:3633` 的完整函数体只有棋盘扫描、毒状态
检查、`shr ax,1` 与生命写回，没有最低值夹取，也不调用死亡移除器 `0000:96C2`。
上层 `1000:35DC` 只依次调用毒扫描与双方状态递减；`0000:4DCD` 随后虽会调用逐关事件
分发器 `1000:42A8`，但这条正常回合路径没有通用零生命扫描。全模块对 `0000:96C2` 的
直接 near call 只有 `0000:63D2/9156/91E6/92A6` 四处，far call 为零；四处都属于伤害
收尾，不在毒／状态链中。交叉检查还确认：

- 玩家单位选择器 `0000:55D3` 检查阵营、行动位、逐槽禁用值和自动行为值，但不检查当前生命；
- 胜负条件检查阵营图/单位槽图上的“存在或消失”，不读取生命；
- AI 的生命百分比函数会把 0 生命算为 0%，随后进入低生命休息策略；
- 休息可恢复最大生命的 15%。

所以结论是：**毒可以把 `1 HP` 写成 `0 HP`，但写成 0 的当下不会让角色死亡。**该单位
暂时仍留在棋盘、计入保护／全灭条件，并可能在死亡扫描发生前通过休息恢复。普通攻击、技术
或脚本伤害的收尾会显式调用全棋盘死亡扫描；之后只要任一这类流程发生，即使打的是别的单位，
仍在场的 0 生命单位也会被一并移除。原版兼容层必须保留这两个时点的区别；若 Mod 希望毒
写成 0 时立刻致死，应作为显式规则开关，而不能改写成原版事实。

## 实现规范

原版兼容层至少需要回归测试：

1. `8003h` 连续三次边界 tick 后清零；
2. 毒伤在计数递减前触发；
3. 生命 `7 → 3 → 1 → 0`；
4. 0 生命毒伤单位仍在棋盘且不满足“单位消失/敌方全灭”；
5. 0 生命玩家单位仍可选择并休息，0 生命 AI 进入休息策略；
6. 重复施毒刷新为 `8003h`；
7. 破邪后的 `7FFFh` 不递减，但可被再次施毒/禁咒覆盖；
8. 混乱单位进入 AI 调度时覆写为 `FFh`；普通职业只尝试防御撤退，射击/技术/女帝职业只尝试 PIT 选格移动，两类都不执行攻击/射击/技术；玩家手动选择本身不被禁止。

地图逐点伤害与全屏战斗伤害对防魔的路径差异仍需实机确认可触发条件；这不影响本页已经闭合的状态 tick、毒伤和零生命棋盘语义。
