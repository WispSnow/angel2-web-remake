# 战斗单位详情 HUD 表现

日期：2026-08-06

## 结论

模块 29 的悬停单位详情不是静态面板图，而是由矩形、`A/6` 装饰片、图案填充、Big5 文本、动态 `D.SWF` 肖像、`A/17` 状态图标和两个比例条按固定坐标拼装。现已用 19 段代码、4 段 DS 数据签名闭合刷新条件、绘制顺序、面板几何、字段来源、资源绑定和第 37 关隐藏规则。

机器规格位于 `../parsed/native/hud-presentations.json`，坐标核验图位于 [`../renders/hud-presentations/unit-detail-layout.svg`](../renders/hud-presentations/unit-detail-layout.svg)。重复导出命令：

```sh
node reverse/tools/angel2-hud-presentations.mjs --extract \
  reverse/unpacked/lzexe-modules/raw/0029-unpacked.bin \
  reverse/renders/planar \
  reverse/parsed/native/hud-presentations.json \
  reverse/renders/hud-presentations/unit-detail-layout.svg
```

核验图嵌入调色板正确的原始 `A/17` 图标和一个代表性 `D/46` 肖像，但不是原版截图：文字字体、背景图案、数值和肖像选择只用于检查坐标。JSON 内的坐标、字段和资源绑定才是权威规格。

## 刷新与消失

`0000:7C27` 先更新焦点/视口格并绘制 `10×7` 战场，再调用 `0000:8492` 管理详情：

- 人物图像/单位详情开关 DS:`5D48h` 和控制门 DS:`6004h` 都必须为 `Y`。
- 鼠标模式下指针 X 必须不超过 440；当前焦点格必须有单位。
- DS:`6019h` 连续累计四个更新 tick 后才可显示；若线性格号仍等于 DS:`6002h` 的缓存则不重复绘制。
- 移出单位或战场区域后，程序清缓存和计时器、令 DS:`5DECh` 退出详情态、使两个 VGA 缓存页失效，并恢复普通侧栏及小地图。

四 tick 是原生更新计数，标称约 40.0006 ms；Web 忠实层使用 40 ms 逻辑等待。

## 拼装顺序与整体范围

详情占据 X=`480..639` 的右栏，使用原生 `640×350` 坐标。`0000:851A` 的调用顺序为：

1. `86C9h`：顶部背景、外框和肖像右侧双竖条框。
2. `8ACDh`：从 loader container 2 动态请求 DS:`3192h` 所指记录，绘制 `D` 记录 frame 0 到 `(488,8)`；所有已渲染 `D` frame 0 均为 `112×112`。
3. `883Ch`：绘制肖像边框。
4. `8B2Bh`：绘制职业、全角斜线和单位名。
5. `88E4h`：绘制回合框。
6. `8962h`：填充数值/状态主体，绘制分隔框、五行数值、比例条与状态图标。
7. 将当前 VGA 页复制到详情缓存。

面板主体为 `(480,150)` 到 `(639,320)`，在 Y=`172/192/256` 分隔数值区和状态区。全部 23 个已确认矩形及颜色索引见机器规格；其颜色使用原生 gameplay VGA DAC 调色板。

### `A/6` 右栏装饰拼装

`A/6` frame `0..14` 是右栏共用的边角、分隔条、回合框与 `HP/EXP` 字样，不是独立的完整面板：

- 单位上框为 `160×149`。frame 1/0 从 X=`487` 起以 8 px 步长铺顶部/底部，frame 5 落四角；frame 6/7 沿肖像左右以 7 px 步长重复 16 次，frame 2/3/4/8 收口肖像底边，frame 14 位于 `(600,113)`。
- 战术小地图仍为 `(485,161,150,150)`；frame 9/10 分别落在 `(480,150)`、`(480,311)`，frame 6/7 从 Y=`160` 起沿左右各重复 22 次。
- 回合框占 `(480,322,160,28)`；frame 12 横向重复 18 次，再由 frame 11/13 在 X=`480/624` 收口。
- 数值/状态主体没有整张位图，而由 `8962h/89DCh` 的调色板矩形构成：外框占 `(480,150)..(639,320)`，五行起始 Y=`151/172/193/214/235`，状态区从 Y=`256` 开始。

导出器逐张校验这 15 张 PNG 的尺寸、无 mask 属性和哈希；`content:stage0` 再把重复绘制固化为浏览器运行时的上框、主体、小地图框与回合框，避免 CSS 近似纹理。

### 肖像映射边界

可以确认 `8ACDh` 把 DS:`3192h` 作为动态索引传给 container 2（`D.SWF`）读取器，并使用 frame 0；不能仅凭图像外观确认所有逻辑值与导出 `D/xxxx` 记录号的一一映射。因此规格保留原始请求字段，不虚构完整肖像表。核验图的 `D/46` 只是尺寸与落点样本。

## 身份与数值行

身份行位于 Y=`124`：

| 内容 | 来源 | 原点 |
| --- | --- | --- |
| 职业/显示名 | DS:`31BBh`，经 DS:`5DEFh` 格式化 | `(484,124)` |
| `／` | DS:`5DF8h` | `(552,124)` |
| 单位名 | DS:`3190h`，经 DS:`5DFBh` 格式化 | `(564,124)` |

所以可见顺序明确是“职业／单位名”，不是反序。

五行模板和原点为：

| 模板 | 原点 | 数值来源 |
| --- | --- | --- |
| `生命00000/00000 ` | `(488,154)` | 当前 DS:`319Fh` / 最大 DS:`31C3h` |
| `攻擊00000/00000 ` | `(488,175)` | 状态/难度后的有效 DS:`31BFh` / 临时状态修正前 DS:`31CFh` |
| `防禦00000/00000 ` | `(488,196)` | 状态/难度后的有效 DS:`31C1h` / 临时状态修正前 DS:`31D1h` |
| `等級00000 ` | `(488,217)` | DS:`31BDh` 成长/等级行 |
| `經驗00000/00000 ` | `(488,238)` | 当前累计经验 DS:`318Eh` / 下个累计阈值 DS:`31A1h` |

这里确认了原版可见标签“等級”，因此 GDD 的中性内部名称“成长/等级行”可以进一步定界：UI 把 DS:`31BDh` 明确呈现为等级，但规则层仍须保留它作为累计成长行计数，而不能假定它等于 `DATA` 当前固定行的末字段。

## 生命与经验竖条

肖像右侧有两个 100 像素高的自下向上比例条：

- 生命：X=`606`、宽 11、颜色索引 11，`percent=floor(currentLife*100/maxLife)`。
- 经验：X=`619`、宽 11、颜色索引 8，`percent=floor(currentExperience*100/nextThreshold)`。
- 两者动态矩形均为 `y=108-percent, height=percent`；百分比为 0 时不画填充。

因此竖条覆盖 Y=`8..107`，旁置于肖像而不是五行文字区。

## 第 37 关数值隐藏

`0000:8B7C` 完成普通格式化后有一条发布版可达的特殊分支：

```text
DS:132F != 'Y' AND stage == 37 AND selected side == 2
```

满足时，`0000:8C24` 把九个五字符数值字段全部改成 `?????`：生命当前/最大、攻击有效/基础、防御有效/基础、等级、经验当前/阈值。DS:`132Fh` 是外部可补丁的开发门；若被改成 `Y` 会跳过隐藏，但正常复刻不应把它做成玩家设置。

## 状态图标与剩余回合

`0000:8A08` 固定读取 `A.SWF` 记录 17。该记录已复原为八个带透明遮罩的 `40×31` 图像，frame `0..7` 与单位动态状态槽 `+08h..+16h` 一一对应：

| frame/槽 | 状态 |
| --- | --- |
| 0 | 攻击上升 |
| 1 | 防御上升 |
| 2 | 防魔 |
| 3 | 混乱 |
| 4 | 攻击下降 |
| 5 | 防御下降 |
| 6 | 施毒 |
| 7 | 禁咒 |

程序按槽 `0..7` 扫描 bit 15。有效图标不是固定占用自己的槽坐标，而是依扫描顺序紧密填入：

```text
X: 484, 522, 560, 598, 484, 522, 560, 598
Y: 259, 259, 259, 259, 289, 289, 289, 289
```

低 15 位剩余值绘制在 `(iconX-6, iconY+20)`，该数字绘制关闭逐字语音。DS:`5E18h..5E63h` 邻接保存七条状态文字候选，但没有发现单位详情绘制器直接引用；已确认 HUD 只画图标和剩余值，不能把这些字符串提升成可见标签。

## 回合显示

`0000:88E4` 把 DS:`2F83h` 转为五字符数字缓冲 DS:`6006h`，取最后三字符填入 `第  10  回合` 模板，前导零会变为空格，再以 `(516,327)` 为原点绘制。因此可见回合字段最多占三个字符。

## 与范围及地图特效层的边界

后续专项已经闭合战场格绘制器，但范围仍不属于 HUD：

- `7DC0h/7DEFh` 以 `(40,23)` 为首格原点绘制 `10×7`、`40×44` 视口。
- `7E2Ah` 读取地形、占用、单位和 DS:`01A9h` 指向的 `50×50` 范围临时图；`7E6Ch` 为两个 VGA 页缓存每格四种源字节。
- 范围值非零时地形保持完整，值为零时四个位平面逐行套 `11h/44h` 网点掩码；选择循环也把非零作为必要合法性条件。
- `7EDDh` 读取的 DS:`58A5h` 是独立 `10×7` 地图特效 sprite 缓存：`0/83h/bit7` 不画，`1..127` 先减 1 后作为动态描述符 frame 绘制。
- `80B0h`、`82CDh` 分别负责当前格标记和焦点/指针层，不等同于移动/命中范围。

完整生产链、普通攻击/移动/射击/技术/工兵绑定及核验图见 [`battle-range-and-target-presentations.md`](battle-range-and-target-presentations.md) 与 `../parsed/native/range-presentations.json`。原“范围图投影到 DS:58A5h”的假设已被唯一写入点 `1000:853Ah` 否定并撤销。

## 实现边界

Web 右栏现已消费上述生成装饰与原生坐标，同时保持三项边界：

1. HUD 是模拟快照的消费者；不得以显示字符串反向驱动生命、经验或状态规则。
2. 第 37 关隐藏只影响九个文字字段，不修改真实数值和双比例条的模拟值。
3. 范围图与地图特效缓存继续作为两个独立层；HUD 不生成或修改任一层。
