## 资源清单与分包

`scripts/generate-resource-manifest.mjs` 从 `public/assets/original/` 生成：

- `public/assets/original/resource-manifest.v1.json`：schema 版本、内容身份、URL、逻辑字节数、
  SHA-256、资源包归属、包依赖与战役顺序；
- `src/game/content/resource-manifest.generated.ts`：运行时固定的清单 URL、schema 版本和内容身份。

清单使用第一阶段发布清理后的最终路径：零碎全景帧、地图命中／死亡、回合切换、逐关连续
特效和地图技能源帧都不会进入清单，取而代之的是 PNG + Phaser JSON Hash 图集。开发／证据源
仍留在 `public/`，生成器只把它们排除于玩家清单，不删除来源。

## 运行时顺序

1. 普通页面先显示同游戏构图一致的 DOM 加载页并读取清单与 `boot`。开场挂载后，静默后台
   读取第 0 关包；后台请求不会阻塞开场动画。`boot` 的 16 张 PNG 会在加载页内从同一次响应
   建立对象 URL 并解码，开场 Canvas 与菜单图片全部就绪后才设置动画时间原点。
2. 标题页后台准备第 0 关时一并读取其已知职业表现；新游戏进入任何战场表面前必须等第 0 关
   包与职业补充集合。若后台读取仍在进行，加载页接管同一批请求并按清单逻辑字节显示进度。
3. 继续游戏先通过原有严格存档校验，再以保存目标关卡通过同一资源门；完成态存档需要来源
   关运行时时，也先载入该来源包。
4. 关卡控制器先解析下一关代码清单，以取得固定／敌方职业，再在建立或挂载新战场表面之前
   等待下一关包及职业表现集合。新关实际挂载后，只静默预取战役顺序中的再后两关；不会把
   全战役设为强制依赖。
5. `stage-49` 结局与 `stage-39` 制作人员表在各自 DOM 表面挂载前走独立资源门。

加载页使用原生 `<progress>`、可读状态与 `aria-live` 文字；进度以响应流累计字节／清单逻辑
字节计算。单个请求失败会保留错误 URL 与 HTTP 状态，并提供聚焦的“重试”按钮；失败项会清除
自己的 Promise 状态，重试会真实重新发请求。并发仍在收尾的请求不会覆盖失败文字。

## 内存与解码边界

- 普通非渲染资源仍只流式读完响应并丢弃正文。资源门会为当前表面与最多两个预取包保留 PNG／JSON
  的压缩字节；正式 Phaser 战场的地图、棋子、地形动作和地图技能图集从同一次响应惰性建立对象
  URL；地图命中／死亡、回合交接、第 4 关力场与第 26 关推柱等连续战斗特效图集也走同一边界。
  场景切换撤销旧 URL，预取淘汰则释放不再被当前／其它预取包引用的编码内容。全景职业／物理侧
  图集、公共尘埃与当前原生关卡可能选中的背景还会在加载门内进一步建立
  对象 URL 并等待 `HTMLImageElement.decode()`，DOM 时间轴因此不会在首帧时再次请求或才开始解码。
  这些解码图只由当前关租约持有，换关即释放上一组，不会把全战役纹理同时放进内存。关卡、部署、
  结局和片尾的 OGG 则在资源门内保留压缩编码数据并直接交给 `MusicTransport`，所以切入场景后的
  首次选曲不会再发网络请求。
- `boot` 是当前表面的特例：它会在隐藏加载页前解码包内全部 16 张开场／标题 PNG。开场运行时
  直接复用这些已解码对象；Canvas 图片与标题／难度菜单的实际 DOM 图片未全部就绪时，RAF 与
  `phaseStartedAt` 都不会启动。切入第 0 关后资源租约照常释放，不让开场纹理永久驻留。
- `MusicTransport` 仍只在当前选择曲目且浏览器已获用户激活时调用 `decodeAudioData()`；成功产生
  `AudioBuffer` 后立刻释放对应编码副本，不提前解码全战役音乐。切换曲目时旧曲保持到新曲解码
  并排程完成后再交叉淡出，不制造网络等待造成的静音断层。
- `BattleScene` 不再每关把 36 个我方职业全部交给 Phaser。它只预载棋盘当前职业、其即时
  转职候选及关卡显式动态棋子；后续转职层与无关职业不会进入该 Scene 的纹理管理器。正式场景
  的这些图片与技能图集使用当前资源租约；实验室没有分段资源门时仍直接读取相同正式路径。
- 没有 Service Worker、R2、全战役强制下载或音乐全量解码；地图、剧情背景和音乐仍是独立文件。

## 自动验收合同

- 单元测试逐项复算 1,291 个清单资源的字节与 SHA-256，核对包图、逐关部署音乐、两关预取顺序、
  图集最终路径和零碎来源排除；另验证当前职业／即时转职候选的棋子、双侧全景与技能图集集合，
  以及原版仅右侧全景职业的边界。
- Chromium 覆盖：冻结所有开场 blob 解码时加载页保持可见且不挂载开场，解除后 16 张源图各
  精确请求一次并绘出首幅背景；开场显示时第 0 关已后台请求但第 1 关未请求；新游戏在第 0 关包、当前职业
  全景或背景音乐任一未完成前都不挂载 Phaser，音乐播放直接复用同一次请求；失败页保留错误并
  可重试；继续游戏等待存档目标关；直接通关只强制下一关，挂载后才请求再后两关且不请求第四关；
  冷缓存士兵全景的职业图集与背景各只请求一次，并在第一段攻击帧前均已解码；正式初級炎暴
  会拒绝地图／棋子／技能图集源 URL 的第二次请求，仍完整显示并结算；命中／死亡与回合交接图集
  也在同样拒绝第二次请求时完成实际演出，从而覆盖 Phaser 重试耗尽边界。
- 加载进度页与失败重试页均纳入显式视觉审计；最终验证命令及结果以本次交付报告为准。
