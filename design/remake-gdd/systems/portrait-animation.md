# 全战役肖像动画合同

版本：Draft 0.2

状态：已实现，等待第 1 关人工复验

## 1. 原版事实

- `[OF]` `D/0..67` 是原版肖像记录范围。除 `D/63` 外，其余记录都包含 `112×112`
  主肖像、frame `1..3` 眼部覆盖片和 frame `4..6` 口部覆盖片。
- `[OF]` 原版三张肖像元数据表覆盖 id `0..62、64..66`，每项保存眼部与口部原点。
  `D/63` 没有元数据，也没有可用覆盖帧，因此只能保持静态主肖像。
- `[OF]` `D/59` 的表 C 元数据把眼部原点写为 `(40,24)`，但其 `16×16` frame 1
  与主肖像在该位置不匹配；frame 1 在 `(56,24)` 与主肖像逐像素完全一致。发布版剧情
  的 50 个直接引用肖像 id 不含 `59`，因此这笔错误不会在原版剧情眨眼流程中暴露。
- `[OF]` `D/67` 没有独立元数据；SAY 74 先加载 `D/56` 再加载 `D/67`，利用查找失败后
  沿用上一组布局的行为完成龍王换色。因此 `D/67` 使用自己的图像帧和 `D/56` 的布局。
- `[OF]` 眨眼顺序为睁眼／半闭／闭眼／半闭／睁眼。剧情口型只在 Big5 双字节字形后
  切换 frame 4“闭嘴”和 frame 5“小幅张嘴”；frame 6 虽是完整素材，发布版剧情不可达。

## 2. 复刻决定

- `[DD]` 敌我双方及命名／通用角色共用一份由证据生成的全战役肖像目录；关卡、部署、
  HUD、剧情和反馈只提交稳定 `portrait` 记录号，不得再维护逐关或逐角色动画表。
- `[DD]` 具备原版覆盖帧和布局的每个角色，在剧情窗与战场 HUD 中都启用相同眨眼能力；
  当前逐字发言者同时启用原版 frame 4/5 口型。未发言肖像保持闭嘴，但眨眼不停止。
- `[DD]` `D/63` 显式标为“原版无动画资料”的静态例外，不能用通用闭眼贴图或推测坐标
  伪造动画。新增证据前不改变这一边界。
- `[DD]` `stableRemake` 按 `REMAKE-010` 把 `D/59` 眼部原点校正为 `(56,24)`；口部仍
  使用原版 `(64,32)`。生成目录同时保留原始坐标与决策 ID，不改写 `reverse/` 证据。
- `[DD]` 眨眼是独立表现随机，不能消耗模拟 PRNG；跳过文本、减少动态、标签页节流或
  音频失败不得改变战斗状态、存档或随机序列。

## 3. 生成与运行时边界

- `scripts/generate-portrait-catalog.mjs` 从
  `reverse/parsed/native/story-presentations.json` 和
  `reverse/renders/planar/D/manifest.json` 生成
  `src/game/content/portrait-catalog.generated.ts`，并把浏览器资产固化到
  `public/assets/original/portraits/`。
- 新关卡引用现有原生肖像记录时，不需要复制主图、覆盖帧、尺寸或坐标；重跑
  `pnpm content:portraits` 即可复现完整目录。
- `/portrait-lab.html` 显示全部 68 笔记录，可强制半闭／闭眼、闭嘴／两种张嘴素材，
  并以正式眨眼时钟和逐字口型持续预览。该页面不建立战役或修改存档。

## 4. 验收

1. 目录包含 `D/0..67` 全部主肖像；67 笔具有三眼、三口覆盖片，`D/63` 明确静态。
2. 第 0–1 关使用的 `0、15、42..48` 都能在实验室及正式剧情/HUD 中眨眼。
3. 蒙欣曼、黛西等第 1 关发言者逐字输出时只切换 frame 4/5，补全后立即闭嘴。
4. `D/67` 显示自己的帧，但布局来源标记为 `D/56`。
5. 所有肖像请求成功，像素边缘不平滑；普通战斗模拟、PRNG 与存档结果零变化。
6. `D/59` 睁眼覆盖片在 `(56,24)` 与主肖像像素完全一致，闭眼帧不得再覆盖脸部左侧。
