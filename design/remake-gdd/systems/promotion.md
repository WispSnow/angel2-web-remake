# 转职系统规格

状态：`accepted`

授权日期：2026-07-27

用户接受日期：2026-08-01

依赖：职业目录、经验成长、普通行动结算、战役 roster、Web 存档

## 玩家目的

玩家在单位进入当前职业的第 4 个成长行后，从原版候选顺序中选择下一职业，让角色取得新的数值、移动 profile 与职业行动方向。选择会清空该单位的当前累计经验，但不会恢复当前生命。

## 证据与决策

- `[OF]` 原版共有 39 个职业记录、12 个可继续转职的来源职业与 31 条普通转职边；候选及顺序见 [`unit-catalog.json`](../../../reverse/parsed/native/unit-catalog.json) 和 [`unit-data-and-promotions.md`](../../../reverse/notes/unit-data-and-promotions.md)。
- `[OF]` 模块 29 在一次正常战斗动作处理后、胜负与逐关事件检查前调用转职扫描；扫描按 `50×50` 棋盘格号从小到大检查全部 side 1 单位。
- `[OF]` 资格要求为当前成长/等级行计数大于 3，且当前职业至少有一个非 `99` 候选；没有角色、关卡或手动/自动控制限制。
- `[OF]` 战斗装载只读取 `DATA` 前三行；第三行后按职业短码成长。12 个可转职来源的 side 1／side 2 短码都使用默认 `经验 +100／攻击 +1／生命 +10`，所以实际触发阈值是“第三行累计经验 +100”。`DATA` 第四行只保留表格证据，不是运行时转职阈值。
- `[OF]` 候选菜单按原生表顺序生成。进入选择后不可取消，必须选出一个合法职业。
- `[OF]` 菜单出现前，`0487h` 先自动播放转职逐字对话且不等待确认：妮雅只在上方窗口自问职业；其他队友先在下方请求主将授职，再保留下方窗口并由妮雅在上方以水神「愛西斯」之名回应。两者复用同一套 `A/18` 窗口资源，但 `08DDh` 的原生文字光标分别位于上窗内 `(27,20)` 与下窗内 `(43,20)`。
- `[DD]` 依据 `REMAKE-018`，`stableRemake` 要求授予者在当前战场实际出场：妮雅在场时保持原版；妮雅缺席的第 3 关改由主将希蜜授职。授予者本人达标时使用单段自问，不让角色向自己请求授职。
- `[OF]` 原生提交写入目标职业并把经验归零；当前生命不变。随后普通装载才以“新职业 + 零经验”重建派生属性。
- `[OF]` 弓兵 `DATA` 第四行 `field6=7`、弩兵首行 `field6=8` 是 31 条边中唯一的表格等级不对齐；生产提交链不读取这两个值，因此它不改变弓兵在职业内第 4 成长行触发、选择弩兵后职业内等级归 1 的规则。
- `[SR]` 依据 `REMAKE-001`，Web 把提交和随后装载合成一个确定性原子事务：职业与经验先变化，再立即重建等级、攻防、最大生命、移动 profile 与职业行动身份，当前生命保持原值。
- `[DD]` 具名角色以角色肖像作为身份，转职后保留姓名与肖像；没有角色身份的通用单位以当前职业的通用肖像作为身份，转职后姓名、职业名、地图棋子和通用肖像都同步为目标职业。授职对话中的通用肖像标签使用完整当前职业名，不使用头像目录中的“戰士”“騎士”等分支标签。
- `[DD]` 第 0 关 M00.5 只解冻转职、职业目录、通用状态边界及其存档/UI 闭环。第 1 关地图、部署、关卡入口、状态系统，以及射击/技术效果仍不因此解冻。
- `[DD]` 弓兵和修女仍保留所有职业共有的普通移动、攻击与休息，因此在第 0 关内可继续行动；其额外“射击”或“技术”入口由职业目录正确声明，但要在相应系统切片获得授权后才显示和结算。
- `[OF]` 原版候选画面保留战场，不加全屏暗层，也没有标题或属性文字。`A/0006` 组成 `(160,110) 332×126` 的固定底框／阴影；`A/0002` 职业图从 `(184,134)` 起按 56 px 单行排列，`48×52` 框内普通色为 palette 1、当前项为 palette 12。
- `[DD]` Web 默认选择画面逐像素恢复上述原版构图和候选顺序。职业名称、行动方向、目标职业已有的额外特性、零经验属性及相对当前职业的数值差不再常驻；鼠标悬浮或键盘焦点落在职业按钮上时，才以增强浮层显示详情。浮层紧邻并居中位于当前职业按钮下方，原有第二行行动方向保持不变；有额外特性的高阶职业在其后另起一行说明。提交不可取消仍属于规则，但不在卡片底部重复警告。屏幕阅读器仍从按钮标签获得同等职业信息。

## 触发与输入

- 进入条件：一次会提交行动的普通攻击、休息、等待或自动行动已经完成表现与规则结算，尚未执行胜负或逐关事件检查。
- 合法行动者：仍在棋盘上的 side 1 单位；触发者不必是刚完成动作的单位。
- 合法目标：当前职业原生候选表中的职业，保持原生 option index 顺序。
- 取消边界：转职覆盖层是强模态；`cancel` 不关闭、不回退战斗，也不改变选择。存档、系统菜单、战场和镜头输入均被阻断。
- 提交时点：玩家确认候选职业时一次性提交；只移动焦点不改变模拟、PRNG 或存档。

## 有序规则

1. 当前动作完整结算并标记行动状态；若行动者死亡则先从棋盘移除。
2. 按 `y * stage.width + x` 升序扫描当前棋盘的 side 1 单位。
3. 对每个单位从职业目录重建成长状态；只有职业内成长行大于 3 且存在候选时加入本次队列。
4. 队列为空时继续胜负与逐关事件检查；否则暂停其后消费者、聚焦队首单位并按当前在场授予者／其他队友分支播放转职对话。
5. 对话逐字完成后自动进入强制候选菜单；现代确认输入可快进逐字或立即推进，但不跳过职业选择。
6. 玩家确认合法候选后，写入目标稳定语义职业 ID，将经验设为 `0`，立即重建目标职业零经验派生属性和行动身份。
7. 当前生命、位置、slot、阵营、已行动标记与战斗 PRNG 均保持不变；具名角色的姓名与肖像保持不变，通用单位的姓名、通用肖像和地图棋子随目标职业更新。生命不按新上限补满，也不因选择发生随机消费。
8. 已提交单位移出队列；若仍有候选则按扫描顺序先播放下一人的分支对话。队列清空后才执行原动作对应的胜负与逐关事件检查。

## 状态变化与边界

| 情况 | 结果 | UI 反馈 |
| --- | --- | --- |
| 单个单位达标 | 强制选择一个候选并原子提交 | 默认只显示原版单排职业图；悬浮／键盘聚焦时在当前按钮下显示职业、行动方向、可选特性、零经验属性与数值差异 |
| 妮雅达标 | 上方窗口播放妮雅自问后自动进入菜单 | 妮雅肖像与原版一段文字 |
| 其他队友达标 | 下方队友请求、上方妮雅回应后自动进入菜单 | 两个肖像、两段原文；第二段保留第一个窗口 |
| 妮雅缺席的第 3 关 | 希蜜本人达标时自问；其他队友由希蜜回应 | 使用希蜜姓名与肖像，不显示未出场的妮雅 |
| 通用单位达标 | 对话与菜单使用当前完整职业名；提交后身份投影随目标职业更新 | 例如“陸戰騎士”转为“獸騎士”后，棋子、姓名、职业名和通用肖像均更新为“獸騎士”，HUD 显示“獸騎士／獸騎士” |
| 具名角色达标 | 姓名与角色肖像不随职业改变 | 对话显示角色姓名和本人肖像；职业菜单与 HUD 另外显示当前职业 |
| 多个单位同时达标 | 按棋盘格号逐个处理 | 显示“第 n / m 位”，每次只允许提交队首 |
| 当前职业无候选 | 不进入队列 | 不显示覆盖层 |
| `cancel`、战场点击或系统键 | 不改变状态 | 覆盖层保持，确认按钮仍为唯一提交入口 |
| 最后一击同时达标 | 先完成全部转职，再判胜 | 转职覆盖层关闭后才进入胜利剧情 |
| 转职后当前生命高于新上限 | 保留当前生命，不截断 | 详情同时显示当前值与新上限；本次不治疗、不扣血 |
| 保存/读取 | 覆盖层期间不可存档；玩家阶段存档保存已提交的语义职业 ID | 读取后按职业目录重建相同派生属性与合法候选 |

## AI 使用

我方自动控制只影响战术行动选择，不替玩家选择职业。自动单位满足资格时仍进入同一强制玩家选择队列。敌方 side 2 使用相同的第三行后成长阈值与属性增量，但永不触发普通转职；跨过同一临界值时只进入职业等级 4 并继续累计经验。

## 规则集与 Mod

| 配置 | 行为 |
| --- | --- |
| `stableRemake` | 使用原生候选与顺序，以原子事务重建派生状态；授予者必须是当前战场的在场主将 |
| `legacyStrict` | 保留原版固定妮雅授职；不暴露原生提交与后续装载之间的不可操作内存态 |
| 可开放 Mod 字段 | 触发成长行、候选有序列表、目标职业数据；修改后必须通过图无悬空 ID、UI、存档和行动能力一致性验证 |

## 表现与可访问性

转职前对话复用 DOM 上下剧情窗、角色肖像、逐字声与独立口型；默认按原版逐字完成后自动衔接，确认键/鼠标/触控可先完成当前逐字，再推进到下一段。职业选择使用透明的 DOM 强模态层，战场保持可见；底框由已验证的 `A/0006` frame 0／1／5 生成，候选继续使用 `A/0002` 原生职业图和最近邻像素边缘。按钮按原版单行几何排列，只有棕色普通底与绿色当前项，不在原版面板内添加名称或属性。鼠标移入会移动当前项，并在该按钮下方近距离居中显示详情浮层；第一行是职业名、第二行保持行动方向，若目标职业有额外特性则紧接一行完整说明，再显示当前与转职后数值。卡片不重复显示经验归零、生命不恢复与不可取消警告。点击才提交；左右方向键沿单行移动，上下方向键作为现代便利映射同样前后移动一项。完整职业信息仍写入按钮辅助技术标签，键盘焦点也可呼出详情。减少动态、动画速度或音量只影响呈现，不改变对话分支、队列、选择结果或 PRNG。

## 验收场景

1. Given 妮雅以士兵、经验 299、当前生命 123 完成一次普通攻击并获得至少 1 经验，When 进入转职，Then 上方窗口先逐字显示妮雅自问原文，结束后自动显示保留战场背景、`(160,110) 332×126` 原版底框及四个单排职业图的菜单，且未悬浮时不显示常驻文字；When 悬浮“騎兵”，Then 其正下方近距离居中显示职业名、行动方向、零经验属性与差值，卡片底部没有重复警告；When 选择候选 0“騎兵”，Then 职业为 `cavalry`、经验为 0、玩家 HUD 成长等级为 1、攻/防/最大生命/移动为 `55/30/200/8`，当前生命仍为 123，已行动保持 true；原生目标首行 `field6=4` 仅保留为职业数据元信息，不替代 HUD 的成长行计数；
2. Given 希蜜以同样条件完成最后一击，When 进入转职，Then 希蜜在下方请求授职、妮雅在上方回应且下方仍可见；When 选择候选 3“修女”，Then 转职先完成，随后才进入胜利剧情；
3. Given 两名 side 1 单位在同一次扫描时达标，When 第一名提交，Then 第二名仍按棋盘格号显示，期间不能操作战场；
4. Given 一个已转职的 v5 战中档，When 迁移为 v6、再次保存并读取，Then 语义职业 ID、经验、当前生命、行动状态、八项状态、PRNG 与可转职资格完全相同；
5. Given 陸戰騎士打开四个高阶候选，When 悬浮“獸騎士”，Then 第二行“普通攻擊”保持原样，其后另起一行显示“特性　命中降攻”及完整效果说明，浮层仍以该候选按钮为中心；
6. Given 相同模拟初态和候选选择，When 分别使用地图/全景战斗、正常/加速或减少动态，Then 转职队列与提交后状态完全相同。
7. Given 第 3 关妮雅不在棋盘且希蜜是当前主将，When 拉朵那达标，Then 下窗保留拉朵那请求、上窗由希蜜回应且使用肖像 45；When 希蜜本人达标，Then 只播放希蜜单段自问。
8. Given 魔術士经验 799，When 获得至少 1 经验，Then 其职业内等级从 3 进入 4 并触发转职；同条件 side 2 魔術士只升级、不进入队列。不得等待未被战斗成长读取的 `DATA` 第四行经验 1050。
9. Given 一个使用职业通用肖像的陸戰騎士，When 打开授职对话，Then 对话说话者与肖像名均显示“陸戰騎士”而非“騎士”；When 选择獸騎士，Then 地图棋子、`name`、`className` 与通用肖像均同步为獸騎士，HUD 显示“獸騎士／獸騎士”。Given 同样流程由具名角色执行，Then 保留其角色姓名与角色肖像。
