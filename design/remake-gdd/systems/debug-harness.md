# 战役调试与场景选择合同

状态：`implemented`

## 目的

本文件只管开发者调试中心（`/debug.html`）。玩家可用的原版Debug模式是另一个系统，
由正式表面的宿主开关开启，见 [`original-debug-mode.md`](original-debug-mode.md)（`REMAKE-174`）；
两者互不依赖。

随着关卡增加，开发、视觉检查和人工验收不应反复重打前置战役。独立 `/debug.html`
提供可发现的场景选择器，并把确定性夹具集中到注册表；普通玩家入口、模拟规则和存档
语义不因调试工具存在而改变。

## 边界与决策

- `[DD]` 调试中心是独立构建入口；普通 `/` 不静态载入调试注册表或调试 CSS。
- `[DD]` 选择页顶部集中提供竞技场、全职业对阵、转职触发、肖像、战斗、地图技能和部署专项实验室入口；它们不受关卡难度选择影响。
- `[DD]` 每个可玩关卡至少登记适用的关前、部署/准备、玩家回合、胜利准备和完成路由。
- `[DD]` 夹具必须明确显示“调试夹具”，使用确定状态与 PRNG，不伪装成原版事实。
- `[DD]` 调试会话只修改当前内存，不自动写入、覆盖或迁移正式 `localStorage` 存档。
- `[DD]` 选择页可设置一个 `0..9999` 的整数“每关成长值”；每名角色的成长预算按
  “（当前关卡序号 − 入队关卡序号）× 每关成长值”推导，离队后冻结，因此开国成员第 0 关为 0、
  第 5 关与异世界之门均为五倍。这不是直接写给高阶职业的当前经验：每名角色在
  `DEBUG_CAMPAIGN_MEMBERS` 登记一个目标顶层职业，原版转职图每个职业至多一个上一职，从入队
  职业到目标只有一条路线。士兵起点的角色入队后的下一关立刻进入路线上的二阶职业，再从零
  消耗预算；当前职业达到转职阈值时扣除该段阈值、进入路线上的下一职，到达目标后剩余预算
  留作经验。以魔术士、骑兵等非士兵职业入队的角色从其真实入队职业开始。
- `[DD]` 选择页的成长档案下拉只用玩家看得懂的名称，说明放在悬浮提示里（用户指定，2026-11-19）：
  - 「預設職業成長」（中心默认）：按上面登记的目标走。目标分配让留到最后的成员把 20 个顶层职业
    各覆盖一次：多莉、琴斯、愛莉歐拉固定为咒术师、魔祭师、巨斧战士，十七名士兵起点的角色与蘇蘭達
    （只能走骑士线）分掉其余 18 个（含巨斧战士，所以它在第 27 关后有两人）；葛蒂拉斯第 20 关后
    离队，与潔西卡重复邪法师。妮雅飞龙骑士、希蜜巫师为用户指定（2026-11-19）。名册构造不读任何
    随机数，相同档案、角色槽和 URL 必然产生相同路径。
  - 「隨機職業成長」：每名角色的目标改为在其入队职业能到的顶层职业里等概率抽一个，之后的预算
    与转职规则和预设档相同。抽选由 URL 的 `seed`（`0..4294967295`）决定，按种子与角色槽各自
    散列，互不牵连；选择页的链接不带种子，场景页进入时抽一个新的并用 `history.replaceState`
    写回地址，工具栏显示「種子 N」，重新整理或带同一种子的链接重现同一阵容。种子只决定夹具名册，
    战斗 PRNG 仍是固定初值。
  - 两档共用同一张逐关手写名册表：它标明哪些关接受每关成长，也是不带 `growth` 的直链所用的
    名册，所以不带 `growth` 时两档相同，随机只作用在每关成长上。旧的 `representative-growth`、
    `promotion-coverage` 档案名不再接受。
- `[DD]` `/debug.html` 默认每关成长值为 `100`，输入框、状态说明和恢复按钮必须直接显示
  该数值；首次进入第 1／5 关的默认成长预算分别为 `100／500`。“恢复预设（每关 100）”
  回到这一统一公式，不再恢复不可见的逐角色硬编码经验。
- `[DD]` 推导只作用于所选确定性成长档案在目标关卡明确配置的友军槽，并按最终职业及其
  剩余经验重算生命。模板基线、未配置关卡与正式记录来源不接受覆盖，避免把未登场槽误标
  为已成长或改变只读记录语义。
- `[DD]` 每个已实现的非第 0 关运行时必须在两档共用的成长档案关卡表中显式登记；不得把配置
  缺失解释为零成长。已经由前置剧情必然提交的职业按首次生效关卡
  序号累计到所有后续 debug 直达，不再逐关复制，以免新增后续关卡时把角色静默还原为士兵。
- `[DD]` 每关成长值随场景 URL 固化，只在从 `/debug.html` 开启场景时生效；关卡内不提供
  改值或重启入口。
- `[DD]` 场景页右上角的调试工具栏开启时收起，只露出「DEBUG」按钮，点按才展开场景、成长与
  一擊勝利／直接通關／戰敗測試面板（用户指定，2026-11-23）；收起时按钮以外的空白不拦截点按，
  下方的右栏照常可操作。端到端用例经 `tests/e2e/debug-toolbar.ts` 的 `openDebugToolbar` 展开后再按。
- `[DD]` 选择页另有「表現設定」：美術風格（原版／高清）、劇情語音（關／1／2／3／最大）、自動翻頁、
  音樂風格（原版／交響），选了立即写入游戏读取的同一份设备偏好（`angel2.preferences.display.v1`、
  `voice.v1`、`music.v1`），所以调试场景与普通 `/` 都按它生效，不必先进场景再开选单。这些是宿主表现
  偏好，不进模拟状态、PRNG、规则身份或存档，与“调试会话不写正式存档”不冲突。语音从「關」打开时按
  `REMAKE-191` 回到自动翻页，这条规则与开场方框、游戏内「音效開關」共用 `preferences.ts` 的
  `withVoiceVolume`；语音为「關」时自动翻页置灰但保留偏好。别的分页改了偏好、或从场景按上一页回到
  选择页时，选择页重读并显示当前值。
- `[DD]` 普通入口不暴露 `window.__ANGEL2_DEBUG__`；`?test=1` 的自动化接口保持独立。
- `[DD]` 调试直达可以跳过剧情和规则结算，因此不能作为真实通关、平衡或存档验收证据。

## 注册表合同

每个条目包含稳定场景 ID、关卡 ID、标题、阶段标签、说明和是否为夹具。未来新增关卡时：

1. 先建立获授权的关卡内容与模拟工厂；
2. 添加不改写规则的正式初态入口；
3. 为难以反复触发的胜负、技能或脚本事件添加最小确定性夹具；
4. 添加完成路由入口；只可启动已经获授权并实现的下一关，冻结关卡停在明确边界；
5. 在成长档案关卡表中显式登记关卡，并确认所有前置必经职业变化已经累计；
6. 用 manifest 枚举单元测试与 Playwright 覆盖场景载入、职业文字／棋子、难度与每关成长值
   传递、直接通关、普通入口隔离和代表性截图。

## 运行时接口

调试场景页可使用 `window.__ANGEL2_DEBUG__`：

- `getState()`：读取只读调试快照；
- `completeCurrentStage()`：直接进入当前已实现关卡的下一条获准路由；
- `prepareVictory()`：建立一次合法攻击即可胜利的明确夹具；
- `forceDefeat()`：触发当前关卡失败流程；
- `openScenario(id)`：切换至已登记场景。

这些方法只在带有效 `debugScenario` 的调试会话中注册。普通 `/` 和 `/debug.html` 选择页
本身均不暴露运行时接口。

## 验收

1. 四档难度会传入所选场景；
2. 第 1 关正式部署直达显示 `5/8` 初态；
3. 玩家回合直达保留完整单位与职业，非空壳演示；
4. 第 0 关直接通关进入第 1 关关前剧情；
5. 第 1 关直接通关进入第 2 关开场事件；第 2 关直接通关停在 `stage-03` 冻结边界；
6. 第 2 关登记关前／开场、固定准备、玩家回合、胜利准备和完成路由五类入口；
7. 桌面、窄屏和减少动态下关卡入口、全部专项实验室入口与工具栏可操作；
8. 普通入口不请求调试模块、不暴露调试全局，也不接受调试夹具作为真实通关证据。
9. 选择页默认明确显示每关成长 `100`，可套用其他值或恢复该预设，桌面与窄屏均可操作；
   第 1／5 关分别按一倍／五倍建立
   成长预算。第 1 关开国角色处于目标路线上的二阶职业；第 5 关跨过阈值的角色进入路线上的
   下一职，当前经验只保留扣除既往职业阈值后的余额，生命据此重算；正式记录来源保持原值。
10. 单元测试从 `STAGE_RUNTIME_MANIFEST` 枚举所有已实现关卡，非第 0 关必须拥有两套成长
    档配置；最新关卡还须从 debug 页面真实链接进入并核对代表性出场职业与棋子。单元测试另
    核对每个目标都是从入队职业走得到的顶层职业、留到最后的成员覆盖全部 20 个顶层职业且只有
    巨斧战士两人、20 个顶层职业都有我方地图棋子，以及预设成长下最后一关人人已到达目标。
11. 「表現設定」初始显示游戏默认值（原版、關、原版），选择后立即写入设备偏好；另一分页改值后本页
    同步显示；从选择页进入场景后，高清剧情插图、语音音量、翻页方式与音乐风格都按所选生效；
    桌面与窄屏均可操作。
12. 选择页的成长档案显示「預設職業成長」「隨機職業成長」，悬浮提示分别说明全职业覆盖与随机抽选；
    随机档从选择页进入时网址获得种子、工具栏显示同一种子、名册与该种子的推导一致，重新整理后
    种子与阵容不变。单元测试核对同一种子结果固定、不同种子的组合各不相同、抽中的目标都可达且为
    顶层、士兵起点的角色在多组种子下能抽到全部 20 个顶层职业，以及花掉的预算仍等于公式。
