# M00.6 最小状态底座规格

状态：`accepted`

授权日期：2026-07-29

用户接受日期：2026-08-01

依赖：战斗单位、Web 存档、规则集

## 玩家目的

状态必须以可保存、可验证的模拟数据存在，使修女炎暴能正确读取和消费防魔，并为后续状态系统保留不破坏存档的语义边界。

## 证据与决策

- `[OF]` 原版单位有攻击提升、防御提升、防魔、混乱、攻击下降、防御下降、施毒、禁咒八个状态字。
- `[OF]` 防魔最高位是当前效果保护标记；不同效果按各自顺序读取和清除。
- `[SR]` M00.6 的炎暴按 `REMAKE-005` 先被防魔阻挡，再消费防魔。
- `[DD]` Web 使用八个稳定语义字段和非负剩余回合；M00.6 只实现读取/消费防魔，不开放其他状态生产、倒计时或 UI 图标。
- `[DD]` 存档升级为 v6；v5 迁移为八状态全 0，不能原地改变 v5 含义。

## 触发与输入

- 进入条件：效果解析器需要读取或修改状态。
- 合法行动者：拥有有效单位 ID 的战场单位。
- 合法目标：动作规则接受的单位。
- 取消边界：动作提交前不修改状态。
- 提交时点：与 `PreparedAction` 的其他补丁原子提交。

## 有序规则

1. 载入时验证八个字段均为安全非负整数。
2. 未设置状态统一为 0；v5 迁移显式补全八个 0。
3. 准备效果时只读取状态副本。
4. 提交效果时应用状态补丁；炎暴阻挡把 `magicGuard` 设为 0。
5. M00.6 不执行通用回合倒计时、毒伤或 AI 混乱覆写。

## 状态变化与边界

| 情况 | 结果 | UI 反馈 |
| --- | --- | --- |
| 无防魔 | 魔法正常结算 | 正常效果反馈 |
| 有防魔 | 炎暴 0 伤害并清除防魔 | 阻挡反馈 |
| v5 读取 | 确定性迁移为八状态全 0 | 正常载入 |
| 损坏状态 | 安全拒绝存档 | 玩家可见错误 |
| 保存/读取 | 八状态逐项一致 | 不依赖 Phaser 或 DOM |

## AI 使用

AI 与玩家效果读取同一状态；M00.6 不新增状态施放决策。

## 规则集与 Mod

| 配置 | 行为 |
| --- | --- |
| `stableRemake` | 使用语义状态与已确认修复 |
| `legacyStrict` | 未来可映射原始状态字；本切片结果相同 |
| 可开放 Mod 字段 | 状态定义、持续时间和效果；需独立系统切片 |

## 表现与可访问性

本切片只要求防魔阻挡有文字和效果反馈，不新增常驻状态图标。表现不得成为状态真值。

## 验收场景

1. Given `magicGuard=1`，When 炎暴提交，Then 生命不变且 `magicGuard=0`；
2. Given v5 战中档，When 迁移为 v6，Then 所有单位八状态全 0、其他状态与 PRNG 不变；
3. Given 任一状态字段非法，When 读取，Then 安全拒绝并显示错误。
