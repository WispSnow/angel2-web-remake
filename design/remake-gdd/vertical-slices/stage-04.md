# 第 4 关纸面垂直切片：`stage-04 / 通過力場`

版本：Draft 0.2

状态：`implemented`；M06 已接受，2026-08-31 原版增援漏实现已修复

## 1. 切片目的

本关首次验证“到达指定区域”而非击败敌军的胜利条件，并把交互部署、玩家军团、自动引导者、
移动安全区和百分比生命效果组合为确定性护送关。第 4 关只消费既有职业行动和一个参数化的
`route-pulse` 特殊行动，不解冻新的射击、状态、深层职业技术或第 5 关内容。

## 2. 玩家体验摘要

- 剧情目标：[OF] 妮雅率军进入騎士團堡后发现强化力场；葛蒂拉斯建立小型结界，带领选中的
  同伴穿过力场进入大殿。
- 战术目标：[OF] 让葛蒂拉斯抵达格号 `<175` 的力场尽头，同时保护妮雅与葛蒂拉斯。
- 主要压力：[OF] 葛蒂拉斯每次自动尝试向上前进后，当前结界安全区外的我方单位生命减半；
  两名士兵在通道前方阻拦，第 4／8／12／16 回合各有最多两名士兵从北端增援。歼灭士兵
  本身不会胜利。
- 新机制：[OF] 固定引导者作为 side 1 行为 `12` 独立行动；[SR] `REMAKE-023` 按机器目标
  显示护送／双保护条件；[DD] 部署和战斗按需显示安全区与生命减半风险，但不改变合法格。

## 10. UI 状态

`nextStage(stage-04) → prebattleStory → deployment → openingStory → player → barrierGuide →
enemy → … → victoryStory → victoryFeedback → savePrompt/saveSlots → nextStage(stage-05)`。

部署状态复用既有 DOM 名单、人数、固定／可选标记和键鼠焦点；地图层增加可关闭的“首輪結界”
轮廓。战斗目标面板同时显示到达区、双保护目标与“葛蒂拉斯行动后，结界外我方当前生命减半”；
格号 `0..174` 展开的全部到达格常驻使用共享淡紫红填充与内缩轮廓；
选择葛蒂拉斯只显示信息和安全区，不打开玩家命令。独立行动时 HUD 以“友军・自动”标明
控制权，以“引导结界”标明战术，不把职责显示成军团。选择任一我方单位都显示其当前
“力场安全／危险”并投影同一安全区轮廓，不再用“安全区 N 格”代替单位风险判断。

正常战斗地图使用逻辑槽 `0/13/14/16`，玩家向分类为“地圖邊界／室內地面／階梯／通道”。
危险信息用文字和轮廓重复表达，不能只用红绿颜色；`MAGIC/26` 与其余地图技术一样不读取
`prefers-reduced-motion`，22 次绘制与 44 tick 在任何表现设置下都不变，只有「動畫 ×4」
改变墙钟。

SAY 174 的葛蒂拉斯发言必须投影合法肖像记录 `D/0`；记录号 `0` 不是“无肖像”。随后妮雅的
胜利反馈与存档询问完整复用常规上方剧情窗几何：`112×112` 肖像主图位于 `(32,26)`，
`400×86` 的 `A/18` 文字窗位于 `(153,10)`，两者完整纹理边界相隔 6 px；不得因切换到
结算覆盖层而产生横向或纵向偏移。
