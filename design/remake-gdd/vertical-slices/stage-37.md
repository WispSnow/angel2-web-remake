# 第 36 个可玩关卡（内部第 37 关）：究極女神

版本：Draft 0.1

状态：`[OF]/[SR]/[DD] 已闭合；M70 已指定，M71 已接受`

## 1. 切片目的

本切片承接“異世界的碧娜維姬”，复现碧娜維姬吸收部下力量后化成头与双手三个部位的
最终首领战。玩家口径称其为“第 36 关”，运行时与存档使用原版稳定 ID `stage-37`。

本关验证后期最大我方编队与原版专属首领链：妮雅固定，二十八名候选竞争二十六个开放格，
最多二十七人；头与两只手固定不移动，以两套交替术法和共享手部状态行动。

## 2. 玩家体验摘要

- 剧情目标：阻止碧娜維姬继续吸收力量并击破“究極女神”；
- 战术目标：保护妮雅并消灭头与两只手三个部位；
- 阵容特点：妮雅固定，二十八名候选、二十六个开放格，最多二十七人；
- 首领特点：三部位均不可移动；头交替使用高級回復／高級冰雪，两手共享究級落雷／
  究級炎暴的交替状态；
- 结算特点：没有专属胜利 SAY，普通胜利反馈后保存，并停在原生模块 25／内部
  `stage-49` 的主线结局链入口。

## 4. 关前剧情与入场

[OF] 模块 25 没有 stage 37 的关前剧情三元组或背景资源。完成 stage 36 后直接进入部署；

## 7. 首领行动合同

### 负面状态与控制

- [OF] 頭／手免疫冰雪的位移与独立行动禁用，也免疫混乱、施毒状态写入；技术表现仍完整播放；
- [OF] 攻击下降、防御下降均正常写入 3 回合并各降低有效攻／防 20；专属术法使用固定公式，
  所以攻击下降不改变高級回復／高級冰雪／究級落雷／究級炎暴的结果；
- [TBD] 上一条与 2026-09-02 复核的单位装载顺序冲突，尚未据此改动实现。模块 29 的
  `0000:502A → 0000:51EC → 1000:8C2D`（写入 ±20）之后才调用 `1000:8B60`，而 `1000:8B60`
  在场景 37 对全部 side 2 单位**整字改写** `31BF/31CF/31C1/31D1/31C3`（攻 100、防 10、
  最大生命 10000），因此原版本关三部位的有效攻／防应当完全不受这四个 ±20 状态影响。
  两个来源分别是本文件既有的 `[OF]` 记载与
  [`ordinary-combat-formulas.md`](../../../reverse/notes/ordinary-combat-formulas.md#装载顺序状态修正先于难度倍率)
  的新反汇编；`STAGE37_EVENT_PROGRAM.boss.statusAndControl` 的 `fixedDelta: -20` 是
  `scripts/generate-stage37-runtime.mjs` 里的手写常量，不是从映像取出的证据。闭合前请勿
  单方面改写任一侧。
- [OF] 禁咒只有龍免疫。頭／手正常写入、显示并递减禁咒 3 回合，但 `2P/3P` 专属分发不读取
  普通技术职业的禁咒门禁，四种专属行动仍可提交；这不是禁咒免疫；
- [SR] `REMAKE-124` 取代本关的施毒免疫：`IP` 与叢林普通命中都可向頭／手写入 3 回合
  中毒，每个完整回合把当前生命降至 `max(1,floor(life/3))`；混乱与冰雪免疫不变。保存层
  继续保存各部位完整状态计数，不新增隐藏抗性、控制递减或首领专属净化。

### 頭

- [OF] 初始切换状态为 0；第一次行动使用 `3I/高級回復`，第二次使用 `3C/高級冰雪`，
  此后每次成功提交后交替；
- [OF] 高級回復以头自身为中心，按原版范围处理友方三部位；高級冰雪同样锁定头自身落点；
- [DD] 回復轮保持原版“頭→左手→右手”；冰雪轮改为“左手→右手→頭”。这是
  `REMAKE-013` 下冰封目标不再受到任何伤害所需的确定性排程：两手必须先完成当轮攻击，
  頭的冰雪最后结算；若手已离场或已行动，只延后到仍可行动的手之后；
- [SR] 继承现有技术结算、状态免疫和确定性 PRNG，不因动画、音频或加速设置改变结果。

### 两只手

- [OF] 两手共享一个初始为 0 的切换状态，而不是每只手各自记录；
- [OF] 任一手第一次行动使用 `4L/究級落雷`，成功提交后共享状态翻转；下一只手使用
  `4F/究級炎暴`，随后继续共享交替；
- [OF] 目标选择按 side 1 棋盘顺序扫描；每个候选调用 `randomBelow(5)`，结果为 0 时选中，
  整轮无人命中就从头继续扫描；目标选择本身消费战斗 PRNG；
- [SR] 已离场或冻结目标不进入候选；这是 `REMAKE-013` 对不可行动技术目标的统一修复；
- [SR] 究級炎暴继承 `REMAKE-005` 的零除安全保护，不复刻可能崩溃或污染状态的未定义结果；
- [SR] 预览／规划使用 PRNG 克隆，只有动作提交才消费主 PRNG；读档必须恢复共享切换状态
  与完整 PRNG 状态。
