# UI、交互与表现方向

## 视觉基线

- `[OF]` 原版战斗输出为 `640×350`；主战场占左侧，右侧为肖像、HP/EXP 竖条、属性和状态，底部显示地点与回合。
- `[OF]` 标题前滚动开场同样使用 `640×350`：背景为位于 `(24,0)` 的 `608×257` 原生图，三行文字槽从 Y=`317` 向上滚至 `258`；发布版共 591 次滚动更新、17 行文字和 7 张可达背景，完整时间约 `70.92 s`。
- `[OF]` 标题底图 `BK/51` 位于 `(0,0)`，人物层 `BK/52` 位于 `(32,0)`，Logo 层 `BK/53` 位于 `(0,216)`；两项标题边框 `BK/40 index 0` 位于 `(480,50)`，四项难度边框 `BK/40 index 1` 位于 `(480,21)`；标题选项热区为 Y=`75/99`，难度热区为 Y=`51/75/99/123`。
- `[OF]` 战场视口为 `10×7` 个 `40×44` 图块；逻辑地图为 `50×50`，小地图用于定位全图和当前视口。
- `[OF]` 战场当前焦点框不是粗实色描边：原程序先画调色板 0 的 `40×44` 双像素底框，再覆盖调色板 15 的 `39×43` 单像素框，组合成一像素白色高光和一像素黑色阴影的原版斜面轮廓。
- `[OF]` 战场焦点不在单位上时，右栏显示 `A/0006/19` 战术桌与实时小地图；焦点进入单位格后，单位详情叠加在同一右栏上，小地图变暗且隐藏当前视口与双方单位标记，而不是在画布外常驻另一块战术面板。
- `[OF]` `A/0000` 的八个原生组件组成完整左侧战场框：`00` 为 `480×23` 顶栏，`01/02` 为左右角饰，`03` 是两侧共用的 `40×80` 彩色玻璃，`04/05` 是左右雕像，`06/07` 是底座；组合后中央开口精确对应 `(40,23)`、`400×308` 战场视口。

### 字体分层

- `[DD]` 玩家可见文字按来源分两层，玩家应当一眼就能分辨哪一半是原版的：
  - **原版复现**的表面用原版 `16×15` 点阵字（合并字模见
    `reverse/notes/battle-text-rendering.md`）：右栏身分列／五行数值／状态回合数、回合框、
    底部关卡名、通用命令选单、系统选单、`遊戲功能` 设定框、集体命令选单、確定／取消
    确认框、`A/18` 对白窗正文与肖像姓名牌、全景战斗左右状态框与伤害数字、祈禱结果文字、
    标题读取进度面板的标题／表头／逐槽资料、出击准备名单、开场滚动与标题选单、片尾尾声。
  - **复刻增强**的表面用现代字体：地形描述框、状态图标与右栏热区悬浮提示、难度提示卡、
    转职详情卡、信息栏单位／技能提示、图鉴与复刻说明覆盖层、记录备份与分页控件、
    胜负条件面板的条件说明与出击提示正文、宿主缩放控件、加载页与浏览器激活门。
- `[DD]` 原版点阵字只有 1,253 个字符（`NATIVE_FONT_CHARACTERS`）。复刻新写的说明文字
  经常落在字库之外，绘制器遇到缺字会跳过该格并保留光标前进，因此新文案接入点阵字前必须
  先做字库覆盖检查；无法覆盖的文案属于复刻增强层，应留在现代字体，不得为迁就字库改写原文。
- `[DD]` 原版本身没有对白续行标记；`KY` 只是等待输入。复刻不添加闪烁三角之类的提示符。
- `[DD]` `A/18` 窗内不显示发言人姓名行；说话者身份由原版自己的肖像姓名牌承担，
  文字仍以等价无障碍文本保留。

## 浏览器画面策略

- `[DD]` 以原版 `640:350` 逻辑画布为构图基准，保持宽高比并使用留边适配窗口。
- `[DD]` 优先提供整数倍缩放；窗口不足时允许等比非整数缩小，但仍保持像素清晰选项。
- `[DD]` 游戏规则不依赖 CSS 尺寸、设备像素比、帧率或浏览器缩放。
- `[DD]` 宽屏额外空间默认只用于留边；可选资料面板不得挤压或遮挡 `10×7` 主战场。
- `[DD]` 正常战斗默认不显示独立的画布外辅助区块；额外规则、键位与 Mod 资料只能从按需系统/暂停表面打开。
- `[DD]` 逻辑画布下方的宿主面板是复刻自有的页面 chrome，不属于原版构图：左侧是「畫面縮放」，
  右对齐「復刻說明」、「圖鑑」与「RoadMap」三个入口。它们不得画进 `640×350`，也不得进入原版战斗子选单——
  原版的五行方框是已取证的构图，加一行就伪造了证据。每个覆盖层只有一个入口按钮：分页在覆盖层
  自己的页签列里，把入口拆成逐分页按钮会把同一件事说两遍，也让宿主那一行越长越像游戏的一部分。
  前两个入口的分界是内容形态而不是主题：「復刻說明」逐条叙述复刻与原版的差异，「圖鑑」是可查询
  的资料表；把资料表塞进说明面板会让「共 N 条」这类说明用语去数一个不该被数的东西。
- `[DD]` 三个覆盖层共用同一套骨架：以页面级覆盖层呈现，不暂停、不查询、也不修改任何模拟状态，
  底下的战斗照常跑完敌方阶段。覆盖层内的按键一律停在覆盖层，不得抵达绑在 `window` 的战场输入；
  `Esc` 关闭并把焦点交还给打开它的入口按钮。表面切换时覆盖层随宿主面板一并卸载。
- `[DD]` 「復刻說明」分三个页签，入口每次都开在第一个：`Bug 修復`（原版缺陷与复刻修复）、
  `功能增強`（不改变合法操作与结算结果的资讯、表现与操作增强）与 `平衡性調整`（`[DD]` 产品决定）。
  归类按玩家实际感受到的那一面：只把已有规则画出来的增强进「功能增強」，
  改变了谁会中招的进「平衡性調整」。「功能增強」里不动规则的条目没有规则决策编号，
  出处是 `design/remake-gdd/` 的对应 `[DD]` 段落（介面在本文件，流程与存档在 `02-game-flow.md`），
  不得为它们另造编号体系。
- `[DD]` 「圖鑑」分两个页签，入口每次都开在第一个：`職業圖鑑` 与 `角色圖鑑`。两页共用「左栏索引 ＋
  右栏详情」版面，各自保留自己的选中项，因此在两页之间来回不会把玩家看到一半的条目重设掉。
- `[DD]` 「RoadMap」分为 `畫面與聲音`、`劇情與玩法`、`Mod 與共創` 三页，并常驻显示 QQ 交流群
  `1107513111` 与用户提供的原始二维码。这里列的是可讨论、会调整的候选愿景，不是发布承诺、完成状态
  或设计解冻；会改变玩法的条目仍须先闭合规则、UI、AI、存档与验收合同。二维码不得经过生成式重绘，
  避免破坏可识别性。
- `[DD]` 面板文字随游戏本体发行，而 `reverse/`、`design/` 与决策记录不会——玩家手上没有这些文件。
  因此面板上任何玩家看得到的文字都不得出现仓库路径、文件名、`[OF]/[DD]/[SR]` 证据标签，或
  `stableRemake`／`legacyStrict` 这类玩家在游戏里选不到的规则集代号；需要备忘出处时写进源码注解。
  没有决策编号的条目因此不画编号徽章，条目之间也只能互相引用同一面板里真的看得到的条目。
  同一条界线适用于其余玩家可见表面：标题记录面板显示的是规则集的可读名称，不是它的代号。
- `[DD]` 面板正文使用玩家能直接观察或操作的语言：说明原版出现什么现象、复刻现在怎样表现、对战局
  有什么影响。证据门槛、开发流程、架构边界，以及「处理器／渲染器」「模拟随机／存档语义」「原子提交」
  「宿主工具列」等实现术语只留在设计文档与源码注解，不用来向玩家证明条目正确；确需说明确定性时，
  改写为「相同操作得到相同结果」「不会改变之后的随机结果」等玩家可验证的结果。
- `[DD]` 面板只比对「原版怎么样」与「复刻现在怎么样」，不叙述复刻自己走过的路。玩家没有经历过
  复刻的中间版本，「复刻此前……现已改为」「曾试过 X，试玩后收回」「另一个方案被否决」都是开发
  过程，不进面板。由此推论：复刻自己写坏又贴回原版的修正在面板上等于「原版与复刻相同」，没有
  可比对的差异，不立条目（`REMAKE-105` 因此不收）；透露开发进度的说法（「目前已实装关卡」）同样
  不写。
- `[DD]` 「職業圖鑑」的全部数值从 `class-catalog.generated.ts` 与正式动作目录派生，3 级后成长
  直接对 `classStatsFor`／`nextExperienceThresholdFor` 取样，因此平衡覆写自动反映到面板上，
  不产生第二份手抄真值。
- `[DD]` 「職業圖鑑」的棋子与普通全景动画共用一个「我軍／敵軍」切换，玩家能直接比较两侧配色
  与方向；全景区默认显示不循环的静态「站立」帧，该帧取角色作为受击者、接触前的原生
  `direct frame 0` 常态，而不是攻击者 `class+50` 的起手动作；并提供「攻擊／格擋／重傷／死亡」四种可重播
  动作。预览只消费正式全景脚本、生成图形和 DOM 渲染器，不建立战局、不提交模拟结果，也不维护
  第二份动画表。
- `[OF]` 女帝、龍、頭、手只有右侧普通全景图形；龍、頭、手也没有 side 1 地图图形。因此后三者
  的「我軍」切换禁用；女帝仍可查看既有的我方棋子，但该侧全景区必须明确说明原版素材缺失，并
  引导切到「敵軍」查看唯一可重放版本，禁止镜像或挪用其他职业伪造左侧全景。
- `[DD]` 「角色圖鑑」收录原版角色描述子表里的全部具名角色，敌我同列；两侧都有描述子的角色
  （换过阵营的四人与龙塔七姊妹）单独成组，而不是硬塞进任何一侧。身份、名册槽与出场关卡由
  `character-catalog.generated.ts` 派生，出场关卡必须同时合并静态模板、名单候选、逐关事件生成
  与对白肖像四条通道——只看开局编成会漏掉第 20 关的妖龙这种「整场首领战都由事件生成」的角色。
- `[DD]` 角色简介是复刻替玩家写的导读，来源限定在游戏自己演出过的东西（剧情对白、胜负条件与
  编成），不补写原版没有的设定。原版既没有人物图鉴也没有角色介绍文字，所以没有台词、也没有
  专属桥段的角色刻意留空并如实说明，而不是用套语把每一格填满。简介里的关卡编号是玩家看到的
  序数，不是原版关卡编号（第 10、11 关互换，25 之后整体位移），由单元测试逐条回头核对。

## 输入原则

- `[OF]` 原版支持语义化的主操作、副操作、方向、菜单与系统动作，并通过 Joymouse 配置连接键盘/鼠标。
- `[DD]` 复刻版以语义动作而非物理按键定义交互，使键盘、鼠标和手柄共享相同规则。
- `[DD]` Web 默认键位采用现代 PC 游戏习惯：方向键／`WASD` 导航，`Enter/Space` 确认，`Esc/Backspace` 取消／返回；战场 `Tab` 对焦下一名未行动友军，`G` 打开集体命令，`O` 打开胜负条件。`Ctrl/Insert` 与 `Alt/Delete` 仅作为不冲突的原版相容确认／取消键；原版 `W/Z/A/S` 与 `Enter` 取消、`Tab` 集体命令因直接冲突而不保留。
- `[DD]` 主操作负责选择/确认，副操作负责取消/返回；已提交的模拟动作不能被普通副操作撤销。活动操作或面板存在时，`Esc` 先逐层返回；中性战场再次按 `Esc` 才打开系统菜单。
- `[SR]` Web 在中性战场将鼠标右键从原版“次操作”改为“下一名可行动友军”：按当前编队顺序循环、跳过已行动单位并自动居中镜头。若移动/攻击/敌军预览/行动菜单或任一可取消面板已打开，同一次右键优先执行逐层取消并被消费，不得继续切换单位。
- `[DD]` 所有关键流程可仅用键盘完成，也可仅用鼠标完成；手柄支持不改变菜单拓扑。
- `[DD]` 标准手柄在部署与战场使用十字键／左摇杆导航、`A` 确认、`B` 取消、`Menu/Start` 系统菜单；战场另以 `Y` 打开集体命令、`View/LB` 打开胜负条件、`RB` 对焦下一名未行动友军。魔弓箭道预览期间 `LB/RB` 保留为切换箭道；部署期间 `LB/RB` 切换名单与地图焦点。
- `[DD]` 输入重映射是设备偏好，不进入规则集。
- `[DD]` 物理设备切换只能改变焦点来源；不得因鼠标移入、手柄唤醒或键盘导航本身提交模拟动作。
- `[DD]` 原版右栏战术桌的 12 个物件热点保持发布坐标与正常态无框；鼠标停留时只显示单一 `1 px` 半透明浅金轮廓和极淡底色，不叠加第二层外框，持续 `450 ms` 后才在战术桌下缘显示原文短提示，移开或打开阻断层立即隐藏。键盘/辅助技术焦点即时显示同一提示和克制轮廓；每个热点保留稳定可访问名称，四个显示开关另公开当前按下状态。
- `[OF]` 战场鼠标内区为 X=`40..432`、Y=`26..325`；指针进入上 `<26`、下 `>=326`、左 `<40`、右 `>=433` 的战场框边缘区时，视口按对应方向逐格滚动并夹取到地图边界。下方热区包含 X=`80..399`、Y=`331..349` 的完整地点名称 banner；该纯展示层必须将指针事件透传给战场输入。
- `[OF]` 小地图内鼠标悬停以指针格为中心夹取一个 `10×7` 预览视口，并绘制白色 `30×21` 像素框；主操作点击把预览原点 `+4,+3` 设为战场焦点，视口使用同一夹取结果。悬停本身不改变焦点、棋盘或随机状态。
- `[DD]` 复刻版默认启用边缘驻留滚屏：进入边缘立即滚动一格，继续停留则按固定节拍重复，移回内区、右栏或画布外立即停止。该操作只改变视口原点，不移动逻辑光标、不改变选中或行动状态；方向键导航与手柄导航继续保留。

## 关卡标题、目标与现代提示

- `[OF]` 原版战场地点名位于底栏，胜利条件可从右栏热点或系统菜单按需打开。
