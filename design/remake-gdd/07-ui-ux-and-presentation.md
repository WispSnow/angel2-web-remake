# UI、交互与表现方向

## 视觉基线

- `[OF]` 原版战斗输出为 `640×350`；主战场占左侧，右侧为肖像、HP/EXP 竖条、属性和状态，底部显示地点与回合。
- `[OF]` 标题前滚动开场同样使用 `640×350`：背景为位于 `(24,0)` 的 `608×257` 原生图，三行文字槽从 Y=`317` 向上滚至 `258`；发布版共 591 次滚动更新、17 行文字和 7 张可达背景，完整时间约 `70.92 s`。
- `[OF]` 标题底图 `BK/51` 位于 `(0,0)`，人物层 `BK/52` 位于 `(32,0)`，Logo 层 `BK/53` 位于 `(0,216)`；两项标题边框 `BK/40 index 0` 位于 `(480,50)`，四项难度边框 `BK/40 index 1` 位于 `(480,21)`；标题选项热区为 Y=`75/99`，难度热区为 Y=`51/75/99/123`。
- `[OF]` 战场视口为 `10×7` 个 `40×44` 图块；逻辑地图为 `50×50`，小地图用于定位全图和当前视口。
- `[OF]` 战场当前焦点框不是粗实色描边：原程序先画调色板 0 的 `40×44` 双像素底框，再覆盖调色板 15 的 `39×43` 单像素框，组合成一像素白色高光和一像素黑色阴影的原版斜面轮廓。
- `[OF]` 战场焦点不在单位上时，右栏显示 `A/0006/19` 战术桌与实时小地图；焦点进入单位格后，单位详情叠加在同一右栏上，小地图变暗且隐藏当前视口与双方单位标记，而不是在画布外常驻另一块战术面板。
- `[OF]` `A/0000` 的八个原生组件组成完整左侧战场框：`00` 为 `480×23` 顶栏，`01/02` 为左右角饰，`03` 是两侧共用的 `40×80` 彩色玻璃，`04/05` 是左右雕像，`06/07` 是底座；组合后中央开口精确对应 `(40,23)`、`400×308` 战场视口。
- `[OF]` 地图棋子下方常驻显示当前生命数字，数字以白色像素字配合敌我红/蓝底色；行动完毕的单位不依赖变灰表达，而是在棋子左下侧显示原版灰底红字 `E` 标识。该标识为 `16×14` 像素，相对棋子逻辑底部中心的左上偏移为 `(-22,-15)`；三位数生命标签会与其右边缘轻微重叠。
- `[OF]` 每条原版 `D/<角色>` 肖像记录不是单张静态图：frame 0 为 `112×112` 主肖像，frame 1–3 是“睁眼／半闭／闭眼”覆盖片，frame 4–6 是口型覆盖片；肖像元数据的四个布局字节依次给出眼部与口部覆盖片在主肖像内的 X/Y 原点。
- `[OF]` 原版剧情肖像和战斗右栏肖像都会间歇眨眼。眨眼等待受原生 PIT 计时值影响，眼部按“睁眼 → 半闭 → 闭眼 → 半闭 → 睁眼”覆盖，不替换或缩放整张肖像。
- `[OF]` `D` 记录虽保存 frame 4–6 三张口部覆盖片，但发布版两套剧情解释器的口型状态都只在 `0/1` 间切换，绘制索引为 `state + 4`，所以正常对白只使用 frame 4“闭嘴”和 frame 5“小幅张嘴”；frame 6“完全张嘴”没有发布版对白生产者。不发言的角色保留闭嘴帧，眼部和口部是可同时工作的两套覆盖层。
- `[OF]` 单位职业行动使用原版通用菜单的紧凑三行布局、金色多层边框、深褐点阵底与蓝/红顶角饰；菜单在战场内靠近所选单位放置并避开右侧详情栏。键盘上下循环选择，主操作确认，次操作返回上一层。
- `[OF]` 玩家移动、普通攻击及其他原版选格范围不使用彩色格覆盖：范围字节非零的合法格保持完整地形，零值格使用逐行交错的 `11h/44h` 黑色网点，只保留 25% 地形像素。退出选格后恢复全图原亮度。
- `[OF]` 地图普通攻击命中使用 `UN/62` 的 `0..7→0` 九次 `40×44` 斩击绘制，每次 10 个原生 tick；随后按实际扣除量逐点更新棋子下方生命，每点 1 tick。目标存活时，反击对攻击者重复同一命中与逐点扣血链。
- `[OF]` 弓／弩公共棋盘射击与炎暴在各自固定图形结束后逐点更新棋子生命数字，每成功扣 1 点等待 1 native tick；落雷使用另一条一次写入结果的原版结算路径，不能据此泛化。
- `[DD]` Web 的逐点数字是准备结果的只读投影；真实生命、防魔、经验、行动位、死亡移除与 PRNG 后态仍在整段表现完成后原子提交，不能让动画中间帧成为规则真值。
- `[OF]` 全景普通攻击的先攻击后流结束后，受击者与伤害数字单独保持约 `1000 ms`，反击方随后才起手；原版 75 fps 录像中可见保持约为 `2.4..3.3 s`，反击首条声音请求位于 `3.345 s`，两段不是零间隔共边界。
- `[DD]` Web 采用玩家指定的 `667 ms` 表现时长（首轮 `1000 ms` 标定值的约三分之二），并把同一保持用于两处：先攻结束到反击起手，以及最后一次非致死受击到返回地图。保持段冻结受击者、伤害数字、镜头和生命条；致死分支已有完整死亡流，不再叠加此等待。
- `[OF]` 地图致死后使用 `MAGIC/12` 的 15 个描述符：前六步仍保留棋盘单位，完成后清除单位，再播放九步向上延伸并收束的光柱。地图死亡本身不绑定全屏死亡音 `E/11`。
- `[DD]` 模拟层可以先完成原子结算，但表现层必须保留攻防双方的只读影像和显示生命，直到上述清格边界；这类影像不得重新加入占用、ZOC、目标或胜负判断。
- `[DD]` 敌军移动范围预览是原版没有的辅助，继续使用半透明红色格与浅红轮廓，避免与原版玩家范围语义混淆；预览期间显示该敌军详情，但不出现职业行动菜单。
- `[DD]` 默认主题复现原版构图、边框、字体、肖像、色彩和像素比例；所有位图使用已修正位平面顺序与原生调色板。
- `[DD]` 像素素材默认使用最近邻缩放，不做平滑、重绘或自动色彩增强。

## 浏览器画面策略

- `[DD]` 以原版 `640:350` 逻辑画布为构图基准，保持宽高比并使用留边适配窗口。
- `[DD]` 优先提供整数倍缩放；窗口不足时允许等比非整数缩小，但仍保持像素清晰选项。
- `[DD]` 游戏规则不依赖 CSS 尺寸、设备像素比、帧率或浏览器缩放。
- `[DD]` 宽屏额外空间默认只用于留边；可选资料面板不得挤压或遮挡 `10×7` 主战场。
- `[DD]` 正常战斗默认不显示独立的画布外辅助区块；额外规则、键位与 Mod 资料只能从按需系统/暂停表面打开。

## 战场信息层级

### 常驻

- 无单位焦点时显示原版战术桌、实时小地图、当前视口与单位标记；
- 有单位焦点时在变暗且无棋子标记的小地图上叠加其肖像、姓名、职业、当前/最大生命、攻击、防御、等级、经验、HP/EXP 视觉条与状态图标；
- 当前回合；
- 当前关卡地点；
- 敌我阵营、棋子当前生命数字与 `E` 已行动状态；
- “胜利条件”“回合终了”与表现/声音设置不作为右栏底部常驻按钮，只在玩家明确呼出的系统菜单中出现。

### 选择动作后

- 移动/攻击/射击/技术的合法范围；
- 当前目标和行动会否提交；
- 地形与必要的免疫/无效说明；
- 取消会返回哪一层。

### 休息反馈

- `[OF]` 单个玩家或 AI 单位休息时，先在该棋子上播放 `MAGIC/0` 的五帧治疗公共尾效，
  每帧 15 native tick；随后清空效果并提交 15% 最大生命恢复与行动位。原链没有 `E/36`
  治疗声音，不能因为复用治疗图形而补播声音。
- `[OF]` `全部休息` 使用独立批量结算链，不为每名单位播放上述动画。命令对白结束后仍按
  原版一次提交全部合格单位，避免把集体命令延长为逐人演出。
- `[DD]` Web 表现期间生命与行动位保持为演出前投影，尾效和空白清理结束后原子提交；
  敌方／我方自动休息沿用相同棋子特效并保持现有相机对焦。

### 按需详情

- 完整状态说明、地形规则、职业行动、转职图；
- 胜利/失败条件；
- 可选伤害区间或公式说明；
- 当前规则集与 Mod 来源。

## 输入原则

- `[OF]` 原版支持语义化的主操作、副操作、方向、菜单与系统动作，并通过 Joymouse 配置连接键盘/鼠标。
- `[DD]` 复刻版以语义动作而非物理按键定义交互，使键盘、鼠标和手柄共享相同规则。
- `[DD]` 主操作负责选择/确认，副操作负责取消/返回；已提交的模拟动作不能被普通副操作撤销。
- `[SR]` Web 在中性战场将鼠标右键从原版“次操作”改为“下一名可行动友军”：按当前编队顺序循环、跳过已行动单位并自动居中镜头。若移动/攻击/敌军预览/行动菜单或任一可取消面板已打开，同一次右键优先执行逐层取消并被消费，不得继续切换单位。键盘 `Alt/Delete/Enter` 与手柄副按钮仍保留取消/返回；系统菜单仅由 `Esc`、手柄菜单键或明确热点打开。
- `[DD]` 所有关键流程可仅用键盘完成，也可仅用鼠标完成；手柄支持不改变菜单拓扑。
- `[DD]` 输入重映射是设备偏好，不进入规则集。
- `[DD]` 物理设备切换只能改变焦点来源；不得因鼠标移入、手柄唤醒或键盘导航本身提交模拟动作。
- `[DD]` 原版右栏战术桌的 12 个物件热点保持发布坐标与正常态无框；鼠标停留时只显示单一 `1 px` 半透明浅金轮廓和极淡底色，不叠加第二层外框，持续 `450 ms` 后才在战术桌下缘显示原文短提示，移开或打开阻断层立即隐藏。键盘/辅助技术焦点即时显示同一提示和克制轮廓；每个热点保留稳定可访问名称，四个显示开关另公开当前按下状态。
- `[OF]` 战场鼠标内区为 X=`40..432`、Y=`26..325`；指针进入上 `<26`、下 `>=326`、左 `<40`、右 `>=433` 的战场框边缘区时，视口按对应方向逐格滚动并夹取到地图边界。下方热区包含 X=`80..399`、Y=`331..349` 的完整地点名称 banner；该纯展示层必须将指针事件透传给战场输入。
- `[OF]` 小地图内鼠标悬停以指针格为中心夹取一个 `10×7` 预览视口，并绘制白色 `30×21` 像素框；主操作点击把预览原点 `+4,+3` 设为战场焦点，视口使用同一夹取结果。悬停本身不改变焦点、棋盘或随机状态。
- `[DD]` 复刻版默认启用边缘驻留滚屏：进入边缘立即滚动一格，继续停留则按固定节拍重复，移回内区、右栏或画布外立即停止。该操作只改变视口原点，不移动逻辑光标、不改变选中或行动状态；方向键导航与手柄导航继续保留。

## 关卡标题、目标与现代提示

- `[OF]` 原版战场地点名位于底栏，胜利条件可从右栏热点或系统菜单按需打开。
- `[DD]` 默认不在每关开战前新增阻断式标题/目标卡；关卡若有原生专用过场，则按其剧情规格处理。
- `[DD]` 新手提示必须非阻断、不夺焦点、不覆盖普通战场合法目标，并能按规则集或用户偏好关闭。
- `[DD]` AI 内部目标格、行为编号和搜索预算不因“意图辅助”自动公开；每关规格只定义玩家应知道的高层意图。

## 表现与规则同步

- `[DD]` 模拟先产生规范化结果，表现按事件播放；表现完成不是决定伤害的时钟来源。
- `[OF]` 原版“子選單”的 `戰鬥動畫` 发布初值为 1，即普通攻击默认进入全屏战斗表现；关闭后才使用棋盘表现。
- `[OF]` 原版战术桌以 `A/0006/19` 为底图，并让四个直接表现开关换用原生局部帧：戰鬥動畫 `20/21`（剑收回/拔出）、地圖方格 `24/25`、地圖捲動 `26/27`（地图卷起/展开）、人物圖像 `30/31`。这些帧直接读取与规则/表现分支相同的 DS:`1119/111A/111B/1118` 状态；音效、音乐与命令类热点不使用同类点击二态。
- `[OF]` 原版“音效開關”不是一个总静音项，而是 `說話／移動／戰鬥／按鍵` 四个独立请求门；`E` 键和右栏夜窗热点都打开同一面板。四项只决定对应 VOC 请求是否提交到底层数字播放链，不改变请求来源的规则或表现事件。
- `[OF]` 原版“音樂開關”是 `無聲／1／2／3／最大` 五选一，发布初值为“最大”；`M` 键和右栏桌面热点打开同一面板。它属于独立的 RIX/OPL 音乐路径，不受四项 VOC 开关控制。
- `[DD]` Web 首次启动控制器时默认选择“全景”，并保留“地图”作为玩家可随时切换的表现选项；该偏好不得改变普通攻击结算、经验、AI、PRNG 或存档规则语义。
- `[DD]` 战斗表现、地图方格、边缘滚动和人物图像作为设备级本地表现偏好独立保存，不写入战役存档。首次使用分别为全景、方格关、滚动开、图像开；坏值安全回退到这些默认值。
- `[DD]` 四类音效同样作为设备级本地偏好独立保存，首次全部开启。脚本移动、地图/全景战斗、剧情逐字声和按钮确认声分别在音频播放边界读取对应分类；关闭任一分类不能阻止语义音频事件产生，也不能连带关闭另外三类。
- `[DD]` 五档音乐作为设备级本地偏好独立保存，WebAudio 增益依次映射为 `0／0.08／0.16／0.24／0.32`；“最大”保持既有 `0.32` 听感基线。调档只更新全部已建立音轨的增益，不重建音频对象、不重置当前时间、不改变入场/循环段；“無聲”也让传输继续静默运行。
- `[DD]` Web 音乐传输预解码曲对并在同一 `AudioContext` 时间线上提前排定短入场与循环主体；`ended` 只能更新可观测状态，不能启动下一音轨。RIX 派生 PCM 保留原始 WAV，另以固定帧数的周期线性交叠生成循环资产；浏览器解码若重采样，再在实际输出采样率的短窗口内选择双声道低斜率切点并二次周期化。素材处理、音量和浏览器调度都只能改变表现，不能推进阶段或模拟时钟。
- `[DD]` Web 眨眼间隔使用独立的表现随机源，不读取或推进战斗 PRNG；每次完整眨眼后重新抽取下一段等待，不能退化为固定周期。切换焦点、镜头滚动或 DOM 重绘不得重置正在进行的眨眼周期。眨眼是局部、低幅度的角色生命感表现，即使启用系统“减少动态效果”也继续播放；该设置只压缩或停用大幅位移、闪烁与震动。
- `[DD]` 逐字对白正在输出时，只有当前活动窗口的肖像在闭嘴与小幅张嘴间交替。切换由原版字形事件驱动：每绘制一个 Big5 双字节字形（原生判定 `AL > 7Fh`）切换一次，ASCII 空格、换行和半角字符不切换；文字补全、原生等待、窗口失去活动权或关闭后立即回到闭嘴。口型属于表现状态，不推进剧情、战斗 PRNG 或模拟时钟。
- `[DD]` 原版地图/全屏攻击、射击、技术、死亡和逐关脚本的顺序按专项证据复现。
- `[DD]` 动画速度只缩放等待，跳过会抵达相同最终状态；关键选择和未读剧情默认不自动跳过。
- `[DD]` 当前活动剧情窗右下角常驻玩家可见的“跳過”按钮；一次明确点击结束当前整轮 SAY 对话，而不是只补全或推进当前一页。该便利动作只压缩对话表现，不跳过关前脚本移动、回合事件、胜负结算、保存询问或其他规范状态转移；双窗口切换时按钮跟随当前发言窗。
- `[DD]` Web 剧情窗保留原版 `112×112` 肖像与上下窗分工，但收紧为相接构图：上窗肖像上边缘与文字框上边缘对齐，下窗肖像下边缘与文字框下边缘对齐；文字框侧边必须与肖像框侧边相接，不留空隙。该布局修正只改变 DOM 表现坐标，不改变原文、分页、窗口活动顺序或逐字节奏。
- `[DD]` UI 在动画中可锁定冲突输入，但锁定不能改变 AI 或随机流。

## 可访问性与原貌的分层

- `[DD]` 色觉辅助使用轮廓、图案或标签补充阵营色，不重染原始素材作为唯一方案。
- `[DD]` 减少闪烁、降低屏幕震动、字幕背景和音量独立控制默认可用。
- `[DD]` 原版字体模式与高可读字体/放大文本可切换；文本内容和分页事件必须保持一致。
- `[H]` 战场 UI 的最小可读尺寸需在笔记本与高 DPI 屏幕上实测后确定。

## UI 验收

- 在标准 `640×350` 基准截图上，主战场、右 HUD、小地图和底栏区域与原版构图对应；
- 正常启动按滚动开场 → 标题 → 四档难度 → 第 0 关剧情顺序执行；任意键可结束开场但不能绕过标题或难度确认；
- 标题和难度画面使用调色板正确的 `BK/51–53` 与 `BK/40` 原生层；`BK/40 index 0` 是两项标题框，`index 1` 是四项难度框，切换菜单时必须同步替换；
- 进入标题画面时先让 `BK/51` 底图做阶梯式调色板淡入，再依次渐显 `BK/52` 人物层和 `BK/53` 标题 Logo；禁止用横向裁切或瞬时显示替代；
- 标题与难度菜单的默认项、循环导航、鼠标悬浮和确认热区均与模块 23 一致；
- 空地焦点显示明亮小地图、视口框和单位标记；悬浮或激活单位时显示详情覆盖层，小地图变暗且不再绘制视口框和单位标记；
- 小地图悬停白框尺寸与边界夹取正确；点击只更新视口与焦点，不能改变单位、行动位、生命、经验或 PRNG；
- 肖像右侧同时存在 HP 与 EXP 两条独立竖条，填充高度分别来自当前生命/最大生命与当前经验/下一阈值；
- 正常战斗右栏不常驻功能按钮；系统入口呼出独立菜单，关闭后恢复原先焦点与右栏状态；
- 战术桌 12 个物件在正常态无常驻框；悬停不足 `450 ms` 不显示提示，达到延迟后显示对应原文，移开即隐藏；全部热点的 ARIA 名称、弹出类型、四项开关状态和键盘确认路径可访问；
- 戰鬥動畫、地圖方格、地圖捲動、人物圖像切换后，战术桌分别立即换用 `A/0006` 的 `20/21、24/25、26/27、30/31` 原生局部帧；刷新后画面必须与已持久化状态一致，且不得为音效、音乐或命令入口虚构二态；
- 新控制器进入战斗时“戰鬥動畫”显示为全景；玩家切换为地图后，后续普通攻击使用棋盘表现且模拟结果与全景一致；
- 顶栏、彩色玻璃、左右雕像和底座使用 `A/0000` 原生像素，不以 CSS 渐变或通用边框近似；
- 每个地图棋子下方显示与模拟同步的当前生命；已行动单位显示 `E` 标识，未行动单位不显示，且不以降低棋子透明度替代；
- 地图普通攻击严格出现九帧斩击、逐点生命变化、存活目标反击，以及致死时 6+9 个死亡描述符；死亡单位只在第六个描述符后从地图表现层消失；
- 开启战斗动画后，第 0 关使用 `C.SWF/0` 的 448×148 原生宫殿横版背景、左右 200×148 状态栏和中央裁切战斗窗；攻击侧使用对应职业 `class+50` 动作组，受击侧使用 direct 组，反击时只切换动作身份而不交换物理左右；
- 全景窗底部左右生命条各有 210 像素有效宽，以每点生命一像素显示并每 210 点按红→蓝→绿→浅红换层；左条由外侧向中间增长、右条镜像。命中时条形一次切到扣血后数值，上方状态框的生命数字仍冻结为战前值，不得改成最大生命比例条、逐点扣血或单一中央装饰线；
- 士兵全景攻击执行原生 `2,2,2,2,9,9` 子步及 6 帧攻击组；骑兵执行 `2,2,2,2,2,6,9,6` 子步、完整 9 帧攻击组和独立冲击辅助通道，命中锚点为镜像对称的 `x=328/120`，命中后投枪通道不被清除，而是换回向上斜折的 frame 6 并按 `(±30,-16)` 每子步偏折飞出战斗窗，不得停在接触点或插在地面，禁止用棋盘棋子帧、直线位移动画或通用淡入淡出代替；
- 全景受击先按本次实际伤害选择 direct 姿态：伤害 `<=10` 使用 frame 3 的站立格挡且不离地，伤害 `>10` 使用 frame 1 的常规受击，并执行本次**攻击者职业**的离散纵向脚本；士兵为 `0→4→8→12→8→4→0 px` 一次弹跳，骑兵为 36 px 主峰落地后再出现 24 px 次峰。生命归零不覆盖该阈值段，而是在整段运动结束后追加 frame 2 / `E/11` 的倒地死亡段。不得按受击者职业固定受击类型，也不得用通用直线或连续缓动替代原生命令步；
- 命中音效不是按阈值固定的：引擎只按伤害切换击后命令流指针，声音完全由攻击者与受击者那两条击后流自己的 `V1..V5` 记号决定。士兵与骑兵的击后流恰好写着 `V1/V2`，所以呈现为 `E/2`／`E/0`，但 36 个职业里有 14 个不是这样（巨龍騎士两个分支都是 `V5 → E/4`，妖龍騎士的格挡分支原生无声）。实现必须逐职业重放击后流的声音记号，不得在没有记号时补一个通用撞击声；
- 镜头是每渲染子步整跳 8 像素的阶梯式推镜，且 `:R/:L/:J` 的方向寄存器跨命令流保留：33/36 个职业的击后流不写方向命令，靠继承先攻流末尾的方向。因此先攻以 `:J` 收尾的职业在命中前后会出现原作刻意的停顿（巨龍騎士 350 ms、武僧 880 ms、士兵 320 ms），不得用连续缓动或提前恢复推镜来「修顺」；
- 全景攻击先只启用攻击者通道，保留明显的跨场助跑或武器飞行；目标通道在接触前才显示。左侧攻击把世界向右击退，右侧攻击把世界向左击退，镜头在命中后继续沿受击方向跟随，但受击者的屏幕水平锚点保持不变；士兵/骑兵命中后的远景余程分别为 64/112 px，并以 8 px 原生步进推进，近地面保持 2× 视差。攻击者只在接触后的窗口边缘短暂可见，进入受击保持阶段时必须已经离开战斗窗，禁止再给受击者叠加屏幕横向滑动或完整展示攻击者跑回原位；
- 存活目标反击前必须保留 `667 ms` 的全景保持段：先攻者已经退场，受击者、伤害数字、镜头与生命条保持在先攻终点；之后才切换为反击方起手。最后一次非致死受击同样保持 `667 ms` 再返回地图；致死分支完成自身死亡流后直接收场。动画加速只等比例缩短墙钟时间，不能删除该阶段或改变结算、音效与 PRNG；
- 普通速度以约 40 ms／渲染子步播放，使士兵 26 子步的接近段约为 1 秒；`動畫 ×4` 使用约 10 ms／子步，必须实际达到四倍播放速度且不得省略帧或位移；
- 全景人物、冲击辅助图和伤害数字只能出现在中央 `x=96..543, y=152..315` 战斗窗内，不得越界盖住顶部状态栏；
- 剧情与战斗右栏肖像均使用对应角色自己的三张原生眼部覆盖片，并按元数据原点无缝叠加；一次眨眼完整经过半闭、闭眼、半闭后回到睁眼，连续两次等待由表现随机源重新抽取；
- 当前逐字发言肖像只使用自己的 frame 4/5 口部覆盖片并按 Big5 双字节字形交替，绝不选中 frame 6；文字补全后闭嘴，保留在另一窗口的非当前角色不得继续动嘴；
- 上窗肖像与文字框顶边对齐，下窗肖像与文字框底边对齐，两种文字框均与相邻肖像框零间距相接；关前、战场内和转职双窗口都遵守同一关系；
- 调色板、肖像和战场图块与已验证渲染无系统性色偏；
- 200%、300% 整数缩放不出现插值模糊；
- 键盘与鼠标能完成标题 → 第 0 关 → 胜利 → 保存的同一流程；
- 鼠标停在战场四边可连续逐格滚动，离开边缘立即停止；滚屏期间逻辑光标、单位坐标、选择与行动态均保持不变；
- 关闭地圖捲動后，战场边缘不再移动镜头且已有驻留滚动立即停止；方向键、焦点居中和小地图定位仍可用；
- 地圖方格只叠加原生逻辑格边界；人物圖像关闭时单位焦点不覆盖战术桌，重新开启后按当前焦点恢复详情；
- 右栏音效热点、`E` 键和游戏功能入口打开同一“說話／移動／戰鬥／按鍵”面板；四项可独立开关并在刷新后保持，关闭某类时其音频请求仍可审计但不尝试播放；
- 右栏音乐热点、`M` 键和游戏功能入口打开同一“無聲／1／2／3／最大”面板；五档互斥并在刷新后保持，调档期间当前曲目、入场/循环段和播放请求计数不变；
- `MUSIC/7→6` 与 `MUSIC/5→4` 的入场衔接及偶数主体回环均无事件调度空隙或 PCM 硬切；循环派生资产可由生成器逐哈希重建，原始 RIX 转录 WAV 不被覆盖；
- 关闭战斗动画或提高速度不会改变任何战斗状态；
- 只依靠颜色之外的视觉线索也能区分阵营、范围和已行动状态。
