# Mod 设计政策

## 目标

Mod 应建立在可验证的复刻基线上，使数值、职业、关卡、剧情和表现可以独立调整，同时任何存档都能回答“由哪些规则与内容产生”。

## 可修改内容分类

| 类别 | 示例 | 默认允许范围 |
| --- | --- | --- |
| 表现 | 肖像、图块、动画、音效、音乐、字体、文本主题 | 不改变模拟事件和时序依赖 |
| 本地化/剧情 | 对白、说明、角色名显示、剧情分支 | 需保留稳定脚本事件 ID；新分支声明内容版本 |
| 数值 | 职业成长、伤害参数、状态、难度系数 | 只能覆盖显式字段，必须声明取整规则 |
| 职业 | 转职边、职业行动、技术池、地形 profile | 需通过图、UI、AI、存档一致性检查 |
| 关卡 | 地图、部署、阵容、目标、事件、路由 | 使用完整关卡规格，不允许只替换图片 |
| 规则 | 撤销、自动战斗、新伤害类型等 | 属于规则 Mod，形成独立规则身份 |

## 稳定身份原则

- `[DD]` 原版资源、角色槽、职业记录、关卡、动作和剧情事件都应有稳定语义 ID；文件名或数组位置只是来源信息。
- `[DD]` Mod 通过显式覆盖或新增 ID 工作，不直接补丁任意运行时内存偏移。
- `[DD]` 多个 Mod 修改同一字段时必须产生可见冲突或明确顺序，不能静默依赖加载偶然性。
- `[DD]` 移除 Mod 后若存档引用缺失内容，应拒绝进入战斗并给出缺失清单，不以错误职业/空地图代替。

## 与原版事实的边界

- `[DD]` Mod 不修改 `reverse/` 下的取证输出；原版数据始终可重新生成和比较。
- `[DD]` “修复原版 bug”的 Mod 仍是规则选择，除非该修复按 [`01-ruleset-policy.md`](01-ruleset-policy.md) 正式进入 `stableRemake`。
- `[DD]` 无原版消费者的兼容字段默认只往返保存；Mod 若赋予语义，必须声明自己的字段 schema 与版本。

## Mod 友好的关卡规格

一个关卡内容包至少声明：

- 标题、地图和初始镜头；
- 初始单位、固定/可选部署、上限；
- 胜负条件；
- 回合/状态/位置/胜负触发事件；
- 剧情、音乐、表现资源；
- 下一关与失败路由；
- 所需职业、动作和规则版本；
- 验收场景。

第 0 关的原版复刻内容合同见 [`vertical-slices/stage-00.md`](vertical-slices/stage-00.md)，它也应能在未来作为首个关卡 Mod 示例。

## 第一阶段不做的事

- `[DD]` 当前不设计可视化地图编辑器或脚本语言；先把原版全部玩法写成无歧义内容合同。
- `[DD]` 当前不承诺热重载、多人共享仓库或在线 Mod 市场。
- `[DD]` 当前不开放任意代码执行作为 Mod 格式。

## 验收重点

- 启用/停用纯表现 Mod 不改变第 0 关结果哈希；
- 数值 Mod 在存档元数据中可见，且旧存档不会静默套用新数值；
- 冲突 Mod 能列出冲突的语义字段；
- 缺失 Mod 的存档给出可恢复错误，不进入半损坏战斗；
- 无 Mod 的 `stableRemake` 始终可回到原版基线数据。
